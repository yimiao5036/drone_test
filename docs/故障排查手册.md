# 故障排查手册

> 目标：按“现象→检查点→代码位置”的顺序定位问题，避免一出现故障就同时修改多个模块。  
> 最后更新：2026-10-20（§11.1 双目室外 0% 已定位为超出 ≈7.95m 量程，<8m 近距有效占比 99.2%；新增 G4 串口台架排查入口见 `tools/px4_link_smoke.md` §2.5；§19/§20 保留）。

## 1. 排查基本原则

1. 先确认当前运行的是正式`drone_control`还是独立探针；
2. 先检查配置，再检查日志，再检查模块计数，最后才修改代码；
3. 一次只改变一个变量，并保存修改前后的日志；
4. 视频探针、正式程序不能同时占用摄像头、NPU和本地RTSP输出路径；
5. 串口调试工具和正式程序不能同时打开同一个串口；
6. PX4 已到位（装机体+GPS）：连接失败/无 Home/停留自检**不再属于预期现象**，按 心跳→GPS fix→Home 排查；未连接时（串口松动等）出现这些现象则不是 Bug，也不要伪造；
7. 禁止为“先跑起来”伪造距离、高度、Home、姿态或控制有效标志；
8. 正式配置始终保持`enable_control=false`。

## 2. 当前硬件条件提醒

当前现场具备（2026-10-10 更新）：

```text
香橙派 + 双目摄像头 + 图传/HM30 + 地面站 + PX4（装机体 + GPS）
```

预期现象（PX4 已连接）：

- 视频链路、地面站串口物理链路正常运行；
- `/dev/ttyS1` 建立心跳，`home_valid` 可成立，地面站可显示真实 GPS/姿态/电池/Home；
- TargetEstimator 可出有效 NED 影子状态，MissionStateMachine 可越过自检；
- **仍不可能验证飞行控制**：`enable_control=false`，且正式控制接入路径（阶段 4）未建成。

PX4 未连接（未上电/串口松动）时，仍可能出现旧现象：无法得到心跳、TargetEstimator
等待 EKF 锚点、状态机停在自检——未连接时这些不是 Bug；连接后若仍如此，按
心跳 → GPS fix → 锚点流（#49）顺序排查，不要伪造，也不要改代码绕过。

**室内提示（2026-10-10，现场在室内）**：室内可能拿不到 GPS fix / Home / 锚点——此时
状态机停留自检、TargetEstimator 等待 EKF 锚点属**预期现象，不是通信问题**。判据：
先看「PX4 心跳已连接」是否出现（出现=通信正常，去查 GPS/Home/锚点流）。分阶段
验证见 `docs/PX4实链验证清单.md`。

## 3. 三分钟快速检查

### 3.1 确认运行进程

```bash
pgrep -af 'drone_control|video_latency_probe|px4_link_smoke'
```

如果正式程序和视频探针同时存在，先正常停止其中一个。

### 3.2 确认实际配置

启动日志中查找：

```text
正式主程序加载配置: path=...
主程序集成创建: video=... px4=... ground_station=... target_estimator=... control=...
```

不要只看源码目录中的`config/config.json`。构建目录和部署目录可能各自有配置副本，必须以启动日志的`path`为准。

### 3.3 找最新日志

```bash
ls -lt logs/ | head
```

实时查看：

```bash
tail -f logs/<最新日志文件>
```

按关键字过滤：

```bash
grep -E 'ERROR|WARN|启动失败|超时|回退|拒绝|断开' logs/<日志文件>
```

### 3.4 确认构建版本

开发机：

```bash
cmake -S . -B build
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
```

### 17.9 多边形围栏（65018/65019/65022）

> **地面站刷新后区域不见了**：区域副本落盘在 Web 平台 `data/fence.json`（服务端启动读回），
> 页面刷新/重连都从 `GET /api/fleet` 的 `fence` 快照恢复；若机载自报区域（65022）与副本不一致，
> 「共享区域」抽屉 05 段会显示不一致原因，可点「以机载为准」采纳，或重新下发 65018。
>
> **2026-10-29 现场教训（0072 日志）**：`65019` 一直显示 `state=3`（无区域）且
> `距边界=0.00m` 时，先看启动日志的 `任务状态机围栏区域输入已绑定: enabled=…`——
> 旧版本在 `fence.enabled=false` 下既不判定也不上报真实状态，区域看起来"没生效"。
> 现版本 `enabled=false` 只关动作、不关判定与上报。另：相对 Home 的高度**不能**
> 直接用 `-local_z_m`（那是相对 EKF 锚点），锚点可能比地面高若干米，会让高度带
> 在地面就判越界；正确口径见 `AltitudeForFence()`。

> **`fence.enabled` 自 2026-10-29 起默认 `true`**：开启但尚未收到 65018 时，机载会按
> `fence.default_*`（默认以 Home 为心、半边长 100m、高度带 0~30m、动作 return）生成一份
> 默认区域，落盘 `config/zone.json` 并通过 65022 回读；地面站不一致会提示重写。
> 不想要默认区域就把 `fence.enabled` 设 `false`（此时只上报 65019，不做判定动作），
> 或调小 `default_half_side_m`。
>
| 现象 | 定位 | 处置 |
|---|---|---|
| 65019 一直 `fence_state=3`（no_zone） | 没收到 65018、`config/zone.json` 不存在/非法、`fence.enabled=false`（默认已为 true）、或 Home 尚未有效（默认区域无法生成） | 确认地面站在发区域、看 `围栏区域缓存已装载/不可用` 与 `围栏默认区域已生成` 日志、查 `home_valid` |
| 65019 是 `4`（zone_invalid） | zone_id/version 为 0、顶点 <3、或 EKF 锚点无效（`ned_ref_valid=false`） | 检查 65018 字段；室内无 GPS 时锚点无效属预期 |
| 越界不上报 | `SetFenceInput()` 未在 Start 前绑定、区域被判定 invalid | 看启动日志 `任务状态机围栏区域输入已绑定: enabled=..`（`enabled` 只门控动作，不影响判定与上报） |
| 越界但不停/不返航 | 当前状态在地面段或 S12~S14（按设计不动作）、`violation_debounce_ms` 未到 | 看 `围栏越界中止` WARN 是否出现；确认在 S3~S11 |
| 起飞被 `65015 reason=21` 拒绝 | 65014 的 zone_id/zone_version 与机载缓存不一致 | 先发 65018 对齐，或让地面站发 zone_id=0 |
| 设定值被"卡"在边界内 | `FlightController::PublishPosition()` 多边形钳制生效 | 预期行为；WARN `飞行控制器围栏多边形钳制` 带位移与累计次数 |
| 设定值**没有**被钳制（跑出区域） | 多边形未生效：`LatestFencePolygon()` 顶点<3、EKF 锚点 `ned_ref_valid=false`、或多边形重建时锚点尚未就绪 | 圆形兜底围栏已于 2026-10-29 删除，无多边形即无几何钳制；查 65019 是否为 `3/4`，SITL 可用 `--sitl-stage4-mission` 看 `[SITL] 围栏多边形诊断` 一行（`valid=/顶点=/锚点有效=/Home有效=`）。重建在锚点就绪前会保留脏标记并每拍重试 |

判据：`65019.fence_state` 与 `65013.fence_state` 应一致；`distance_mm` 为内正外负。

### 17.10 人工返航指令（65020/65021）

| 现象 | 定位 | 处置 |
|---|---|---|
| 地面站"主动返航"按钮点不动 | 只在"已选中飞机 + 已连接 + `mission.state ∈ [3,11]`"时可点 | 先选中飞机，确认 65013 的 state 已进 S3~S11 |
| 接口 409 | 机载状态不允许（地面 S0~S2、S12~S14、故障） | 看 65021 `reason`：5=未起飞、6=已在返航、7=任务故障 |
| 接口 503 | 飞机离线 / 链路未打开 / `linkConfig.type='none'` | 先"连接设备"并确认心跳 |
| 回执 `result=2 reason=4` | `command_id` 与上一次重复（幂等保护） | 预期：同一指令重发不会重复执行；重新点按钮会生成新 id |
| 回执一直不来 | 65021 依赖 `SetMissionCommandAckInput()` 在 Start 前绑定 | 看机载启动日志装配项与 `任务指令回执已发布` INFO |
| 机载收到但不动 | 指令 `valid_for_ms=1000`，串口积压超 1s 会按过期丢弃 | 对照 `任务指令已发布` 时间戳与 `任务指令（主动返航）` 日志 |
| 返航中再点，回 `kCompleted` | 已在 S12/S13 时按"目标状态已达成"回 `kAlreadyReturning` | 预期行为；进度看 65013 state 与 65019 |

判据：接受路径必然伴随 65015 `reason=12 (cancelled_by_gcs)`，且机载状态下一拍变 `RETURN_HOME(12)`。

> **例外（2026-10-28 SITL 复现）**：`PublishTakeoffAbortAck()` 首行即
> `if (!accepted_assignment_.has_value()) return;`，所以**没有先发过 65014 分配**的
> 场景里，65020 被接受后不会出现 65015（SITL 的 `--sitl-stage4-command` 就是如此，
> 判据改为 65021 + S12 航向）。现场若手工点“主动返航”而没有走任务分配流程，同样
> 不要拿“没看到 65015”当故障；带分配的路径由单测
> `MissionCommandReturnHomeAbortsToReturnHome` 覆盖。

（原 `TargetEstimatorBaselineTest.GroundTargetConvertsWithAnchorBaseline` 的 ctest
逐用例隔离失败已于 2026-10-21 修复：测试改为等待 `LastState()` 已发布，而不是只等
`UpdateCount()`；根因为 `LastState` 仅按 10ms 发布节拍更新。）

### 17.11 PX4 命令发送失败/无 ACK（2026-10-30 起按语义分流）

机载到 PX4 的写通道分三类，失败现象与处置不同（实现见 `include/communication/px4_link.md` §3.6）：

| 现象 | 日志 | 含义与处置 |
|---|---|---|
| `PX4 关键命令发送连续失败，已达上限丢弃` | ERROR，含 `command=`/`attempts=10` | ARM/DISARM/LAND 等关键命令写失败 10 次（50ms 退避）后被丢弃；查串口线缆/波特率/`/dev/ttyS1` 是否被占用，命令需重新下发 |
| `PX4 命令发送失败，已放回队首重试` | WARN 节流（首次 + 每 100 次） | 关键命令写失败后保序重试中；若持续出现，按上一条排查 |
| `PX4 遥测请求发送失败，已丢弃（可重放）` | WARN 节流 | 内部遥测请求（`REQUEST_MESSAGE`/`SET_MESSAGE_INTERVAL`）写失败直接丢弃，属预期；约 1s 后低频重排直至成功（或下次建链重发）。仅当持续出现时说明写通道异常 |
| ARM/DISARM 一直无 ACK（`AckTimeoutCount` 增长） | `PX4 命令 ACK 超时` | 命令已写出但 PX4 未回 ACK：查飞控是否在 Offboard/安全锁、参数是否被拒；`AckTimeoutCount` 不包含写失败命令 |
| 位置设定值偶发不生效 | 无专门日志 | 流式设定值为最新值缓存，写失败只跳过本周期，下一周期发最新值；持续不生效查 `setpoint_timeout` 与类型掩码 |

判据：`AckTimeoutCount()` 只统计"写成功但没等到 ACK"；写失败只累加 `ErrorCount()`。
关键命令与内部遥测请求使用独立队列，遥测请求失败不会阻塞后续 ARM/LAND。

## 4. 程序无法启动

### 现象A：控制台提示配置文件不存在

检查：

```bash
./build/drone_control --config /绝对路径/config.json
```

配置查找顺序：

1. 显式`--config`；
2. 可执行文件旁`config/config.json`；
3. 当前目录`./config/config.json`。

代码：

- `main.cpp::ParseRequestedConfig()`；
- `src/config/config.cpp::ResolveConfigPath()`。

### 现象B：配置解析失败

常见原因：

- JSON逗号或引号错误；
- 队列容量、周期或超时为0/负数；
- 地面站启用但PX4关闭；
- TargetEstimator启用但地面站或PX4关闭；
- `enable_control=true`但PX4或地面站关闭，或`controller`节参数违反`Validate()`（阶段四装配门禁，Task 6 起允许前置齐备时加载）；
- 身份、component或串口参数不合法。

先运行：

```bash
./build/config_test
```

代码：`src/config/config.cpp`。

### 现象C：程序返回“没有任何模块成功启动”

检查启动日志中每个模块的启动失败原因。`DroneApplication`允许单模块降级，只要有一个模块成功就继续运行；全部失败才返回错误码2。

代码：`src/application/drone_application.cpp::Start()`。

## 5. 视频完全没有画面

按下面顺序检查，不能直接跳到YOLO。

```text
视频输入源：video.camera_source = rtsp 还是 uvc？
【rtsp】摄像头网络可达？
→ RTSP能否被ffprobe读取？
→ CameraReceiver是否收到字节？
【uvc】/dev/videoN 节点存在且权限可读？
→ UvcCameraReceiver是否收到字节（ReceivedBytes）？

→ 【stereo_split=true】StereoFrameSplitter左右目是否输出？
→ FrameCompositor是否输出标注帧？
→ VideoSender是否写出RTSP？
→ MediaMTX和HM30路径是否正确？
```

```bash
ping -c 3 192.168.144.25
ffprobe -rtsp_transport tcp 'rtsp://192.168.144.25:8554/main.264'
```

以实际配置地址为准。确认输入实际编码是H.265/HEVC，不要根据URL扩展名猜编码。

代码和文档：

- `include/video/camera_receiver.md`。

### 5.2 CameraReceiver有连接但没有后续画面

检查日志是否出现：

- RTSP打开失败；
- 读取超时；
- 重新连接；
- 参数集未就绪。

关键计数：

```text
CameraReceiver::ReceivedBytes()
CameraReceiver::ErrorCount()
```

判断：

- `ReceivedBytes`不增长：问题在摄像头、网络或RTSP接收；
- `ReceivedBytes`增长但解码帧不增长：进入解码器排查。

### 5.3 UVC双目输入（camera_source=uvc）

先确认设备与档位，再看接收器计数：

```bash
ls -l /dev/video*                       # 节点是否存在、当前用户是否在video组
v4l2-ctl -d /dev/video0 --list-formats-ext   # 确认MJPG与目标分辨率/帧率档位存在
```

典型现象：

| 现象 | 优先检查 |
|---|---|
| 启动日志`打开UVC设备失败`反复重连 | 设备节点/权限、USB接触、`uvc_device`配置是否指向正确节点 |
| `UVC档位协商失败` | 设备不支持配置的MJPG/宽高分帧率：以`--list-formats-ext`实际档位为准改`uvc_width/uvc_height/uvc_fps` |
| `ReceivedBytes`不增长且无错误 | 拔插后节点号变化；或摄像头被其他进程（探针/上一实例）独占 |
| 接收正常但拆分器`ErrorCount`增长（`输入帧非法`） | 解码输出尺寸≠`uvc_width/height`：档位被驱动回退到默认值，以G_FMT回读日志为准修正配置 |
| 左右目`Dropped`增长 | 对应目输出池耗尽；右目无消费者属预期计数路径，异常的是左目丢帧 |
| `RgaFallbackCount`增长 | librga调用失败（日志含原因），已自动回退memcpy不影响画面；查DRM/RGA驱动 |

关键计数：

```text
UvcCameraReceiver::ReceivedBytes() / ErrorCount() / ConnectCount()
StereoFrameSplitter::LeftFrameCount() / RightFrameCount() / *DroppedCount() / RgaFallbackCount()
```

代码和文档：

- `src/video/uvc_camera_receiver.cpp`、`src/video/stereo_frame_splitter.cpp`；
- `include/video/uvc_camera_receiver.md`、`include/video/stereo_frame_splitter.md`。

注意：拆分链路下YOLO/叠加消费的是左目`kDecodedFrameLeft`；左目有画面但“画面反了”（左/右物理目相反）是已知悬置项，不影响出图，见拆分器实现文档。

## 6. 收到码流但解码失败

关键计数：

```text
EncodedFrameCount
DecodedFrameCount
DroppedFrameCount
ErrorCount
```

典型判断：

| 现象 | 优先检查 |
|---|---|
| 编码帧增长，解码帧一直为0 | 编码类型、VPS/SPS/PPS、关键帧、rkmpp加载 |
| 启动时短暂`invalid pps id`后恢复 | 可能是GOP中途接入，等待参数集/随机访问帧 |
| RGA DMA持续回退 | DRM对象/图层/线性NV12/NV16布局或librga |
| 帧池满 | 下游过慢、句柄未释放、池容量不足 |
| 软件解码正常、硬解失败 | ffmpeg-rockchip/rkmpp环境和像素格式 |
| 全部 `_rkmpp` 解码器/编码器消失（`ffmpeg -decoders \| grep rkmpp` 为空） | apt 用发行版 FFmpeg 覆盖了 ffmpeg-rockchip（同版本号撞车）；按 `docs/部署与打包.md` §8 恢复并 `apt-mark hold` |
| 解码器创建日志 `设备=drm` 而非 `rkmpp` | 链接的 FFmpeg 不含 rkmpp 设备类型（发行版库混装）；查 `pkg-config --modversion libavcodec` 是否 62.x、`ldd build/drone_control \| grep avcodec` 指向 |
| 硬解画面偏色/错位 | 看 DRM 图层日志 fourcc：mjpeg_rkmpp 应为 `NV16` 并走 RGA `imcvtcolor`；详见 `include/video/drm_nv12_transfer.md` |

硬解和RGA相关日志必须结合计数判断，不能只看单条原生库输出。

代码和文档：

- `src/video/video_decoder.cpp`；
- `src/video/drm_nv12_transfer.cpp`；
- `include/video/video_decoder.md`；
- `include/video/drm_nv12_transfer.md`。

## 7. 有原始画面但没有YOLO检测

检查顺序：

7. 当前画面是否确有模型可识别目标。

## 8.1 视觉稳定性判定不锁定或频繁丢失


排查顺序：

1. `YoloDetector::ObservationCount()` 是否随帧增长？

   - 不增长：模型当前看不到目标，检查画面内容、置信度阈值和模型是否匹配；
   - 增长：继续下一步。
3. 看日志中的视觉稳定性行（默认每5秒一条摘要，状态变化时另有一条）：

   ```text
   视觉稳定性状态变化: SEARCHING -> ACQUIRING 连续检测=1 ... 累计转换=1 累计观测=1
   视觉稳定性状态变化: ACQUIRING -> LOCKED 连续检测=5 ... 累计转换=2 累计观测=5
   ```

   - 一直是 `SEARCHING` 但 `累计观测` 在涨：模型没看到目标，不是门限问题；

**实链发现（2026-10-16 / 2026-10-19）：目标流运行中突然停止刷新 + 一批 result=13 被拒**——
`地面站心跳超时: timeout_ms=3000` WARN 与随后的 `地面站心跳建立` 成对出现即为该模式：
心跳中断超过 `heartbeat_timeout_ms` 后**按设计置离线并清空时间同步**，离线期间到达的
目标一律按 TIME_SYNC_UNAVAILABLE（result=13）拒收；心跳恢复后还需重新积累
`minimum_samples` 个 TIMESYNC 样本（≈1 秒）才恢复接收；估计器会先打
`目标估计状态已过期`，恢复时打 `目标估计器重新初始化: reason=previous_state_expired`。
实链例：心跳中断 3~4s → 约 10 / 5 条目标被拒（result=13）→ 自动恢复，总空窗 ~2~3 秒。
机载节流日志通常看不到这批拒绝，需从地面站目标记录核对。**心跳为何缺失取决于地面站
侧**（其 1Hz 心跳定时器与目标流同链路，故障时仅心跳缺失）——在 GS 主机/服务端观察
发送时间戳定位；机载侧行为符合设计，不是缺陷。

**2026-10-19 再次复现（0041）**：16:02:26 先出现
`地面站时间同步偏移突变: state=SYNCHRONIZED->DEGRADED` → 74ms 后目标估计过期；
16:02:45 `地面站心跳超时: timeout_ms=3000` → 1s 后心跳恢复、再 1s 后时间同步建立 →
`目标估计器重新初始化: reason=previous_state_expired`。两次都在约 1~1.5s 内自动恢复，

本轮与 Home 漂移无关（Home 变化仅打

## 12.1 「PX4 Home变化」WARN 每约 2 秒重复刷屏

现象（2026-10-16 晚 至 2026-10-20）：`PX4 Home变化（诊断记录，估计器不重置）: 旧=(...) 新=(...) gps_fix=N 卫星=N eph=... epv=... 锚点ref=(...收N) 局部位置=(...)`

`PX4 Home变化，目标估计器已重置局部NED滤波状态` 仅存在于 2026-10-16 及以前的日志。
该版本以精确 ≈2.0s 周期逐条持续出现。

**2026-10-20 日志降噪后**：每次启动只保留**首条**完整明细，其后改为**每 30s 一条**
`PX4 Home变化窗口汇总（周期|停止）: 窗口=...s 变化=N次 首=(...) 末=(...)
水平范围=...x...m 净漂移=...m 高度净漂移=±...m 高度范围=...m 最大单步=...m +
gps_fix/卫星/eph/epv/锚点ref/局部位置`；停止时强制输出未满 30s 的窗口。
判读 Home 漂移仍看窗口行（首条明细给出起点，窗口行给出次数/范围/净漂移/最大单步）。
首条明细与窗口汇总之间的采样间隔最多 30s，需要更高分辨率时临时降低日志等级或
在独立探针中采集，不在生产热路径恢复逐条打印。

**先判性质，这通常不是 Bug**（2026-10-13 室内首测、**2026-10-15 室外复测定论**）：

- 2.0s 周期 = PX4 默认 0.5Hz `HOME_POSITION` 广播周期；
- PX4 在 **disarmed 期间会持续把 Home 更新为当前全局位置估计**（`HomePosition::update`，
  disarmed+landed 时按 `max(2×eph, 1.0m)`/`max(2×epv, 1.5m)` 判据刷新），
  全局位置估计本身随 GNSS/EKF 游走 → Home 跟着漂；
- **2026-10-15 室外实测订正（重要）**：室外开阔高地、良好收星（卫星 21~29 颗、
  eph 0.58~0.87m）条件下 **Home 依然持续漂移**（12 分钟水平包络 ≈20m×5m、高度
  22m 平滑往复），**维护者现场确认 QGC 同源数据同步漂移**——**"室外稳定 fix 后
  Home 应收敛"的旧判据不成立**，漂移是 PX4/GNSS 侧行为（非机载代码缺陷），
  与收星质量非简单相关（多路径/卫星几何变化/气压计温漂共同作用）；
- **诊断字段用法（2026-10-15 新增）**：
  - `锚点ref=(纬度,经度,高度,收N)`：EKF 投影参考锚点（GPS_GLOBAL_ORIGIN），
    **收 N = 锚点被重设的次数**——N 不增长且数值恒定 = 锚点稳定（即"坐标系锚
    不随全局估计漂移"，与 Home 的漂移形成对照）；N 持续增长 = 锚点也在变；
    ⚠️ **2026-10-16 实机订正（根因：消息号写错）**：**GPS_GLOBAL_ORIGIN 的消息号
    是 49，不是 411**（411 = CURRENT_EVENT_SEQUENCE）——历史配置把锚点流请求写成
    411，因此实机 PX4 对两条请求分别回 `REQUEST_MESSAGE(411)`→result=2、
    `SET_MESSAGE_INTERVAL(411)`→result=4（**配置已订正为 49**）。订正前 `--`/收0
    **不能判读为"锚点稳定"**（也可能是流未实例化）；先用只读探针定案：
    `px4_link_smoke --probe-message-interval 49`（interval_us=-1 → 流未实例化；
    >0 → 该流按此周期调度，此时"收 0"才等于"锚点稳定"，详见
    `tools/px4_link_smoke.md` §2.4）。定案前不要用"收 N"做处置方案裁决；
  - `局部位置=(x,y,z)`：飞机相对锚点的局部坐标——静止时的漂移量即
    "EKF 局部估计残差"（方案裁决的关键收益量）；
  - 三者一条日志齐全：Home 漂（全局快照）/ ref（锚点）/ local（局部残差）。
- **Home 生命周期（PX4 v1.17.0 源码结论，2026-10-16）**：`Commander.cpp:1841` 自动
  跟随条件 = `!已解锁 && landed && 无任务`，阈值 = 水平 max(2×eph,**1m**) / 垂直
  max(2×epv,**1.5m**)（`HomePosition.hpp:54-55`）。即：**未解锁期间 PX4 持续把 Home
  贴到当前位置估计上**；**解锁即停更（Home 冻结）**，起飞瞬间（`Commander.cpp:2145-
  2150`，`was_landed && !landed`）再按离地那一刻重设一次；`COM_HOME_IN_AIR=0`（默认）
  → 飞行中不再跟随（例外：起飞后 120s 内的高度一致性修正、航向重置改 yaw、显式
  `DO_SET_HOME`）；落地+上锁后自动跟随恢复。**推论：解锁后"Home 漂移 + 每 2s 重置"
  在实飞阶段自消；但锁存值 = 解锁/起飞时刻的估算值，不是真值。**
- **"局部 NED 原点 = PX4 Home" 是近似约定（飞行阶段存在固定偏置 H）**：项目约定见
  `flight_controller.cpp:519-521`，但 PX4 局部帧原点实际是 EKF 锚点（#49，已实测
  稳定），Home 是另一个点。地面阶段 PX4 让 Home 贴住飞机 → 目标 NED（Home 原点）
  与自身/视觉（锚点原点）的基准差 ≤ 跟随阈值（1~2m，漂移的大幅摆动被"贴住"机制
  吸收）；**起飞后 Home 冻结而飞机飞走 → 基准差变为固定值 H ≈ 起飞时刻飞机的局部

先区分：

- 模块从未启动成功；
- 模块启动成功但计数不增长；
- 阈值过小；

```text

```

只注册实际创建的组件。当前配置启用 Px4Link：PX4 已到位时应保持在线，若持续超时先查 `/dev/ttyS1` 接线/权限/波特率与心跳（见第 10 节），而不是直接放大超时；PX4 未连接时该健康源超时属于正确的降级反映。

**串口断开自动重连（2026-10-21）**：Px4Link 连续读错误达到 3 次会关闭端口，
按 `reconnect_interval` 重开。日志成对出现：

```text
WARN  PX4 串口链路中断，关闭端口准备重连: reason=连续串口读取错误 ...
INFO  PX4 串口重连成功: ... 等待心跳
```

重连期间 `connected=false`，控制器授权链撤权停发；重连成功后要等新的 PX4 心跳
才恢复 connected，不恢复旧命令。若反复重连，查 USB 串口接触/供电/设备节点；

G4 台架工具在拔串口时是**退出码 4 退出**，不要把它和生产程序的重连行为混淆。

不要为了消除告警直接增大所有超时。先确定数据源是否应该存在。

## 17. 怀疑程序向PX4发送了控制

立即检查：

```json
"enable_control": false
```

全局搜索：

```bash
grep -RIn 'SetInput.*Px4Setpoint\|px4_link_->SetInput\|SendCommand' \
  src include main.cpp
```

正式`DroneApplication`中`px4_link_->SetInput(...)`只允许出现在`enable_control=true`的装配门禁分支（`src/application/drone_application.cpp`，阶段四 Task 6 起）；该分支存在属预期，仓库生产`config.json`永远`enable_control=false`，分支不触发。若配置为false仍怀疑有控制输出，核对`DroneApplication::ControlAssembly()`快照与启动日志中是否存在WARN「正式控制输出已启用」。

捕网执行器（阶段四 Task 10 / Task 5，2026-10-21 抽象为 `INetActuator`）是正式程序唯一的`SendCommand`消费点：状态机每拍 `Update()` 推进时序，进入 S10 INTERCEPT_EXECUTING 调用一次触发；触发 ACK 后执行器按 `reset_delay` 自行发复位（不再由离开拦截序列触发）。当前 `single_pwm` 实现发 `MAV_CMD_DO_SET_ACTUATOR`（归一化 -0.7/0.0，PWM 映射在 PX4 侧）。它同样只在命令窄接口注入后可达——`enable_control=false` 时零调用；即使 `true`，还需 `interception.enabled=true` 且 S9/S10 入口条件满足（默认配置关闭，整机不会自发触发捕网）；触发/复位入队时打 WARN「捕网执行器触发/复位行程命令已入队」，可用它甄别命令是否由状态机发出。执行器 187 ACK 超时/非 ACCEPTED/断连/入队超时 → 状态机 S16、`active_warning_bits` bit4、`CancelPendingCommands()` 一次并停发一切控制意图（不重试/不补发复位），排查见 `include/state_machine/net_actuator.md` 与 `mission_state_machine.md`。

注意：`Px4Link`单元测试和`px4_link_smoke`包含命令或setpoint测试能力，不等于正式程序已经绑定控制。

## 17.1 S5 位置速度前馈（P3，2026-10-19）

现象与排查：

- **S5 意图前馈全为 0**：先查 `controller.enable_position_velocity_feedforward`
  （默认 **false**，这是生产安全基线）；打开后查 `TargetState.velocity_valid_mask`——
  地面站该轴速度有效位是否置位；若只有点、无速度位，则需 KF 累计
  `target_estimator.min_velocity_position_updates`（默认 5）次位置更新后才可用；
  目标过期/重置会清零。
- **前馈值偏小/被截断**：查 `FlightController::ClampedCount()` 是否增长与
  `controller.max_feedforward_mps`（默认 2.0，独立于速度意图的 `max_speed_mps`）；
  水平模长与垂直分量分别钳制。按目标速度谱设置上限（P1）。
- **前馈某轴被丢弃**：查 `FeedforwardDroppedCount()` 与节流 WARN“前馈轴非有限已丢弃”
  /“前馈掩码含未知位”。坏轴只丢该轴，位置意图照常发布，属安全降级。
- **S6 前馈为 0**：属预期（P3 决策：S6 冻结段保持纯位置，避免越过冻结点）；
  S7 速度意图也不带前馈。
- **接近围栏时过冲**：前馈不参与位置围栏（围栏只钳制位置目标），边界附近可能
  出现瞬态过冲，由 PX4 geofence 兜底；需要更保守时降低 `max_feedforward_mps`。
- **前馈已到控制器但 PX4 行为无改善**：先在 PTY 契约用例确认线上 type mask 同时
  放行位置与速度轴；再用 `--sitl-stage4-feedforward`（FF 开/关）复跑 A/B 并核对
  `tools/feedforward_report.py` 的稳态滞后；同时核对 PX4 `MPC_XY_VEL_MAX`/`MPC_XY_P`。
  2026-10-19 SITL 实测 FF 开启使 p95|lag| 从 1.49m 降到 0.40m。

## 17.2 拦截后返航/降落（S11~S14，2026-10-19）

- **发射后不停留 S10、直接进 S12**：属 V1 单发设计（发射命令入队即视为动作结束，不判命中）；`return_home.enabled=false` 仅用于捕网执行器隔离测试。
- **S12 原地悬停**：`home_valid`/`ned_ref_valid`/`local_position_valid` 任一无效，或返航超 60s；查 WARN「返航等待 Home/EKF 锚点有效」「返航超时」。Home 局部坐标由 Home 经纬度 + EKF 锚点换算，不依赖 `HOME_POSITION.x/y/z`。
- **S12 不进入 S13**：到达判据为水平 2m、垂直 0.5m、水平速度 0.5m/s 持续 1s；查位置/速度遥测、位置意图 reason 低位=8。
- **S13 不发 AUTO.LAND**：命令接口未注入（`enable_control=false` 或装配异常）、PX4 已被 failsafe 接管（状态机按设计让权、只监控）；查 WARN「AUTO.LAND 入队失败」「PX4 已离开 Offboard」。
- **S13 落地后不到 S14**：仍 armed 且 DISARM（400）未 accepted；查命令 ACK/PX4 disarmed。
- **不应出现 PX4 RTL**：正常返航不切 RTL；若观察到 4/5，说明返航设定值流中断触发了 PX4 Offboard 丢失 failsafe，或 PX4 被其他 failsafe 接管——按 PX4 侧参数与链路排查。

## 17.3 S9/S10 拦截入口（2026-10-19）

- **一直不进 S9**：先查 `interception.enabled`（生产默认 **false**，需在本地副本显式开启）；再逐项查 `lock_frames` 连续 LOCKED、测距 `valid`+新鲜且落在 `min_range_m~max_range_m`（**上限 2026-10-23 已冻结为双目测距极限 8m，下限 2.0 仍为占位**；测距本身只在 <8m 有效，若目标在 8m 外先按 §11.1 排查量程）、PX4 `connected+armed+Offboard(6/0)`、姿态/局部位置有效、命令接口已注入、捕网未触发且执行器 `Ready()`（无在途触发/复位时序）。`min_battery_percent` 当前保持 **0（不启用）**；设为 >0 后若电池遥测无效或低于门限，S9 入口会被保守挡住。
- **S9 进进出出**：看 WARN「拦截条件失效」——通常是视觉状态断流、测距超龄/越窗、PX4 离开 Offboard 或锁定帧计数被 LOST 清零；S9 条件恢复后由 S7 重新进入。
- **S9 不自动进 S10**：`auto_authorize=false` 时地面站确认授权协议尚未实现，只能等 `authorization_timeout_ms` 超时返航；V1 现场使用应保持 `auto_authorize=true` 或等待授权协议落地。
- **S9/S10 期间飞机减速/刹车**：S9/S10 设计为继续输出视觉伺服意图；若日志显示伺服降级/停发，按 S7 伺服排查（姿态/视觉超龄）。
- **入口默认安全**：`interception.enabled=false` 时整机不会自动发射；`enable_control=false` 时即使开启也无命令接口（S9 入口条件不满足）。

## 17.4 G4 串口台架（2026-10-20）

- **启动即报“必须同时提供 --bench-ack-props-off”**：这是强制安全确认，不是参数错误；
  拆桨、固定机体、遥控器可接管后再加该开关。
- **报“只允许 transport=serial”**：台架模式不接 UDP SITL；UDP 用
  `--sitl-stage4-controller`，两者互斥。
- **预检停在 landed/armed/位置姿态**：查 PX4 是否真的落地且未解锁、EKF 局部位置
  与姿态是否有效；台架不允许在 armed/空中启动。Home 无效只 WARN，但 ARM 可能被
  PX4 preflight 拒绝。
- **ARM ACK denied**：查 PX4 preflight、GPS/Home、遥控器链路与 QGC 告警；禁止
  force arm。`--bench-ack-props-off` 不等于允许绕过 PX4 安全检查。
- **G4-4 拔串口后工具退出码 4**：这是预期——机载侧已停发意图、关闭串口
  （机载心跳停止）、刷盘并退出，不尝试 AUTO.LAND/DISARM。机载软件到此为止；
  PX4 是独立系统，其 failsafe/上锁由飞控自身配置（需要时用 QGC 核对），不作为
  机载软件门禁。重新接线前先确认现场安全。
- **脉冲段报方向判定失败**：看打印的控制器发布侧设定值北/东分量；若设定值方向正确
  但电机实际方向不对，按 G4-2 人工记录并检查电机/桨序/机架坐标约定，不要改工具
  阈值掩盖。
- **停发后不退出 Offboard**：查 PX4 `COM_OF_LOSS_T`、Offboard 丢失保护参数与
  串口链路；工具只停发意图，不主动切模式。
- **停发时 landed=false**：工具拒绝 DISARM 并尝试 AUTO.LAND；先确认是否真的离地，
  不要为通过测试伪造 landed 或强制上锁。
- **完整命令、自动判定项与人工项**：`tools/px4_link_smoke.md` §2.5。

## 17.5 电池守卫与自动起飞门禁（2026-10-22）

- **65014 回 `battery_config_unknown`**：PX4 `BAT_LOW_THR`/`COM_LOW_BAT_ACT`
  未读到或非法。用 QGC 确认 PX4 参数：`BAT_LOW_THR` 为 norm
  （1.17 范围 0.12~0.5，默认 0.15=15%；机载×100 后要求
  `0 < 百分比 < 100`）、`COM_LOW_BAT_ACT=0`（Warning Only）；查 Px4Link 参数回包与
  `battery_low_threshold_valid`/`low_battery_action_valid`。机载不设本地
  百分比阈值，不要改代码阈值绕过。
- **65014 回 `battery_telemetry_invalid`**：`SYS_STATUS`/`BATTERY_STATUS`
  未到达或字段无效（电压/剩余量/新鲜度）。查电源模块接线、PX4 电源配置；
  不得把无效值伪造为 0。
- **地面 availability 一直 unavailable、65014 回 `battery_low`**：剩余电量
  不高于 `BAT_LOW_THR`（含相等）。充电/换电后遥测恢复且未执行空中任务，
  availability 自然回 ready；地面低电不锁存 terminal。
- **飞行中突然进 S12、65015 aborted**：看 reason：`battery_low` 为持续低电
  超过 `takeoff.battery_low_debounce`；`battery_telemetry_invalid` 为遥测
  立即失效。属设计内中止：S12 用机载位置设定值返航，不走 PX4 RTL、不空中
  disarm；一次任务只中止一次，S12/S13 再收到低电不会重复触发。
- **日志 `BAT_LOW_THR=0.2%` 或低电永不触发**：旧版本把 PX4 norm 直接当百分比
  与剩余电量比较。2026-10-22 起 `Px4Link` 读取时 ×100；SITL/实机预期日志为
  `BAT_LOW_THR=15.0%`，仍显示 0.x% 说明运行的是旧二进制。
- **SITL 目标等待/丢失后进入 S12 但没有机载返航**：PX4 的 Offboard 丢失兜底
  （`intent_timeout`+`coast_timeout`+`COM_OF_LOSS_T`，约 2.3s）早于 10s 目标
  看门狗，PX4 已自行 RTL 落地；S12 会识别 `landed && !armed` 直接收口。
  是否改为机载返航见 `docs/PX4实链验证清单.md` §7.4「待决策」。
- **低电前已接近 S9/S10**：状态机在交接/拦截入口之前评估电池守卫，低电当拍
  即转 S12，不会发出 187 发射命令。
- **RC 相关**：机载不读 RC、不要求 RC 在线；RC 人工接管导致 PX4 离开
  Offboard 时状态机停发让权，65013 availability 不含 RC 状态。

  禁止为通过测试降低超时或 force arm。
- **bootstrap 停流回 IDLE**：控制器 `bootstrap_timeout` 应覆盖
  `bootstrap_lead+mode_timeout+arm_timeout`（配置校验强制）。若状态机仍等待
  模式/解锁而控制器已停流，检查配置关系与 `takeoff.bootstrap_timeout` 注入。
  bootstrap 超时只停流，不进入 COAST、不自动重试。
- **S4 高度超时**：见 `height_timeout`、`climb_rate_mps` 与 PX4 高度来源；
  空中超时回 65015 aborted(takeoff_timeout) 并走 S13 AUTO.LAND。
- **S5 自动返航（目标等待/丢失）**：看 65015 reason：
  `target_wait_timeout` 表示起飞后从未获得匹配目标（`takeoff.target_wait_timeout`）；
  `target_lost` 表示获得后匹配目标持续失效（`takeoff.target_lost_timeout`）。
  两者都会中止任务 → S12，一次任务只中止一次、不触发 187。常见根因是 65010/
  估计目标的 `target_id` 与 `assignment.target_id` 不一致（控制任务下非匹配
  目标被过滤，S5 不更新引导）、估计器断流/超龄或 65010 过期。
- **65014 取消无效果/回 rejected**：取消用 `flags.bit1`（不要求 bit0），
  `assignment_id` 必须等于当前活动分配。无活动分配且该 id 从未处理回
  `rejected(not_ready)`；活动分配是其他 id 回 `rejected(already_assigned)`。
  地面取消回 READY（可用新 id 重新分配），空中取消转 S12 且本地上电不再分配；
  重复取消只重发最近结果，500ms 内不重复 DISARM。
- **取消后仍有 65010 被处理**：检查 `target_id` 是否等于已取消分配的
  `assignment.target_id`；取消/terminal 后 tracker 不再持有活动分配，目标过滤
  随之失效，状态机也不会进入任务链。
- **验收工具**：`python3 tools/assignment_sitl.py --help`；SITL 用
  `--connection udpin:0.0.0.0:14550`，台架经 HM30 用地面站链路串。脚本只发
  65014/65010 并打印 65015/65013，不直接发 PX4 控制命令。

## 17.8 地面站直控发射没有动作（65016/65017，2026-10-23）

- **现象**：`tools/net_fire_tester.py` 发 65016 后收不到 65017，或收到
  `REJECTED` 而机构不动。
- **先看回执原因码**（`[ACK] 65017 command_id=... result=... reason=...`）：
  - `CONFIRMATION_MISSING(3)`：地面站未置 `flags.bit0`（工具加 `--no-confirm` 时的
    预期结果，正常发送不要加）；
  - `FLIGHT_STATE_STALE(7)`：PX4 未连接/无心跳，或 `landed_state_valid=false`
    （没有 PX4 时本服务无法判定落地，必然拒绝）；
  - `ARMED(8)` / `NOT_LANDED(9)`：解锁或空中，本服务拒绝一切发射，先上锁/落地；
  - `UNSUPPORTED_VERSION(2)`：`protocol_version != 1`；
  - `ACTUATOR_BUSY(12)`：上一次触发-复位时序未走完（舵机保持/复位中），等回执
    `COMPLETED` 再发；
  - `NO_REMAINING_SHOTS(14)`：单发已用尽，需人工维护复位后才可再触发（复位不
    恢复发数）；
  - `ACTUATOR_FAULTED(11)`：执行器进入终态故障（ACK 超时/断连），日志有 ERROR
    原因，需排查 PX4 侧 Output Function/PWM 映射与 ACK 链路；
  - `ACTUATOR_UNAVAILABLE(10)`：未注入命令接口或执行器未创建（检查
    `enable_control` 之外——本服务只依赖 `gcs_fire_enabled` 与 PX4 链路存在）。
- **完全收不到 65017**：确认正式程序启动日志有“地面站直控发射已装配”
  （`actuator.gcs_fire_enabled=true` 才装配）；未装配时 65016 仍会被链路解码但在
  机载日志出现节流 WARN「捕网发射指令无人消费」，且不回 ACK——看到该 WARN 即可
  断定“开关关闭”，无需再怀疑协议或地址。另确认 65016 帧头与 payload 的 50/51 地址都是目标飞机身份
  （`--aircraft-system/--aircraft-component`），广播地址不会触发。
- **收到 COMPLETED 但机构不动**：机载只发 `DO_SET_ACTUATOR` 归一化量（触发
  `-0.70`、复位 `0.00`），PWM 由 PX4 按 `PWM = MIN + (v+1)/2 × (MAX−MIN)` 映射。
  先按“落点是否等于设计值”判：**待机应为 1500µs、触发应为 1150µs**
  （MAIN5 = `Peripheral via Actuator Set 1`，`PWM_MAIN_MIN5=1000`、
  `PWM_MAIN_MAX5=2000`、`PWM_MAIN_DIS5=1500`、`Rev Range=off`；`net_channel=1`
  是 Actuator Set 编号，不是物理通道 5）。
  - **落点判据**：ulog / `listener actuator_outputs` 里**复位落点应是 1500**；
    若落在量程中点（如 1325），说明 MIN/MAX 填错，与机载无关。因为 `v=0`
    永远映射到量程中点，而机载复位值就是 `0.0`，所以 MIN/MAX 必须关于 1500
    对称（1000/2000）。
  - **2026-10-28 现场实例**：`Minimum/Maximum` 被填成 `1500/1150`（顺序反、
    且非 1000/2000），中点变成 1325——ulog 实测 `1500（Disarmed）→1448（触发）
    →1325（复位）`，触发只走 52µs（约 15% 行程），机构不动、无声音；改回
    `Minimum=1000 / Maximum=2000 / Disarmed=1500 / Rev Range=off` 后实测
    `1500→1150（保持 1.5s）→1500`、舵机到位。
  - 落点正确但机构仍不动时，再查舵机供电（MAIN 排针只出信号不出 5V，VCC 需
    外部 5~6V 且与飞控共地）与 `Rev Range` 方向；
  - 机载侧可在日志核对 `捕网执行器触发命令已入队`（set/norm）与复位入队。
- **安全提醒**：本通道默认关闭（`gcs_fire_enabled=false`），只在拆桨台架/测试的
  本地副本打开；与 `interception.enabled` 同时为 true 会在配置加载期直接报错。

## 17.7 S5 目标失效原地保持（2026-10-22）

- **现象**：S5 期间地面站目标过期/`target_id` 不匹配/估计器断流，飞机**原地
  悬停**（不追旧目标、也不被 PX4 的 RTL 接管），65013 `active_warning_bits`
  置 **bit5**；日志出现 `S5 目标失效，进入原地保持: ... reason=9`。
  这是设计行为（原因码 9 的位置保持意图，目标=PX4 当前局部位置、无前馈、
  10Hz），目的是让 setpoint 流不断、PX4 留在 Offboard，把控制权留给状态机。
- **为什么不直接停发**：停发会在约 2.3s 内触发 PX4 Offboard 丢失兜底
  （`COM_OF_LOSS_T` 1s → Position 回落；SITL 无 RC 时 `NAV_RCL_ACT=2` 升级
  为 AUTO.RTL），10s 看门狗到点时 S12 只能让位 S13，机载 5m 返航不会执行。
- **排查“没有保持”**：按顺序确认 ① 是否控制任务（`enable_control=true` 且
  命令接口已注入，影子模式不保持）；② 是否处于 S5；③ PX4 快照
  `connected && local_position_valid`（局部位置无效时回落停发，属设计兜底）；
  ④ 是否有中止锁存（`mission_abort_latched_`）或已进入 S12/S13。
- **排查“一直悬停不返航”**：看累计保持时长——`takeoff.target_hold_max_ms`
  （默认 60000）到点会回 65015 aborted（已获得目标按 `target_lost`，从未获得
  按 `target_wait_timeout`）并转 S12；若目标反复闪烁，`target_lost_timeout`
  会被清零，此时只有累计上限能收口，不要误判为“看门狗失效”。
- **恢复**：连续 3 个决策拍（约 300ms）看到新鲜估计才退出保持，日志出现
  `S5 原地保持结束: 目标恢复 ...`；不足 3 拍不会退出（防抖动）。
- **验收**：`S5*Hold*` 单测覆盖保持目标/无前馈/10Hz、恢复迟滞、影子不保持、
  局部位置无效回落、累计上限两条回执；SITL 场景 7a/7b 需按新语义复跑
  （见 `docs/PX4实链验证清单.md` §7.4）。

## 20. 视觉观测融合（TargetEstimator 第二阶段）

开关 `runtime.enable_visual_position_fusion`（依赖目标估计器+双目测距+PX4，配置期校验）。
语义：视觉观测只在地面站有效期内细化估计，不初始化、不延展（§19 纪律下跳过类不打日志，
只计数）。

### 20.1 视觉更新计数一直为 0（VisualUpdateCount 不增长）

按门禁链从上往下查（每类拒绝有细分 reason 的节流 WARN）：

| 拒绝 reason | 含义 | 排查 |
|---|---|---|
| 视觉距离不可用或字段非有限 | valid=false / NaN | 双目测距侧：有效占比、近端簇点数（stereo_ranger.md） |
| 视觉观测时刻为0 | 帧缺失批次的节拍消息 | 正常节拍，不计异常 |
| 视觉观测时刻在未来 | 钟域错乱 | source_time_ms 来自左目帧 timestamp，应与 steady_clock 同域 |
| 视觉观测超龄 | 管线积压超过 max_observation_age_ms | 看测距处理耗时与帧率 |
| 同帧多框歧义 | 一帧多个框 | v2 单目标约定；确认场景确实单目标 |
| PX4快照缺失或超龄 | flight_state_max_age_ms 内无快照 | PX4 链路/心跳（第 10 节） |
| PX4姿态无效 / 局部位置无效 | attitude_valid / local_position_valid 为 false | 室内无 GPS fix 时 local_position 无效属预期 |

未初始化（无地面站目标）与地面站已过期两类**跳过不计错误**——视觉不造目标、
不延展有效期（过期政策归状态机）。

### 20.2 视觉 NED 方向/位置系统性错误

- 固定角度偏转：`target_estimator.visual.mount_*` 仍是全 0 准直假设（未标定）？
  1° 安装误差 ≈ 20m 处 0.35m 系统偏差；标定前属预期。
- 整体平移错误：核对 **LOCAL_POSITION_NED 原点 ≈ HOME_POSITION** 假设——
  室外悬停时把 GLOBAL_POSITION_INT 经 `GeodeticToLocalNed(Home, …)` 换算后与
  LOCAL_POSITION_NED 对比；PX4 EKF origin 在 GPS 切源时可静默重置，发现不一致
  先怀疑原点假设。
- 估计滞后/相位延迟：观测已过 EMA（smooth_alpha=0.4）再过 KF 的双重平滑，
  影子阶段录制对比后再决定是否调参。
