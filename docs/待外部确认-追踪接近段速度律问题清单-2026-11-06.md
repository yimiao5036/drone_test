## 0. 一句话

反无人机系统，机载接收地面站 5 Hz 的目标点（`65010`）——协议**有可选的速度位**（vn/ve/vd，cm/s）
和航向，但**手动打点时不填**（显式 0 = 静止目标），只有"重复发送/任务调度接管"的动点流才带真速度；
机载对没速度位的轴回退卡尔曼估速，
在 S5 接近段生成一个"位置引导点"下发给 PX4 offboard；
现在要定的是**接近段速度律**（怎么从 40 m 外追上一个 2~4 m/s 的动目标），
已用交互演示验证了候选方案，有 8 个工程判断需要外部意见。

## 1. 链路与能控的量（都是代码里的真值）

```text
地面站 65010（5 Hz，位置 + valid_for_ms + 可选速度位 vn/ve/vd/航向；
              手动打点填 0 = 静止目标，动点流由地面站按 motion 现算）
  → TargetEstimator（线性卡尔曼，每轴 [位置, 速度]）
  → 状态机 S5：算引导点 g = 飞机位置 + 单位视线 × 步长
  → PositionIntent（位置 + 速度前馈 + yaw）
  → FlightController：限速/slew/围栏钳制
  → PX4 offboard SET_POSITION_TARGET_LOCAL_NED（位置 + 速度前馈；加速度位恒被忽略）
```

## 2. 已经验证过的结论（我们自己信的）

1. **"余量"决定能不能追上，剖面只决定怎么追**。稳态接近速率 = `v_cruise − |v_t|`；
   余量为 0 时，在 40 m 场景下永远停在 42 m。
2. **时间最优（bang-bang）不能直接用**，切换面附近必抖；我们改成
   **比例接近律** `u = clamp(k·(dAim − R), 0, Vmax)`，`k = 0.6 /s`，实测切换 8 次、无抖动。
3. **提前量用碰撞三角形**（time-to-go）而不是固定 500 ms：
   `t_go = [(r·v_t) + √((r·v_t)² + (Vmax²−v_t²)|r|²)] / (Vmax²−v_t²)`，
   夹紧 `t_go ≤ 4 s`、提前距离 `≤ min(0.5·d, Vmax·0.5 s)`。
4. **转弯约束必须有**：纯追击追绕圈目标会陷"冲过头→掉队→再冲"的极限环，
   实测距离在 5~66 m 之间摆；加 `v ≤ a_lat·d / v_t⊥` 后绕圈能收。
5. **峰值不用固定 Vmax**：给定距离与两个加速度，峰值由闭式解决定
   （无上限时是三角形，有上限才出现匀速段）。

## 4. 要问的 8 个问题

### Q1 速度律选型：比例接近 vs 比例导引（PN）

我们现在是"沿视线速度匹配 + 比例接近"：`v = v_t·n̂ + u·n̂`。
但远段 `k·d` 恒饱和，`k` 从 0.3 改到 1.2 到点时间完全一样（11.9 s），只影响末端贴合软硬。
**问**：这个场景（低速 2~4 m/s 目标、机体限速 2~6 m/s、要"贴上去交接视觉"）用 PN（`a = N·V_c·λ̇`，N=3）会不会明显更好？还是纯追击 + 提前量就够？

### Q2 提前量的模型假设

碰撞三角形假设**目标匀速直线**。绕圈/蛇形时它会算错方向（演示里瞄准点会甩到一个圆弧外）。
**问**：这种目标，应该用"卡尔曼短时域预测（当前速度 + 曲率）"还是"PN 天然不需要提前量"？两者在 5 Hz + 200 ms 时延下的差别有多大？

### Q3 转弯约束的写法

我们现在用 `v ≤ a_lat·d / v_t⊥`（以速度 v 跟住视线转动需要 `a = v·ω`，`ω ≈ v_t⊥/d`），
`a_lat` 取 `controller.max_accel_mps2 = 2.0`（保守）。
**问**：这个近似合理吗？实机上 `a_lat` 该按什么取（PX4 倾角 45° 理论 ~9.8 m/s²，但速度环/姿态环有滞后）？绕圈 4 m/s、r=20 需要 0.8 m/s² 向心加速度，为什么 a=1.0 反而追不上？

### Q4 到点判据与"速度匹配"冲突

到点判据要求**速度 ≤ 0.5 m/s** 并保持 2 s；但末端策略若是"速度匹配目标速度"，
目标 2 m/s 时机体速度也是 2 m/s，**永远满足不了 0.5 m/s**。
**问**：这个 0.5 m/s 应该理解成"相对目标的速度差"还是"绝对地速"？如果目标在动，视觉交接到底该不该先悬停？

### Q5 卡尔曼整定（只在"没带速度位"时才是瓶颈）

机载 `σ_a = 8.0 m/s²`，演示显示它"跟位置够用、往前推不行"（前视误差 2.13 m vs 整定到 2.0 时 1.37 m）。
但注意：**`65010` 带了速度位时，机载优先用地面站速度**（`target_estimator.cpp:834-860` 覆盖 KF 速度），
KF 只是兜底；此时前视精度取决于地面站速度本身的精度与时延，与 σ_a 无关。
**问**：反无人机这种目标（可加速、可急转），兜底场景下 σ_a 取多少合适？要不要换 CA/IMM？
位置量测用的是地面站 GPS 精度（默认水平 10 m），要不要按实测噪声重标？

### Q6 实机加速度能力与加速度前馈

我们只下发**位置 + 速度前馈**，`px4_link` 里 `AX/AY/AZ_IGNORE` 恒置位（加速度前馈被丢掉）。
PX4 的 `MPC_ACC_HOR` 只被 goto 用，offboard 通路没有加速度限幅。
**问**：要不要打开加速度前馈（PX4 支持 `afx/afy/afz`）？开了之后由谁保证不超机体能力？
还是维持现在"位置 + 速度前馈 + 我们自己的梯形/比例律"更稳？

### Q7 目标跑到围栏外怎么办

现在 FlightController 会把越界设定点钳到边界（`fence_margin_m`），飞机贴边悬停，
地面站只看到一条提示（我们新加的 bit7「目标在围栏外」），不会自己绕行/放弃。
**问**：工程上常见做法是"贴边等"、"沿边界绕行"还是"直接放弃任务"？绕行的话谁来做路径规划？

### Q8 外部地面站到底会不会填速度位

协议本来就有 `velocity_north/east/down_cms` + `heading_cd`（`flags` bit1~bit4），
我们自己的 Web 地面站：手动打点填 0（显式静止）、动点流按 `motion` 现算真速度。
需要确认外部那套地面站（雷达/视觉跟踪）跟踪动目标时**是否填速度位、精度多少、时延多少**——
填了，前视直接用它的速度；不填，只能靠卡尔曼（差分速度在 5 Hz + 0.8 m 噪声下误差 ~4 m/s，不可用）。
**问**：你们的 65010 发不发 vn/ve/vd？如果发，是滤波输出还是差分？典型精度/时延？
另外注意一个坑：`flags` 若把速度位置位却填 0，机载会当成"显式静止"，KF 的速度量测（σ=5 m/s）也会被拉向 0。

## 5. 还需要对方提供的输入

1. 机体（香橙派 + PX4 + 多旋翼）**实际可持续的水平速度与加速度**（不是参数表，是带负载实测）。
2. 视觉交接（S6/S7）对**进入速度/姿态**的要求：能不能在 2 m/s 时直接锁，还是必须先降到 0.5 m/s 以下。
3. 目标类型（多旋翼/固定翼）与典型机动（巡航 2~4 m/s、绕圈半径、是否能急转）。
