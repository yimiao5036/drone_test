# 系统架构设计

## 1. 架构目标

系统采用“物理链路隔离、消息驱动、策略可替换、控制单出口”的架构。V1 优先实现可验证的安全闭环，同时为摄像头、避障、返航、拦截设备和 PX4 版本升级保留边界。

## 2. 分层

```text
设备适配层
  摄像头 / 激光雷达 / PX4 串口 / 地面站电台 / 图传 / 电源监测

数据与感知层
  H.265 解码 / YOLO / 光流 / 标定转换 / 状态估计

策略与控制层
  GPS 接近 / 视觉跟踪 / 目标丢失 / 障碍处理 / 返航 / 拦截策略

任务层
  状态机 / 控制权仲裁 / 健康管理 / 告警
```

下层不依赖上层。设备适配器只负责数据和命令，不包含任务状态转移；状态机只使用接口，不直接访问串口或图像缓冲区。

## 3. 核心模块

> 命名约定：下表名称是设计边界；代码实现中接口为 `I` 前缀（如 `ICameraReceiver`），
> 骨架期提供 `XxxStub` 占位实现，接口签名见 `docs/数据接口文档.md` §4。

| 模块 | 职责 | 可替换边界 |
|------|------|------------|
| CameraReceiver | TCP 建连、接收 H.265 码流、断线重连 | 视频协议适配器 |
| VideoDecoder | H.265 解码为图像帧 | 软件/硬件解码后端 |
| YoloDetector | 输出类别、置信度和像素位置 | 模型与推理后端 |
| OpticalFlowEstimator | 从相邻图像计算光流 | 光流算法 |
| LaserRangeFinder | 读取、校验和时间标记单点距离 | 雷达型号适配器 |
| PerceptionFusion | 对齐视觉、光流、雷达和机体姿态 | 融合算法 |
| TargetEstimator | 平滑、预测并维护目标状态 | 卡尔曼或其他估计器 |
| Px4Link | MAVLink 收发、ACK 关联和遥测快照 | PX4 版本适配层 |
| GroundStationLink | 任务输入、状态回传和授权 | MAVLink dialect/电台适配器 |
| MissionStateMachine | 任务阶段和控制权仲裁 | 不依赖具体设备 |
| FlightController | 生成位置或速度设定值 | 控制算法 |
| VideoSender | 发送标注视频 | 图传协议适配器 |
| HealthManager | 数据新鲜度、链路和设备健康 | 健康规则 |

## 4. 策略接口

以下名称表示设计边界，不是当前代码实现：

| 接口 | 输入 | 输出/责任 |
|------|------|-----------|
| `IObstacleAvoidanceStrategy` | 障碍物、雷达、光流、飞行状态 | 安全动作和是否允许恢复 |
| `ITargetLostStrategy` | 预测状态、最新 GPS 目标、搜索状态 | 继续预测、搜索、位置引导或返航 |
| `IReturnStrategy` | Home、本机状态、感知和健康 | 返回路径或控制设定值 |
| `IInterceptionDevice` | 准备、执行、终止请求 | 通用设备状态和结果 |
| `IInterceptionAuthorizationPolicy` | 锁定、健康和地面站授权 | 是否允许执行 |
| `IPostInterceptionPolicy` | 目标、设备、电源和任务状态 | 返回、继续或等待地面站 |
| `ICompanionPowerMonitor` | 独立电池硬件数据 | 算力板电源状态 |
| `ICameraPoseProvider` | 帧时间 | 固定外参；未来可替换为云台姿态 |

V1 通过简单实现满足接口：障碍策略为刹停悬停、返航策略为算力板控制返回 PX4 Home、拦截后策略为默认返航。

## 5. 初始执行模型

最初按七个逻辑执行单元设计：

| 执行单元 | 主要工作 |
|----------|----------|
| 摄像头采集线程 | TCP 接收、H.265 解码、图像时间标记并写入内存池 A |
| 感知线程 | YOLO、光流、目标估计，输出结构化感知结果和标注帧 |
| 图传线程 | 从内存池 B 读取最新标注帧并发送 |
| PX4 通信线程 | 串口 MAVLink 双向通信和命令发送 |
| 地面站线程 | 电台 MAVLink 双向通信 |
| 激光雷达线程 | 串口读取、校验、滤波前数据发布 |
| 状态机与控制线程 | 固定周期消费最新快照、决策并生成 PX4 指令 |

七个是初始逻辑映射，不是永久限制。H.265 硬件解码器、NPU 驱动或算法库可能创建内部线程；若实测表明 YOLO 与光流互相阻塞，可拆分感知工作线程，但不得改变消息契约。

## 6. 数据流

```text
摄像头 TCP -> H.265 解码 -> 图像池 A -> YOLO/光流
                                      -> 感知结果 -> 状态估计
                                      -> 标注图像池 B -> 图传

地面站目标状态 -------------------------------> 状态机与控制
激光雷达距离 -> 校验/时间标记 -> 感知融合 -------> 状态机与控制
PX4 遥测 -> 飞行状态快照 ----------------------> 状态机与控制

状态机与控制 -> 控制命令队列 -> PX4 通信线程 -> PX4
状态机/健康/任务结果 -> 地面站线程 -> 地面站
```

只有 PX4 通信线程可以写飞控串口。遥控器接管、状态机和策略模块只能提交意图，最终由控制权仲裁器决定是否产生飞控命令。

## 7. 队列和内存所有权

- 图像使用固定容量内存池和 RAII 句柄，消费者完成后自动归还。
- 图像队列满时丢弃最旧待处理帧或覆盖最新槽，不能阻塞控制链路。
- 图传拥塞只能导致图传帧丢弃，不能反压摄像头或感知。
- 控制命令队列容量小，采用最新有效命令优先；过期命令不得发送。
- 状态、健康和告警消息需要保留事件语义，不得全部用覆盖式队列。
- 每个队列必须记录容量、满队列策略、最大消息年龄和监控指标。

## 8. 时间与控制周期

- 设备源时间和算力板接收时间分别保存。
- 算力板内部超时使用单调时钟，不能用会跳变的系统墙钟。
- 控制线程按固定周期运行，而不是等待任意传感器消息后被动执行。
- 每次控制计算使用同一时刻附近的 PX4、视觉、雷达和目标数据快照。
- 超龄数据只能触发降级或告警，不能继续生成正常控制指令。
- 具体频率和超时通过性能测试确定并配置化。

## 9. 健康与控制权

`HealthManager` 分别维护：

- 设备在线状态。
- 数据新鲜度和质量。
- 算法运行状态。
- PX4 模式、armed、landed 和位置有效性。
- 地面站、遥控器和算力板控制权状态。
- 两套电源状态。
- 拦截设备能力状态。

状态机消费健康快照，不直接根据某一次读取失败做永久状态转移。故障严重度应随任务状态变化，例如摄像头故障在 GPS 接近阶段可降级，在视觉跟踪阶段则是关键故障。

## 10. 升级原则

- 摄像头协议变化只替换 `CameraReceiver`。
- 固定相机换云台时增加云台适配器并替换 `ICameraPoseProvider`。
- 更换 YOLO 模型或 NPU 后端不改变感知消息。
- 增加深度相机或多点雷达时扩展感知源，由融合层统一输出障碍状态。
- 从刹停升级到绕行时替换 `IObstacleAvoidanceStrategy`，不修改任务状态枚举。
- 更换 PX4 版本时由 `Px4Link` 适配消息和保护参数。
- 新增拦截手段只实现 `IInterceptionDevice`。
- 算法升级必须保持旧策略可回退，并支持仿真和录制数据回放对比。

## 11. 测试边界

- 通信适配器使用录制字节流和断线注入测试。
- 感知算法使用录制视频、雷达和姿态数据离线回放。
- 状态机使用模拟时钟和 mock 接口验证全部转移。
- 控制器先在 PX4 SITL 中验证，再做串口台架和受控飞行。
- 必测故障包括旧目标位置、旧视频帧、雷达异常、遥控器接管、算力板控制输出中断和 Home 无效。
