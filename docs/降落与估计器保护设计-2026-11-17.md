### 1.2 根因链

1. **罗盘 #1 失效**（MAG0 `bad_comms`/超时）→ 磁融合权重下降；
2. **Z 轴振动 5.24 m/s² + 加速度计削波** → `filter_fault_flags = 1024`（`fs_bad_acc_vertical`）；
3. 两个 EKF 实例同时置位 → **主滤波器切换** → **全状态重置**；
4. 重置把 local z 平移 9 m，而 `AUTO.LAND` 的位置设定值仍在**旧参考系**里：
   - 水平 → 凭空出现误差 → 位置环输出 45° 倾角；
   - 垂直 → 估计认为"离地 0.7 m" → **推力被砍**（以为已触地）；
5. **放大器：AUTO.LAND 全程无人监督**。本次从 27.5 m 降到触地约 60 s，其中 EKF 故障到翻转有 7 s，我们一秒钟都没参与。

实现要点：

- 订阅按 **`SET_MESSAGE_INTERVAL` 登记**：`config/config.json` 的 `px4.message_interval_requests`
  追加 `141@200000us`、`230@1000000us`、`241@1000000us`；**SITL 三份配置
  （`px4_sitl*.json`）各自维护同名字段，必须同步追加**，否则 SITL 里是按 PX4 默认频率
  收（实测 141 默认 ~10 Hz，VIBRATION 默认 0.5 Hz），测不到"我们登记的频率"有没有生效；
- 消息解析集中在 `px4_link.cpp` 的 `HandleXxx()` + 到达时间/计数模式，**高频热路径不打日志**；
- `STATUSTEXT` 单独做节流：同一文本 10 s 内只落一条，WARN 及以上全记，INFO 计数后丢弃。

**SITL 证据（2026-11-17 14:11~14:20，`tools/sitl_harness.sh smoke`）**：
补 SITL 配置前后各跑一次 60 s 基础场景——补之前 `ALTITUDE 601 条`（≈10 Hz，PX4 默认）、
`VIBRATION 30 条`（0.5 Hz）；补之后 `ALTITUDE 303 条`（5.05 Hz）、`VIBRATION 60 条`（1 Hz）、
`ESTIMATOR_STATUS 60 条`（1 Hz），说明频率登记确实下发到 PX4 了。起飞场景另外验证了
气压基准抓取：`起飞气压基准已锁定: amsl=0.22m` + 晚到补抓 `起飞气压基准已补抓: relative=0.01m`。

### 3.3 估计器健康判据（`EstimatorGuard`）

新增一个**纯函数模块**（建议 `include/state_machine/estimator_guard.h` +
`src/state_machine/estimator_guard.cpp`，便于单测），输入上一拍与当前拍快照，
输出 `kOk` / `kDegraded` 与结构化原因：

| 判据 | 触发条件（初值，全部进 config） | 说明 |
|---|---|---|
| z 单拍跳变 | `|Δz| > 0.5 m` 且 `|Δz| > 10 × |vz|·Δt + 0.1` | 现场是 9 m，稳过 |
| xy 单拍跳变 | `|Δxy| > 1.0 m` 且与 GPS 位移不一致 | 排除真实高速机动 |
| 估计器 flags | `flags` 命中 `bad_estimator_flag_mask`（掩码默认 **0=关闭**，见下） | 位语义随 MAVLink 方言变化，不能先验写死 |
| 估计器比值 | `pos_vert_ratio`/`pos_horiz_ratio`/`vel_ratio` 任一 > 1.0 持续 1 s | PX4 自己的可信度 |
| 传感器健康掉位 | `present & ~health` 命中 GYRO/ACCEL/MAG/AHRS，持续 1 s | 本次罗盘失效这条会亮 |
| 高度源不一致 | `|相对高度(EKF) − 气压相对高度| > 1.5 m` 持续 2 s | 交叉校验 |
| STATUSTEXT 关键字 | 含 `EKF`/`estimator`/`reset`/`arming denied` | 兜底 |
| 消息缺失 | `connected` 且 `LOCAL_POSITION_NED` 超过 500 ms 未更新 | 断链本身就要降级 |

**滞回与恢复**：判据置位后锁存（`estimator_degraded_`），**不自动恢复**，
只允许经"重置任务状态"（P4）或程序重启清除——避免抖动时反复切模式。

## 4. P2：S13 拆两段

### 4.1 时序

```

   │  到达 Home（水平 ≤ arrival_radius，稳定 arrival_hold）
   ▼
S13a  机载受控下降（Offboard 位置引导，我们全程持有控制权）
   │  · 水平目标：Home 上方（起飞原点优先）
   │  · 垂直目标：相对高度 = 1.2 m（配置）
   │  · 速度：0.8 m/s；低于 3 m 时 0.3 m/s
   │  · 每拍发布 position intent（reason_low = 12 降落下降），保持授权链
   │  · 每拍跑 §3.3 判据 + 两条额外保护（§4.5）
   ▼  判据命中：相对高度 ≤ 1.2 + 0.15 m、|vz| ≤ 0.2 m/s、
   │  水平误差 ≤ 0.5 m，且稳定保持 500 ms
S13b  交 PX4：发 DO_SET_MODE(AUTO.LAND 4/6)，确认后**停止发布 intent**
   │  · 由 PX4 land detector 判触地，COM_DISARM_LAND 自动上锁
   │  · 我们只监视 landed / armed（沿用现有分支）
   ▼  landed && !armed
S14   DISARMED，任务结束
```

### 4.2 状态与字段

不新增状态编号（S13 仍是 `kLanding`），内部用两个标志区分段：

```cpp
bool landing_descent_phase_ = true;    ///< true=S13a 机载下降；false=S13b 已交 PX4
bool landing_takeover_ = false;        ///< 沿用：PX4 接管/我们放手
std::chrono::milliseconds landing_descent_started_ms_ = 0;
bool landing_baro_mismatch_latched_ = false;
```

`TransitionTo(kLanding)` 的入口初始化（现有 `landing_command_sent_ = false` 等）追加
`landing_descent_phase_ = (enable_control && return_home_.enabled && !return_px4_takeover_)`。

**影子模式（`enable_control=false`）保持现状**：直接发 `AUTO.LAND`，不做 S13a ——
避免无控制输出时还去"发布意图"。

### 4.3 下降控制怎么发

复用 `PublishPositionIntent()`（S5/S12 同一出口），新增原因码
`kReasonLandingDescent = 12`：

| 字段 | 取值 |
|---|---|
| `target_x/y` | Home 水平（`return_origin_` 优先，否则 Home 经纬度） |
| `target_z` | `base_z − 相对高度目标`（`base_z` 取 `RelativeAltitudeBaseZ()`） |
| `max_speed_mps` | 0.8（≥3 m）/ 0.3（<3 m） |
| `feedforward_*` | 0（垂直不用前馈，避免叠加） |
| `yaw_valid` | false（下降不转机头，保持原航向） |
| `reason_low` | 12 |

> `RelativeAltitudeBaseZ()` 已在 `types.h` 里做了"优先 HOME_POSITION.z、PX4 重设 Home
> 时基准随坐标系平移"的处理，比裸 `takeoff_ref_local_z_m` 更抗漂移；但**它不抗本次这种
> 全状态重置**，所以 §4.5 的交叉校验与 §5 的降级判据必须同时生效。

### 4.4 切段的判据

```text
hold = 500 ms
相对高度 ≤ descend_target_ag_m + handover_alt_tolerance_m(0.15)
且 |vz| ≤ handover_vz_mps(0.2)
且 水平误差 ≤ handover_horizontal_m(0.5)
上述条件连续成立 hold
```

命中后：发 `AUTO.LAND`（失败按 `return_home.command_retry` 重试）→ 一旦确认
ACK `result=0` 或观察到 PX4 已不在 Offboard，置 `landing_descent_phase_ = false`
并**停止发布 intent**（让授权链按现有规则断开），进入 S13b。

### 4.5 三条保护（缺一不可）

| # | 保护 | 触发 | 动作 |
|---|---|---|---|
| **1** | **高度源交叉校验** | `baro_altitude_valid` 且 `|相对高度(EKF) − baro_relative_m| > 1.5 m` 持续 2 s | 锁存 + WARN + **立即跳 S13b**（提前交 PX4，不硬降到 1.2 m） |
| **2** | **低空水平漂移** | 相对高度 ≤ 3 m 且（水平误差 > 1.0 m 或地速 > 0.5 m/s） | **立即跳 S13b**，并把事件写日志（宁可让 PX4 落，也不在 1 m 高度画圈） |
| **3** | **控制权保持** | S13a 期间每拍必须发布 intent；若 intent 被 FlightController 拒绝（有限性/围栏/速度门禁） | 计数节流告警；连续 10 拍被拒不推进 → 跳 S13b |

另外两条兜底：

- **超时**：`landing.descent_timeout`（默认 120 s，27 m 按 0.8 m/s 约 33 s，留余量）到点即跳 S13b；
- **控制权被抢**：观察到 PX4 离开 Offboard 且非 AUTO.LAND → 沿用现有
  `landing_takeover_ = true`，只等落地（不抢回控制权）。

### 4.6 围栏与低空

S13a 的 intent 会经过现有的围栏钳制（`ClampIntoPolygon`）。Home 在围栏内时无影响；
若 Home 恰在边界外（不合法配置），钳制会把水平目标拉回界内 → 与"垂直下降"叠加后
落点偏移。**处理**：S13a 入口先判 Home 是否在围栏内，不在界内则**跳过 S13a**直接
S13b（并 WARN 说明原因）。

## 5. P3：EKF 降级处置（L1）

### 5.1 触发

§3.3 任一判据命中 → `estimator_degraded_ = true`，并在**任意状态**下生效（不只降落：
S5 接近段同样需要保护，本次事故只是恰好发生在降落）。

### 5.2 动作序列（一次，锁存）

1. `DO_SET_MODE(176)` → 主模式 **POSCTL（3/0）**（新增常量 `kPx4MainModePosctl = 3`）；
2. **停止发布 control intent**（POSCTL 由 PX4 位置环自己保持，Offboard 设定值不再有效）；
3. 状态机**冻结推进**：不进入 S13b、不触发返航、不自动降落；
4. 日志 WARN（含触发判据与数值），并在 65013 的健康段标出降级（见 §11 的未决 Q1）；
5. 若在 S13a：保留 S13 状态，等飞手/操作员处置；若落地且上锁，仍可正常走 S14。

### 5.3 明确不做的事

| 不做 | 原因 |
|---|---|
| 不自动降落 | EKF z 不可信时自动下降 = 重演本次事故 |
| 不自动 RTL | 水平估计同样不可信 |
| 不自动上锁 | 空中上锁 = 直接摔机 |
| 不自动重试切模式 | 模式切换本身会扰动姿态，锁存一次即可 |
| 不试图"纠偏"估计 | 我们无法知道偏移量，任何补偿都是猜 |

### 5.4 飞手提示

日志与界面都要明确"切 STABILIZED"：
- 机载日志：`估计器降级: 切 POSCTL 悬停，请飞手切 STABILIZED 接管`（含判据名、数值、
  判定耗时、模式命令是否已入队、当时状态；实际文案见 §5.6）；
- 65013 / 事件日志：红字提示（Web 侧文案见 §11 Q1 的取舍；**本期未做**）。

### 5.5 恢复

只允许：**重置任务状态（P4）** 或程序重启清除 `estimator_degraded_`。
若此时在飞，重置会被"未上锁"拒绝 → 必须先降落，符合预期。

## 6. P4：重置任务状态 = 清状态 + 重启 PX4

### 6.1 准入（新的判据表）

| 条件 | 要求 | 失败回执 |
|---|---|---|
| 遥测在线 | `latest_flight_` 有效且 `connected` | `kTelemetryStale`（**新增 reason=9**） |
| 未上锁 | `armed == false` | `kNotOnGround(8)` |
| 落地证据 | `landed_state_valid && landed`；不可用时退化为 `相对高度 ≤ 0.5 m`（基准可用时） | `kNotOnGround(8)` |
| 非故障态 | `mission_faulted_ == false` | `kMissionFault(7)` |
| 本次任务已收尾 | tracker 为终态；**不再**要求 `state == S14` | —— |

**与现状的差异**：删掉 `state != kDisarmed` 这道硬门槛（这正是"落地了却无法重置、只能
重启程序"的原因）；改用"飞控事实（上锁 + 落地）+ 遥测可用"作为门槛。
`airborne_task`（tracker 非终态）从"拒绝"降为 **WARN 后照常执行**（`ResetSortieState()`
本身就会 `assignment_tracker_ = MissionAssignmentTracker{}`）。

### 6.2 时序

```
收到 65020 type=2
  ├─ 判据不过 → 65021 kRejected + 对应 reason（不重启 PX4）
  └─ 判据通过
       1) 65021 kAccepted，reason=kNone（立即回，3 s 超时内）
       2) ResetSortieState()（现有清单）
       3) 发 MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN(246) param1=1
       4) 迁移到 S1 SELF_CHECK，置 px4_reboot_pending_ = true
       5) 等 PX4 回来：心跳 + AUTOPILOT_VERSION + GPS fix≥3 + 估计器健康
       6) 满足 → px4_reboot_pending_ = false，S1 → S2 READY
```

**状态编号复用 S1 SELF_CHECK**（不新增 S17）：语义就是"重新自检"，且
- 现有 `S1 → S2` 的迁移条件可复用；
- Web 已有 S1 文案，不需要改协议/前端映射；
- S1 期间 `BeginArmingSequence` 不可达 → 分配会被拒（正确语义）。

区分方式：`px4_reboot_pending_` + 日志前缀 `PX4 重启等待`，便于事后判读。

### 6.3 重启期间的行为约束

| 项 | 处理 |
|---|---|
| 控制输出 | 必须已 IDLE（准入已保证 `!armed`）；`px4_reboot_pending_` 期间**无论什么原因都不发 setpoint/命令** |
| 遥测 | `px4_link` 现有心跳超时会清空快照（`clearAircraftTelemetry`），沿用；日志区分"重启导致的断连"与"链路故障" |
| 命令重试 | 246 未确认时按 1 s 重试，最多 3 次；之后 WARN 并停在 S1 等心跳（**不无限重发**） |
| 超时 | `mission.reboot_timeout`（默认 90 s，PX4 冷启动 15~30 s，留余量）到点仍未回来 → 保持 S1 + ERROR 日志 + 65013 标故障（不自动重启机载程序） |
| 重复请求 | `mission.reboot_min_interval`（默认 30 s）内重复收到重置指令 → `kDuplicateCommand`/`kNotAirborne` 拒绝，避免把刚起来的飞控再打一遍 |

### 6.4 重启后必须重新确认的项（写进日志与文档）

- **Home** 由 PX4 重新计算 → 我们的 `home_valid` 会短暂失效，`return_origin_` 已在重置时清除；
- **电池保护参数**（`BAT_LOW_THR`/`COM_LOW_BAT_ACT`）与 `AUTOPILOT_VERSION` 需要重新读取（现有启动路径会自动做）；
- **起飞基准**（`takeoff_ref_*`/`home_local_z_*`）失效，下次解锁时重新抓取；
- **估计器**：重启只是重新初始化，**不修复硬件**。罗盘失效、Z 轴振动仍会再次触发故障——
  这是"重启治标不治本"的边界，文档与界面文案都要写明（§6.6）。

## 7. P5：雷达接入（本期只预留）

> **2026-11-17 维护者修订 D4：量程 ≥50 m 改为"12 m 够用"。** 原判据是"27 m 返航要覆盖
> 全程"，但 S13a 只负责**最后一段**（交段高度 1.2 m、S13b 判"离地 <1 m"），12 m 以上
> 根本不需要雷达——那里 baro/EKF 高度足够用，而本次事故的失效形态（"误判已落地 → 砍推力"）
> 只发生在低空。因此 TFmini-S/Plus（0.1~12 m）这类模块即可，不必为覆盖全程选 50 m 级雷达。
>
> **机制已核实**（2026-11-17 联网核对）：`DISTANCE_SENSOR` 除 `current_distance` 外还带
> `min_distance`/`max_distance`/`covariance`/`signal_quality`（百分比：0=未知、1=无效、
> 100=最好）。超出量程时传感器报"无有效测量"而非某个高度值；PX4 侧 EKF2 用
> `EKF2_RNG_QLTY_T`（质量需持续非零才判有效）、`EKF2_RNG_K_GATE`（与垂速的运动学一致性
> 门）等门槛把无效数据挡在融合之外，不会把"超量程"当成 0 m。参考：MAVLink `DISTANCE_SENSOR`
> 字段表、PX4《Distance Sensors》与 `ekf2_params.c`。
>
> **机载侧必须自己再判一遍**（不能只信驱动的 valid 位）：`signal_quality` 达阈值、
> `min_distance < current_distance < max_distance`、时效 ≤ 200 ms；任一不满足即"无测量"，
> **退到下一路高度源，绝不填 0 或填 max_distance**。

#### 7.1 实现修正（2026-11-18，软件侧落地时核对 PX4 源码后；**以本节为准**）

软件侧（单一高度出口 + S13a/S13b 判据 + 预检门禁 + SITL 装置）已落地，
`radar.enabled=false` 时行为与本次改动之前**逐位一致**。落地过程中核对 PX4 源码，
发现设计稿有 5 处必须修正：

1. **`SYS_STATUS.LASER_POSITION` 永远不置位，不能拿来做门禁。**
   `src/modules/mavlink/streams/SYS_STATUS.hpp` 的 `fillOutComponent()` 只填
   battery / motors_escs / parachute / accel / gyro / mag / gps / rc /
   attitude_estimation / local_position_estimate / AHRS / logging / pressure，
   **没有 distance_sensor 组件**；`MAV_SYS_STATUS_SENSOR_LASER_POSITION(bit8=0x100)`
   在整棵 `src/` 里只出现在 pymavlink 的测试数据中。
   → 门禁改为判 **`DISTANCE_SENSOR` 是否在报数**（`common::RadarAlive()`：收到过且时效内）。
   **不判读数量程**：落在地上的下视测距必然在盲区（TFmini-S 最小 0.4 m，装机后离地
   0.1~0.2 m），拿"读数量程有效"当起飞门禁等于任何时刻都拒绝起飞——这与 PX4 自己的
   `distanceSensorChecks` 口径一致（它判 topic 存在 + 时间戳 1 s 内，不判数值）。
   "PX4 要求装测距"交给参数 `SYS_HAS_NUM_DIST`（默认 0；>0 时 PX4 自己会在 ARM 时拒，
   `distanceSensorChecks.cpp`：`Preflight Fail: Distance Sensor 0 missing` /
   `No valid distance sensor 0 data`）。

2. **`signal_quality` 不能按"0=未知就算差"处理。** PX4 的出口把驱动的
   `quality<0`（**TFmini 与 SITL 的 gz 雷达都是这个情况**）映射成 MAVLink **0 = 未知**，
   把驱动 `quality==0` 映射成 **1 = invalid**，2~100 原样透传。
   → 0 必须视为"驱动没有质量指标"而**放行**；只有 2~100 才受 `radar.min_signal_quality`
   约束。若按 MAVLink 文档字面把 0 当"质量差"，TFmini 会**永远**被判无效。

3. **超量程的真实表现是"没有新数据"，不是某个哨兵值。** `TFMINI.cpp` 里
   `distance_m = -1` 起步，解析到 `0xFFFF`（无回波）时**不更新** `distance_m`，
   随后 `if (distance_m < 0.0f) return -EAGAIN;` —— **干脆不发布** `distance_sensor`。
   → `radar.stale_ms`（默认 200 ms）就是超量程的主要防线；"雷达突然没数据" ≈ "飞出量程"，
   不能当成链路故障。TFmini-S 量程 0.4~12 m（`set_min_distance(0.4f)/set_max_distance(12.0f)`）。

4. **`EstimatorGuard` 不加 `LASER_POSITION`，且雷达掉数据不判降级。**
   前者是死代码（位永远为 0，且 `critical_present` 为空时判据本就不触发）；
   后者是**设计意图**——雷达没了高度出口按 雷达→气压→EKF 退化，这是安全方向，
   在那儿切 POSCTL 冻结任务反而更危险。雷达退化只记 INFO（`S13a 高度源: …`）。

5. **`EKF2_RNG_A_HMAX` 元数据上限是 10.0 m，不是 12。** `params_range_finder.yaml`
   的 `min 1.0 / max 10.0`。`param set` 不做范围校验（写 12 会存成元数据外的值，
   地面站标红），而 10 m 以上本来就该停止融合，所以 SITL 装置取 **10**。
   `EKF2_HGT_REF` 也**不显式设置**：默认 1 已是 GPS（0=Baro/1=GPS/2=Range/3=Vision），
   显式写会覆盖现场基线；只要求"绝不能是 2（Range 主基准）"。

另外两条口径写进实现与文档：

- **`AboveTakeoffM()` 的退化链在 `radar.enabled=false` 时不启用**：那时决策高度**只用
  EKF 差分**（气压只做交叉校验），否则"回滚开关"会把 P2 调好的行为悄悄改成 baro 优先。
- **保护 1 的对照源随"正在用的高度源"切换**：用雷达 → 对照气压（气压不可用退到 EKF）；
  用气压 → 对照 EKF；用 EKF（旧路径）→ 对照气压。这样每一种来源都有一个独立见证。
- **S13b 落地确认门禁（`landing.landed_max_agl_m`）的能力边界**：只约束"我们是否认账并
  上锁"，**拦不住** PX4 自己在 `AUTO.LAND` 里做的 land detector 决策；矛盾超过
  `landed_agl_timeout` 仍按 PX4 处置并打 ERROR，避免雷达卡死时任务收不了尾。
  它同时**只在 `radar.enabled=true` 时生效**——用 EKF 给自己当见证等于自证。
