## 1. 先看结论

这是运行在香橙派RK3588上的C++17反无人机机载程序。当前正式程序已经具备：

- 摄像头H.265拉流、硬件解码、RKNN YOLO、检测框叠加、H.264编码和RTSP图传；
- USB双目UVC接入（MJPG SBS全幅采集、SBS左右拆分、左目进识别链路、右目仅统计），按`camera_source`与RTSP链路二选一装配；
- PX4 MAVLink 遥测与 setpoint 编码，控制装配在 `runtime.enable_control=true`（仓库默认）下完成绑定；
- 地面站MAVLink链路、TIMESYNC、目标UPDATE/ACK、健康和任务状态回传；
- HealthManager真实健康监控；
- MissionStateMachine任务状态机（S0~S16 意图链，接入 PX4 控制输出）；
- 地面站单目标位置的局部NED线性卡尔曼估计（**观测**：输出供状态机交接判据/热备份；
  可选融合双目视觉NED观测，`enable_visual_position_fusion`）；
- 单目标视觉稳定性判定的帧级锁定状态（**观测**，基于YOLO帧级观测）；
- 视觉跟踪控制律独立观察节拍（`VisualTrackingShadow` 发布 `kControlIntent` 到**无消费者的**
  观测 Topic，控制律的正式调用点在状态机 S7）；
- 双目测距 v2（`StereoRanger` 稀疏 Census 测距：预置矩阵校正 + 近端簇聚合，量程约 0.4~7.9m，
  输出供控制律距离通道，**观测**）。

当前明确没有：

- 光流正式实现；
- 感知融合正式实现；
- 多目标追踪正式接入；
- 独立雷达或独立电源管理；
- S8 避障、撞击剖面（`kImpact`）实现——**预留**。

**运行模式**（2026-11-17 重新定义，权威定义见
[`运行模式与模块状态定义.md`](运行模式与模块状态定义.md)）：
`config/config.json` 的 `runtime.enable_control=true`（2026-10-30 起为仓库默认）= **控制运行**，
装配层绑定 `Px4Setpoint`、注入 PX4 快照源与命令窄接口；`false` = **只读运行**，
仅用于地面排查（事故后采日志、链路排查、新机体首上电）。

**"控制运行"不等于"什么都会发"**：是否真的动作由各功能门禁决定
（`interception.enabled=false` 不自动拦截、`actuator.gcs_fire_enabled=false` 不装配 65016 直控、
`landing.enabled` 决定 S13 两段或回滚）。**功能代码不得按 `enable_control` 分支**——
只按可观测能力判断（命令接口是否注入、快照是否有效），理由与写法见上述定义文件 §2.1。

**PX4 已到位**（2026-10-10：装机体 + GPS，可出 Home），依赖 PX4 Home/姿态/位置的模块
（目标 NED 实链、状态机导航、控制律整定）已具备实链验证条件；视频链路与地面站物理链路
此前已完成验证。注意：**实链验证 ≠ 允许乱发控制**——控制运行下仍须遵守功能门禁与
[`PX4实链验证清单.md`](PX4实链验证清单.md) 的操作规程。

## 3. 状态标记

**权威定义见 [`运行模式与模块状态定义.md`](运行模式与模块状态定义.md)**，此处只列速查。
2026-11-17 起**不再使用"影子"作为状态词**（旧口径已归档到
[`archive/影子模式与状态标记-历史定义-2026-11-17.md`](archive/影子模式与状态标记-历史定义-2026-11-17.md)）。

| 状态 | 含义 |
|---|---|
| 正式 | 已进入`DroneApplication`实际装配，输出被决策/控制链**消费** |
| 观测 | 已装配、跑真实算法，但输出只进观测/诊断或无消费者的观测 Topic，不产生控制输出（**设计边界**，不是"没做完"） |
| 预留 | 接口/配置/骨架已定，实现未接入 |
| Stub | 只有接口或占位生命周期，没有正式业务算法 |
| 独立 | 单独子工程或工具，未进入正式`DroneApplication` |
| 阻塞 | 缺硬件资料、标定或实机条件，禁止猜测实现 |

**运行模式与状态表正交**：`runtime.enable_control` 只决定"本次运行发不发控制"
（控制运行/只读运行），不改变模块状态。

## 4. 程序入口和装配顺序

正式入口是：

```text
main.cpp
  → 查找并解析config/config.json
  → 初始化异步文件日志
  → 创建DroneApplication
  → BuildComponents()创建组件
  → BindTopics()连接Topic
  → Start()按依赖顺序启动线程
  → 等待SIGINT/SIGTERM
  → Stop()按数据流逆序停止
```

关键文件：

| 作用 | 文件 |
|---|---|
| 进程入口、信号和配置路径 | `main.cpp` |
| 组件所有权、Topic接线、启动停止 | `src/application/drone_application.cpp` |
| 强类型配置 | `include/config/config.h`、`src/config/config.cpp` |
| 公共消息和Topic名称 | `include/common/types.h` |
| 发布订阅实现 | `include/common/topic.h` |

禁止把业务算法写进`main.cpp`或`DroneApplication`。`DroneApplication`只负责创建、接线和生命周期。

## 5.1 单目标视觉观测链路

YOLO有两类输出，职责不同：

```text
DetectionResult          每目标一条，供叠加器画框；空帧不发布
VisualTargetObservation  每个成功推理帧恰好一条，允许detected=false
```

两者的区别是这份工程里最重要的一个设计点：

```text
YOLO输入队列容量为1，会主动丢弃解码帧
→ 解码25FPS、推理约24FPS，两者并不一一对应
→ 因此不能拿“解码帧序号”当视觉节拍
→ 只能靠“每个成功推理帧一条观测”判断“本帧是否确实没有目标”
```

基于帧级观测，`VisualTargetMonitor` 维护：

- 连续检测帧数、连续丢失帧数；
- 平滑后的目标像素中心和置信度；
- 稳定性状态：`SEARCHING / ACQUIRING / LOCKED / LOST`；
- 观测超时（YOLO线程停止或卡死）与“本帧无目标”的区分。

当前该状态只发布到 `kVisualTargetStatus`，没有任何正式消费者，不参与状态机和控制。

## 6. 视频链路逐段说明

### 6.1 摄像头接收

```text
输入：camera_source=rtsp → camera.rtsp_url
组件：CameraReceiver
输出：EncodedFrame（H.264/H.265）
```

```text
输入：camera_source=uvc → video.uvc_device（如 /dev/video0）
组件：UvcCameraReceiver
输出：EncodedFrame（kMjpeg，一帧一个访问单元、皆关键帧、无参数集）
```

两种视频输入实现同一`ICameraReceiver`接口，按`video.camera_source`二选一装配：

- `CameraReceiver`使用FFmpeg拉取RTSP，按访问单元发布H.264/H.265码流，并单独传递流级参数集。它不解码、不做YOLO、不推流。
- `UvcCameraReceiver`经V4L2 mmap从UVC设备读取MJPG SBS帧（如2560×720@30），逐帧发布；open失败/流错误自动重连（默认3秒），健康计数与RTSP接收共用`kCamera`健康源。它不解码、不拆分双目。

### 6.2 视频解码

```text
输入：EncodedFrame（H.264/H.265/MJPEG）
组件：VideoDecoder
输出：FrameHandle（当前为NV12）
```

香橙派优先使用rkmpp硬解（含mjpeg_rkmpp，存在与否取决于ffmpeg-rockchip版本，找不到走软解属预期）。硬解设备上下文两级探测：先运行时探测ffmpeg-rockchip 8.1的`rkmpp`设备类型，探测不到回退`DRM`类型（兼容旧fork/FFmpeg 6.1）。

硬解输出DRM PRIME帧：hevc/h264为NV12，**mjpeg_rkmpp为NV16**（YCbCr422SP）。线性单对象布局满足严格校验时，用RGA DMA-BUF直传到`VideoFramePool`——NV12走`imcopy`纯拷贝，NV16走`imcvtcolor`在解码器内转NV12入池，下游（拆分器/YOLO/叠加/编码）零改动；不满足或失败时自动回退FFmpeg转存（NV16转存帧由sws转NV12）。

MJPG语义：每帧独立（皆关键帧、无参数集、帧间无依赖），单帧解码失败计`DroppedFrameCount`继续，无H.26x的参数集同步问题。UVC链路解码输出为全幅SBS（如2560×720）。

编码侧同样rkmpp优先：h264可用`h264_rkmpp`硬编（带私有选项`rc_mode=VBR`、`rc_max_rate`=配置码率），不存在或打开失败自动回退libx264软编。

### 6.2.1 双目SBS拆分（仅camera_source=uvc且stereo_split=true）

```text
输入：全幅SBS解码帧（2560×720 NV12）
组件：StereoFrameSplitter
输出：左目FrameHandle（1280×720）→ kDecodedFrameLeft → YOLO/叠加；
     右目FrameHandle → kDecodedFrameRight → StereoRanger 辅助图（仅 enable_stereo_ranging=true；
     否则无消费者，仅计数）
```

RGA `imcrop`优先（`DRONE_HAVE_RGA_DMA`），失败/无RGA回退逐行memcpy；左右各一个自有帧池，独立容错。拆分器不注册健康源；**左右目物理对应已实证（2026-09-22）：SBS左半幅=物理右目**，拆分器x_offset已按此交换——左目Topic取右半幅=物理左目，语义与物理方位一致（见`include/video/stereo_frame_splitter.md`）。测距由下游 StereoRanger 观测支路承担（§9.3；v2 稀疏 Census，仅在基准图跑检测，无右目推理）。

### 6.3 YOLO

```text
输入：FrameHandle
组件：YoloDetector + RknnDetectionBackend
输出：DetectionResult
```

YOLO输入队列当前容量为1，队列满时丢旧留新。一帧检测出N个框就发布N条`DetectionResult`；一帧没有目标时当前不发布检测消息。模型输出后处理最多保留128个框。

### 6.4 叠加

`FrameCompositor`同时订阅解码帧和检测结果，根据`frame_sequence`将检测框画到对应或允许滞后范围内的帧上，再发布标注帧。它不执行推理。

### 6.5 编码和图传

`VideoSender`消费标注帧，内部调用编码后端，香橙派优先使用`h264_rkmpp`，输出到本地MediaMTX RTSP地址，再由HM30网络链路送到地面站。

### 6.6 视频所有权

视频像素通过`VideoFramePool`和`FrameHandle`管理：

- 不使用裸指针管理帧生命周期；
- 最后一个句柄释放后缓冲自动归还内存池；
- 内存池耗尽时丢帧，不阻塞采集线程；
- 视频延迟探针会独占摄像头、NPU和本地RTSP路径，不能与正式程序同时运行。

## 7. PX4链路

`Px4Link`负责：

- 串口或UDP传输；
- MAVLink 1/2解析；
- 目标PX4身份过滤；
- 心跳、GPS、全局/局部位置、姿态、电池、Home等快照；
- 命令ACK关联；
- `Px4Setpoint`编码为`SET_POSITION_TARGET_LOCAL_NED`的底层能力。

当前正式应用只绑定：

```text
Px4Link::StateOutput()
```

没有调用：

```cpp
px4_link_->SetInput(...);
```

因此即使`Px4Link`包含setpoint能力，正式程序也没有数据进入该出口。

PX4 **未连接**时（串口松动等仍可能出现）：

- `/dev/ttyS1`连接失败或串口读错误后按 `reconnect_interval` 自动重连属于预期降级；
  重连期间发布 `connected=false` 快照，控制器授权链撤权停发，进程不退出；
- `FlightStateSnapshot.home_valid`不会成立；
- MissionStateMachine停留在自检；
- TargetEstimator等待 EKF 锚点（`GPS_GLOBAL_ORIGIN` #49 流），不发布有效NED状态；
- 禁止在正式程序中自动伪造PX4状态。

PX4 **已连接**时（2026-10-10 起现场具备：装机体 + GPS）：

- 心跳/遥测建立，`home_valid` 可成立，状态机可越过自检，TargetEstimator 出有效 NED 观测状态；
- 若仍停留自检/等待锚点：先看「PX4 心跳已连接」是否出现——**室内拿不到 GPS fix/Home/锚点
  时停留自检属预期，不是通信问题**；有心跳后按 心跳 → GPS fix → Home 顺序排查
  （见`docs/故障排查手册.md` 与`docs/PX4实链验证清单.md`）；
- 控制出口仍不绑定 setpoint。

## 8. 地面站链路

`GroundStationLink`通过`/dev/ttyS6`和地面站通信。

下行：

- 标准心跳、GPS、全局/局部位置、姿态、电池、Home等；
- 65012健康状态；
- 65013任务状态。

上行：

### 9.3 StereoRanger 双目测距 v2（稀疏 Census，观测；实机精度验证在独立测试工程）

```text
kDetection（基准图检测框，原始左图坐标）
  + kDecodedFrameLeft（基准=SBS右半=物理左目）+ kDecodedFrameRight（辅助=SBS左半）

  → 预置矩阵校正（以 cam2/SBS 右半为基准）→ 行带 remap
  → Shi-Tomasi 关键点 + Census 7×7 稀疏匹配（粗/精/亚像素/唯一性/左右一致）
  → bbox 近端簇聚合 Z = fxB/d（fxB=63.57 m·px，量程≈0.4~7.9m）+ EMA
  → StereoTargetDistance
```

输出只接 `VisualTrackingShadow` 距离通道（可选输入）：valid 且未超龄的距离透传给控制律距离 PID 做观测记录，无效/未接线回落 `no_distance_action=kSlowApproach` 定速接近。不产生真实控制输出，不注册健康源；只在基准图跑检测（无右目检测实例）。校正矩阵由 `tools/camera_calibration/export_rectify.py` 预置（C++ 不依赖 OpenCV）。实现细节见 `include/perception/stereo_ranger.md`。

```text
          + 65015 cancelled_by_gcs(12) + TransitionTo(kReturnHome)
  → kMissionCommandAck ──65021──▶ 地面站（result/reason/mission_state）
返航轨迹由 S12 位置意图控制（不是 PX4 RTL）；地面站仅"请求"，是否执行由机载判定。
```


### 自动起飞数据流（2026-10-22，Task 5/6/9）

```text
地面站 65014 → GroundStationLink::MissionAssignmentOutput()
  → MissionStateMachine::SetAssignmentInput（生产装配已接线，Task 9）
  → S2 预检 → S3(kArming)（65015 回执经 AssignmentAckOutput → GroundStationLink）
  → 每决策拍发布 kTakeoff 意图（起飞原点 x0/y0/z0，reason_code bit31）
  → FlightController：门禁全通进入 kBootstrap，每拍发布原点保持 kPosition 流
  → Px4Link → PX4（Offboard 前置 setpoint 流先于模式/解锁建立）
  → 状态机等待 bootstrap_lead → 发 176(Offboard) → 400(arm)
  → PX4 快照 armed && Offboard(6/0) → FlightController 转 kActive
  → S4 每决策拍抬升 z 目标（climb_rate_mps）直至任务高度
S5 位置引导：TargetState（TargetEstimator）+ VisualTargetStatus + StereoTargetDistance
  → MissionStateMachine::SetEstimationInputs（三者齐备时，Task 9）
S5 目标失效原地保持（2026-10-22）：估计/65010 不可用但 PX4 局部位置有效
  → 每拍发 kPositionGuide（目标=PX4 当前位置，reason_code=bit31|9，无前馈）
  → FlightController 维持 ACTIVE、PX4 维持 Offboard
  → 连续 3 拍新鲜才回引导；累计保持超 takeoff.target_hold_max_ms → 65015
    aborted → S12 机载位置返航；65013 置 bit5
```

- 生产装配（`DroneApplication`）已接 65014/65015 与估计输入；只读运行时
  不注入命令接口，65014 回 `control_disabled`，因此整条链不产生控制输出；
- `takeoff` 整节与 `expected_interceptor_type`（取
  `ground_station.aircraft_component_id`）由装配层注入状态机；
- `kBootstrap` 门禁**不读取 RC 字段**（`rc_state_valid`/`rc_connected`/
  `manual_override_active`），RC 由 PX4 自己管理；
- bootstrap 条件失效/意图撤销/超时只回 IDLE 停流（`valid=false`），
  不进入 COAST；
- 控制器 `bootstrap_timeout` 是状态机 S3 模式/解锁超时之外的防卡死兜底，
  装配时取 `takeoff.bootstrap_timeout`（局部副本）；实现细节见
  `include/control/flight_controller.md`「自动起飞预授权」。

意图输入纪律：FlightController 只接 `MissionStateMachine::IntentOutput()`；`VisualTrackingShadow` 的观测意图不带授权请求位（`reason_code` bit31，`common::kControlIntentReasonRequestControl`），若接入控制器会每拍清锁存压死授权门禁，永不接线。装配状态可用 `DroneApplication::ControlAssembly()` 快照断言（`drone_application_test` 覆盖两种运行模式）。

任何修改只要让`Px4Setpoint`进入`Px4Link`，都属于安全边界变化，必须先完成代码评审、SITL、拆桨台架和明确授权。

## 11. 当前实际线程

项目早期文档中的“7个线程”是逻辑规划。当前实现按组件拆分，全部启用时可能存在以下工作线程：

| 线程 | 所属组件 | 主要工作 |
|---|---|---|
| 摄像头线程 | CameraReceiver或UvcCameraReceiver（按`camera_source`二选一） | RTSP读取或V4L2 UVC采集与码流发布 |
| 解码线程 | VideoDecoder | 解码和帧池输出 |
| 双目拆分线程 | StereoFrameSplitter（仅stereo_split=true） | SBS左右目裁剪和各自帧池输出 |
| YOLO线程 | YoloDetector | 预处理、RKNN推理、检测发布和帧级观测发布 |
| 双目测距线程 | StereoRanger（仅enable_stereo_ranging=true） | 帧/检测批次配对、稀疏 Census 测距、距离发布（观测） |
| 视觉跟踪观测节拍线程 | VisualTrackingShadow（观测） | 20Hz固定节拍（`shadow.frequency_hz`）跑跟踪控制律，发布到无消费者的观测 Topic |
| 视觉稳定性判定线程 | VisualTargetMonitor | 连续检测/丢失计数与锁定状态发布（观测） |
| 叠加线程 | FrameCompositor | 帧与检测聚合、画框 |
| 图传线程 | VideoSender | 编码和RTSP写出 |
| PX4线程 | Px4Link | MAVLink收发、状态和ACK |
| 地面站线程 | GroundStationLink | MAVLink收发、TIMESYNC和遥测 |
| 目标估计线程 | TargetEstimator | 单目标线性卡尔曼与周期输出（观测） |
| 状态机线程 | MissionStateMachine | 周期决策与任务状态发布（正式） |
| 飞行控制线程 | FlightController（正式实现；装配行为由运行模式决定） | 固定周期（controller.period_ms）消费意图、门禁链+限幅流水线、Px4Setpoint发布 |
| 健康监控线程 | HealthManager | 新鲜度和CPU负载汇总 |
| 健康采样桥接线程 | DroneApplication | 把模块计数变化转换为健康上报 |
| 主线程 | main.cpp | 信号等待和进程生命周期 |

辅助纯算法对象如`MavlinkHandler`、`LinearTargetKalmanFilter`、`GeodeticToLocalNed`、`VideoFramePool`本身不创建线程。

## 13. 当前硬件条件下怎样运行

### 13.1 只验证视频

```json
"runtime": {
  "enable_video": true,
  "enable_px4": false,
  "enable_ground_station": false,
  "enable_target_estimator": false,
  "enable_control": false
}
```

运行：

```bash
./build/drone_control --config <视频台架配置路径>
```

或使用独占视频探针：

```bash
./build/video_latency_probe --config <配置路径> --duration 60 --interval 5
```

### 13.2 验证地面站目标协议

现有正式配置要求地面站链路依赖PX4状态源。PX4 未连接时，不应放宽正式配置校验或伪造Home；PX4 已到位后**优先用真实 PX4 做实链验证**，原计划的独立无PX4台架工具降为可选补充（若使用，必须显式传入模拟Home并标记`SIMULATED`，且不得创建Px4Link或发送控制）。
