# 项目总览与数据流

> 适用对象：第一次接触工程、排查跨模块问题、准备增加设备或功能的维护者。  
> 本文只描述**当前源码实际实现和实际装配**，不把规划中的能力写成已经完成。  
> 最后更新：2026-09-11。

## 1. 先看结论

这是运行在香橙派RK3588上的C++17反无人机机载程序。当前正式程序已经具备：

- 摄像头H.265拉流、硬件解码、RKNN YOLO、检测框叠加、H.264编码和RTSP图传；
- PX4 MAVLink遥测和底层setpoint编码能力，但正式应用没有连接控制输入；
- 地面站MAVLink链路、TIMESYNC、目标UPDATE/ACK、健康和任务状态回传；
- HealthManager真实健康监控；
- MissionStateMachine安全影子状态；
- 地面站单目标位置的局部NED线性卡尔曼影子估计；
- 单目标视觉稳定性判定的帧级影子状态（基于YOLO帧级观测）。

当前明确没有：

- 正式飞行控制输出；
- 双目深度实现；
- 光流正式实现；
- 感知融合正式实现；
- 多目标追踪正式接入；
- 独立雷达或独立电源管理。

安全配置必须保持：

```json
"enable_control": false
```

当前现场只有香橙派、摄像头、图传和地面站，没有PX4，因此只能完整验证视频链路和地面站物理链路。依赖PX4 Home/姿态/位置的模块只能做开发机单元测试或后续独立无PX4台架工具验证。

## 3. 状态标记

本文统一使用以下状态：

| 状态 | 含义 |
|---|---|
| 正式 | 已进入`DroneApplication`实际装配，处理真实数据 |
| 影子 | 运行真实算法并发布状态，但输出不产生飞行控制 |
| Stub | 只有接口或占位生命周期，没有正式业务算法 |
| 独立 | 单独子工程或工具，未进入正式`DroneApplication` |
| 阻塞 | 缺硬件资料、标定或实机条件，禁止猜测实现 |

## 4. 程序入口和装配顺序

正式入口是：

```text
main.cpp
  → 查找并解析config/config.json
  → 初始化异步文件日志
  → 创建DroneApplication
  → BuildComponents()创建组件
  → BindTopics()连接Topic
  → Start()按依赖顺序启动线程
  → 等待SIGINT/SIGTERM
  → Stop()按数据流逆序停止
```

关键文件：

| 作用 | 文件 |
|---|---|
| 进程入口、信号和配置路径 | `main.cpp` |
| 组件所有权、Topic接线、启动停止 | `src/application/drone_application.cpp` |
| 强类型配置 | `include/config/config.h`、`src/config/config.cpp` |
| 公共消息和Topic名称 | `include/common/types.h` |
| 发布订阅实现 | `include/common/topic.h` |

禁止把业务算法写进`main.cpp`或`DroneApplication`。`DroneApplication`只负责创建、接线和生命周期。

## 5. 当前总数据流

```text
                              ┌──────────────── 视频链路 ────────────────┐
摄像头RTSP/H.265
  → CameraReceiver
  → Topic<EncodedFrame> kCameraStream
  → VideoDecoder
  → Topic<FrameHandle> kDecodedFrame
       ├→ YoloDetector
       │    ├→ Topic<DetectionResult> kDetection ─┐
       │    │   （每目标一条；空帧不发布）           │
       │    └→ Topic<VisualTargetObservation> kVisualTarget
       │        （每成功推理帧一条，允许无目标）
       │             ↓
       │        VisualTargetMonitor（影子）
       │             ↓
       │        Topic<VisualTargetStatus> kVisualTargetStatus
       │        （当前无正式消费者）
       └──────────────────────────────────────────┤
                                                  ↓
                                           FrameCompositor
                                                  ↓
                                  Topic<FrameHandle> kAnnotatedFrame
                                                  ↓
                                             VideoSender
                                                  ↓
                                        H.264/本地RTSP/HM30
                              └───────────────────────────────────────────┘

PX4串口 /dev/ttyS1（当前现场缺失）
  → Px4Link
  → Topic<FlightStateSnapshot> kFlightState
       ├→ GroundStationLink → 标准MAVLink遥测 → /dev/ttyS6 → 地面站
       ├→ MissionStateMachine（影子）
       └→ TargetEstimator（只读取PX4 Home）

地面站 → /dev/ttyS6 → GroundStationLink
  → TIMESYNC和65010目标校验
  → Topic<GroundStationTarget> kGroundTarget
       ├→ MissionStateMachine（影子状态）
       └→ TargetEstimator（单目标线性卡尔曼影子）
             → Topic<TargetState> kEstimatedTarget
             → 当前没有正式消费者

各正式模块计数/错误
  → DroneApplication健康上报线程
  → HealthManager
  → Topic<HealthStatus> kHealthStatus
       ├→ MissionStateMachine
       └→ GroundStationLink → 65012 HEALTH_STATUS → 地面站

MissionStateMachine
  → Topic<MissionStatus> kMissionStatus
  → GroundStationLink → 65013 MISSION_STATUS → 地面站
```

## 5.1 单目标视觉观测链路

YOLO有两类输出，职责不同：

```text
DetectionResult          每目标一条，供叠加器画框；空帧不发布
VisualTargetObservation  每个成功推理帧恰好一条，允许detected=false
```

两者的区别是这份工程里最重要的一个设计点：

```text
YOLO输入队列容量为1，会主动丢弃解码帧
→ 解码25FPS、推理约24FPS，两者并不一一对应
→ 因此不能拿“解码帧序号”当视觉节拍
→ 只能靠“每个成功推理帧一条观测”判断“本帧是否确实没有目标”
```

基于帧级观测，`VisualTargetMonitor` 维护：

- 连续检测帧数、连续丢失帧数；
- 平滑后的目标像素中心和置信度；
- 稳定性状态：`SEARCHING / ACQUIRING / LOCKED / LOST`；
- 观测超时（YOLO线程停止或卡死）与“本帧无目标”的区分。

当前该状态只发布到 `kVisualTargetStatus`，没有任何正式消费者，不参与状态机和控制。

## 6. 视频链路逐段说明

### 6.1 摄像头接收

```text
输入：camera.rtsp_url
组件：CameraReceiver
输出：EncodedFrame
```

`CameraReceiver`使用FFmpeg拉取RTSP，按访问单元发布H.264/H.265码流，并单独传递流级参数集。它不解码、不做YOLO、不推流。

### 6.2 视频解码

```text
输入：EncodedFrame
组件：VideoDecoder
输出：FrameHandle（当前为NV12）
```

香橙派优先使用rkmpp硬解。线性NV12 DRM PRIME布局满足严格校验时，使用RGA DMA-BUF复制到`VideoFramePool`；不满足时自动回退FFmpeg转存。

### 6.3 YOLO

```text
输入：FrameHandle
组件：YoloDetector + RknnDetectionBackend
输出：DetectionResult
```

YOLO输入队列当前容量为1，队列满时丢旧留新。一帧检测出N个框就发布N条`DetectionResult`；一帧没有目标时当前不发布检测消息。模型输出后处理最多保留128个框。

### 6.4 叠加

`FrameCompositor`同时订阅解码帧和检测结果，根据`frame_sequence`将检测框画到对应或允许滞后范围内的帧上，再发布标注帧。它不执行推理。

### 6.5 编码和图传

`VideoSender`消费标注帧，内部调用编码后端，香橙派优先使用`h264_rkmpp`，输出到本地MediaMTX RTSP地址，再由HM30网络链路送到地面站。

### 6.6 视频所有权

视频像素通过`VideoFramePool`和`FrameHandle`管理：

- 不使用裸指针管理帧生命周期；
- 最后一个句柄释放后缓冲自动归还内存池；
- 内存池耗尽时丢帧，不阻塞采集线程；
- 视频延迟探针会独占摄像头、NPU和本地RTSP路径，不能与正式程序同时运行。

## 7. PX4链路

`Px4Link`负责：

- 串口或UDP传输；
- MAVLink 1/2解析；
- 目标PX4身份过滤；
- 心跳、GPS、全局/局部位置、姿态、电池、Home等快照；
- 命令ACK关联；
- `Px4Setpoint`编码为`SET_POSITION_TARGET_LOCAL_NED`的底层能力。

当前正式应用只绑定：

```text
Px4Link::StateOutput()
```

没有调用：

```cpp
px4_link_->SetInput(...);
```

因此即使`Px4Link`包含setpoint能力，正式程序也没有数据进入该出口。

当前没有PX4时：

- `/dev/ttyS1`连接失败或持续重连属于预期降级；
- `FlightStateSnapshot.home_valid`不会成立；
- MissionStateMachine停留在自检；
- TargetEstimator等待PX4 Home，不发布有效NED状态；
- 禁止在正式程序中自动伪造PX4状态。

## 8. 地面站链路

`GroundStationLink`通过`/dev/ttyS6`和地面站通信。

下行：

- 标准心跳、GPS、全局/局部位置、姿态、电池、Home等；
- 65012健康状态；
- 65013任务状态。

上行：

- 固定来源身份`255/190`的GCS心跳；
- 标准TIMESYNC；
- 65010 `TRACK_TARGET_UPDATE`；
- 65011 `TRACK_TARGET_ACK`。

合法目标发布为`GroundStationTarget`。通信层只负责协议、身份、序号和时效校验，不负责目标滤波或飞行控制。

## 9. 影子链路

### 9.1 MissionStateMachine

当前状态机只验证：

```text
PX4导航状态 + 地面站目标 + 健康状态
```

可以发布任务状态并影子进入`GPS_APPROACH`，但不执行ARM、起飞或位置引导，不发布真实控制意图。

### 9.2 TargetEstimator

第一阶段数据流：

```text
PX4 Home + GroundStationTarget
  → WGS-84到局部NED
  → [N,E,D,VN,VE,VD]恒速度线性卡尔曼
  → TargetState
```

当前输出没有接入状态机或控制器。高度不是有效MSL时，Z/VZ使用NaN，不伪造为0。目标过期、目标ID变化或Home变化会按规则失效或重置。

## 10. 当前不存在的控制数据流

设计上的未来控制链是：

```text
MissionStateMachine/策略
  → ControlIntent
  → FlightController
  → Px4Setpoint
  → Px4Link
  → PX4
```

当前实际情况：

```text
MissionStateMachine.IntentOutput()：没有正式控制意图
FlightController：Stub
Px4Link::SetInput()：未绑定
runtime.enable_control：false
```

任何修改只要让`Px4Setpoint`进入`Px4Link`，都属于安全边界变化，必须先完成代码评审、SITL、拆桨台架和明确授权。

## 11. 当前实际线程

项目早期文档中的“7个线程”是逻辑规划。当前实现按组件拆分，全部启用时可能存在以下工作线程：

| 线程 | 所属组件 | 主要工作 |
|---|---|---|
| 摄像头线程 | CameraReceiver | RTSP读取和码流发布 |
| 解码线程 | VideoDecoder | 解码和帧池输出 |
| YOLO线程 | YoloDetector | 预处理、RKNN推理、检测发布和帧级观测发布 |
| 视觉稳定性判定线程 | VisualTargetMonitor | 连续检测/丢失计数与锁定状态影子发布 |
| 叠加线程 | FrameCompositor | 帧与检测聚合、画框 |
| 图传线程 | VideoSender | 编码和RTSP写出 |
| PX4线程 | Px4Link | MAVLink收发、状态和ACK |
| 地面站线程 | GroundStationLink | MAVLink收发、TIMESYNC和遥测 |
| 目标估计线程 | TargetEstimator | 单目标线性卡尔曼和周期影子输出 |
| 状态机线程 | MissionStateMachine | 周期影子决策和任务状态发布 |
| 健康监控线程 | HealthManager | 新鲜度和CPU负载汇总 |
| 健康采样桥接线程 | DroneApplication | 把模块计数变化转换为健康上报 |
| 主线程 | main.cpp | 信号等待和进程生命周期 |

辅助纯算法对象如`MavlinkHandler`、`LinearTargetKalmanFilter`、`GeodeticToLocalNed`、`VideoFramePool`本身不创建线程。

## 12. Topic连接总表

| Topic常量 | 消息类型 | 当前生产者 | 当前消费者 |
|---|---|---|---|
| `kCameraStream` | `EncodedFrame` | CameraReceiver | VideoDecoder |
| `kDecodedFrame` | `FrameHandle` | VideoDecoder | YoloDetector、FrameCompositor |
| `kDetection` | `DetectionResult` | YoloDetector | FrameCompositor |
| `kVisualTarget` | `VisualTargetObservation` | YoloDetector | VisualTargetMonitor |
| `kVisualTargetStatus` | `VisualTargetStatus` | VisualTargetMonitor | 当前无正式消费者 |
| `kAnnotatedFrame` | `FrameHandle` | FrameCompositor | VideoSender |
| `kFlightState` | `FlightStateSnapshot` | Px4Link | GroundStationLink、MissionStateMachine、TargetEstimator |
| `kGroundTarget` | `GroundStationTarget` | GroundStationLink | MissionStateMachine、TargetEstimator |
| `kHealthStatus` | `HealthStatus` | HealthManager | MissionStateMachine、GroundStationLink |
| `kMissionStatus` | `MissionStatus` | MissionStateMachine | GroundStationLink |
| `kEstimatedTarget` | `TargetState` | TargetEstimator | 当前无正式消费者 |
| `kOpticalFlow` | `OpticalFlowResult` | 当前无正式生产者 | 未装配 |
| `kLaserRange` | `LaserRangeSample` | 兼容Stub | 未装配 |
| `kFusedTarget` | `TargetState` | PerceptionFusion Stub | 未装配 |
| `kControlIntent` | `ControlIntent` | 当前无正式生产者 | FlightController Stub |
| `kPx4Setpoint` | `Px4Setpoint` | FlightController Stub | 正式Px4Link未绑定 |

Topic对象通常由生产组件拥有，消费者通过组件的`Output()`方法订阅，不存在全局消息总线实例。

## 13. 当前硬件条件下怎样运行

### 13.1 只验证视频

复制一份配置，不要直接破坏生产配置，并设置：

```json
"runtime": {
  "enable_video": true,
  "enable_px4": false,
  "enable_ground_station": false,
  "enable_target_estimator": false,
  "enable_control": false
}
```

运行：

```bash
./build/drone_control --config <视频台架配置路径>
```

或使用独占视频探针：

```bash
./build/video_latency_probe --config <配置路径> --duration 60 --interval 5
```

### 13.2 验证地面站目标协议

现有正式配置要求地面站链路依赖PX4状态源。没有PX4时，不应放宽正式配置校验或伪造Home。后续应增加独立无PX4台架工具，在工具中显式传入模拟Home，并明确标记`SIMULATED`；该工具不得创建Px4Link或发送控制。

## 14. 修改代码从哪里开始

- 不知道消息字段：先看`include/common/types.h`和`docs/数据接口文档.md`；
- 不知道组件在哪里创建：看`DroneApplication::BuildComponents()`；
- 不知道Topic在哪里接：看`DroneApplication::BindTopics()`；
- 不知道线程在哪里启动：搜索该组件`Start()`和`std::thread`；
- 不知道配置来源：看`config/config.json`、`config.h`、`config.cpp`；
- 不知道错误怎样观测：看组件头文件中的计数接口和对应实现文档；
- 不知道测试在哪里：看`docs/模块索引.md`或`CMakeLists.txt`测试目标；
- 要增加设备：严格按`docs/新增设备接入指南.md`执行。
