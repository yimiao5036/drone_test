# 项目总览与数据流

> 适用对象：第一次接触工程、排查跨模块问题、准备增加设备或功能的维护者。  
> 本文只描述**当前源码实际实现和实际装配**，不把规划中的能力写成已经完成。  
> 最后更新：2026-10-21（捕网执行器 ACK 复位时序/S16、Px4Link 串口重连、G4 台架自动部分；当前状态与门禁见 [`开发进度.md`](开发进度.md)）。

## 1. 先看结论

这是运行在香橙派RK3588上的C++17反无人机机载程序。当前正式程序已经具备：

- 摄像头H.265拉流、硬件解码、RKNN YOLO、检测框叠加、H.264编码和RTSP图传；
- USB双目UVC接入（MJPG SBS全幅采集、SBS左右拆分、左目进识别链路、右目仅统计），按`camera_source`与RTSP链路二选一装配；
- PX4 MAVLink遥测和底层setpoint编码能力，但正式应用没有连接控制输入；
- 地面站MAVLink链路、TIMESYNC、目标UPDATE/ACK、健康和任务状态回传；
- HealthManager真实健康监控；
- MissionStateMachine安全影子状态；
- 地面站单目标位置的局部NED线性卡尔曼影子估计（可选融合双目视觉NED观测，`enable_visual_position_fusion`）；
- 单目标视觉稳定性判定的帧级影子状态（基于YOLO帧级观测）；
- 视觉跟踪控制律影子运行（`VisualTrackingShadow` 发布 `kControlIntent`，无消费者）；
- 双目测距 v2 影子链路（`StereoRanger` 稀疏 Census 测距：预置矩阵校正 + 近端簇聚合，量程约 0.4~7.9m，输出接通影子控制律距离通道；前期参考工程实测精度可接受，卷尺级验收留作阶段四前置）。

当前明确没有：

- 正式飞行控制输出；
- 光流正式实现；
- 感知融合正式实现；
- 多目标追踪正式接入；
- 独立雷达或独立电源管理。

安全配置必须保持：

```json
"enable_control": false
```

**PX4 已到位**（2026-10-10：装机体 + GPS，可出 Home），依赖 PX4 Home/姿态/位置的模块（目标 NED 实链、状态机导航、控制律整定）已具备实链验证条件；视频链路与地面站物理链路此前已完成验证。注意：**实链验证 ≠ 允许控制输出**——`enable_control` 仍为 false，正式控制按阶段 4 接入路径推进。

## 3. 状态标记

本文统一使用以下状态：

| 状态 | 含义 |
|---|---|
| 正式 | 已进入`DroneApplication`实际装配，处理真实数据 |
| 影子 | 运行真实算法并发布状态，但输出不产生飞行控制 |
| Stub | 只有接口或占位生命周期，没有正式业务算法 |
| 独立 | 单独子工程或工具，未进入正式`DroneApplication` |

## 4. 程序入口和装配顺序

正式入口是：

```text
main.cpp
  → 查找并解析config/config.json
  → 初始化异步文件日志
  → 创建DroneApplication
  → BuildComponents()创建组件
  → BindTopics()连接Topic
  → Start()按依赖顺序启动线程
  → 等待SIGINT/SIGTERM
  → Stop()按数据流逆序停止
```

关键文件：

| 作用 | 文件 |
|---|---|
| 进程入口、信号和配置路径 | `main.cpp` |
| 组件所有权、Topic接线、启动停止 | `src/application/drone_application.cpp` |
| 强类型配置 | `include/config/config.h`、`src/config/config.cpp` |
| 公共消息和Topic名称 | `include/common/types.h` |
| 发布订阅实现 | `include/common/topic.h` |

禁止把业务算法写进`main.cpp`或`DroneApplication`。`DroneApplication`只负责创建、接线和生命周期。

## 5.1 单目标视觉观测链路

YOLO有两类输出，职责不同：

```text
DetectionResult          每目标一条，供叠加器画框；空帧不发布
VisualTargetObservation  每个成功推理帧恰好一条，允许detected=false
```

两者的区别是这份工程里最重要的一个设计点：

```text
YOLO输入队列容量为1，会主动丢弃解码帧
→ 解码25FPS、推理约24FPS，两者并不一一对应
→ 因此不能拿“解码帧序号”当视觉节拍
→ 只能靠“每个成功推理帧一条观测”判断“本帧是否确实没有目标”
```

基于帧级观测，`VisualTargetMonitor` 维护：

- 连续检测帧数、连续丢失帧数；
- 平滑后的目标像素中心和置信度；
- 稳定性状态：`SEARCHING / ACQUIRING / LOCKED / LOST`；
- 观测超时（YOLO线程停止或卡死）与“本帧无目标”的区分。

当前该状态只发布到 `kVisualTargetStatus`，没有任何正式消费者，不参与状态机和控制。

## 6. 视频链路逐段说明

### 6.1 摄像头接收

```text
输入：camera_source=rtsp → camera.rtsp_url
组件：CameraReceiver
输出：EncodedFrame（H.264/H.265）
```

```text
输入：camera_source=uvc → video.uvc_device（如 /dev/video0）
组件：UvcCameraReceiver
输出：EncodedFrame（kMjpeg，一帧一个访问单元、皆关键帧、无参数集）
```

两种视频输入实现同一`ICameraReceiver`接口，按`video.camera_source`二选一装配：

- `CameraReceiver`使用FFmpeg拉取RTSP，按访问单元发布H.264/H.265码流，并单独传递流级参数集。它不解码、不做YOLO、不推流。
- `UvcCameraReceiver`经V4L2 mmap从UVC设备读取MJPG SBS帧（如2560×720@30），逐帧发布；open失败/流错误自动重连（默认3秒），健康计数与RTSP接收共用`kCamera`健康源。它不解码、不拆分双目。

### 6.2 视频解码

```text
输入：EncodedFrame（H.264/H.265/MJPEG）
组件：VideoDecoder
输出：FrameHandle（当前为NV12）
```

香橙派优先使用rkmpp硬解（含mjpeg_rkmpp，存在与否取决于ffmpeg-rockchip版本，找不到走软解属预期）。硬解设备上下文两级探测：先运行时探测ffmpeg-rockchip 8.1的`rkmpp`设备类型，探测不到回退`DRM`类型（兼容旧fork/FFmpeg 6.1）。

硬解输出DRM PRIME帧：hevc/h264为NV12，**mjpeg_rkmpp为NV16**（YCbCr422SP）。线性单对象布局满足严格校验时，用RGA DMA-BUF直传到`VideoFramePool`——NV12走`imcopy`纯拷贝，NV16走`imcvtcolor`在解码器内转NV12入池，下游（拆分器/YOLO/叠加/编码）零改动；不满足或失败时自动回退FFmpeg转存（NV16转存帧由sws转NV12）。

MJPG语义：每帧独立（皆关键帧、无参数集、帧间无依赖），单帧解码失败计`DroppedFrameCount`继续，无H.26x的参数集同步问题。UVC链路解码输出为全幅SBS（如2560×720）。

编码侧同样rkmpp优先：h264可用`h264_rkmpp`硬编（带私有选项`rc_mode=VBR`、`rc_max_rate`=配置码率），不存在或打开失败自动回退libx264软编。

### 6.2.1 双目SBS拆分（仅camera_source=uvc且stereo_split=true）

```text
输入：全幅SBS解码帧（2560×720 NV12）
组件：StereoFrameSplitter
输出：左目FrameHandle（1280×720）→ kDecodedFrameLeft → YOLO/叠加；
     右目FrameHandle → kDecodedFrameRight → StereoRanger 辅助图（仅 enable_stereo_ranging=true；
     否则无消费者，仅计数）
```

RGA `imcrop`优先（`DRONE_HAVE_RGA_DMA`），失败/无RGA回退逐行memcpy；左右各一个自有帧池，独立容错。拆分器不注册健康源；**左右目物理对应已实证（2026-09-22）：SBS左半幅=物理右目**，拆分器x_offset已按此交换——左目Topic取右半幅=物理左目，语义与物理方位一致（见`include/video/stereo_frame_splitter.md`）。测距由下游 StereoRanger 影子支路承担（§9.3；v2 稀疏 Census，仅在基准图跑检测，无右目推理）。

### 6.3 YOLO

```text
输入：FrameHandle
组件：YoloDetector + RknnDetectionBackend
输出：DetectionResult
```

YOLO输入队列当前容量为1，队列满时丢旧留新。一帧检测出N个框就发布N条`DetectionResult`；一帧没有目标时当前不发布检测消息。模型输出后处理最多保留128个框。

### 6.4 叠加

`FrameCompositor`同时订阅解码帧和检测结果，根据`frame_sequence`将检测框画到对应或允许滞后范围内的帧上，再发布标注帧。它不执行推理。

### 6.5 编码和图传

`VideoSender`消费标注帧，内部调用编码后端，香橙派优先使用`h264_rkmpp`，输出到本地MediaMTX RTSP地址，再由HM30网络链路送到地面站。

### 6.6 视频所有权

视频像素通过`VideoFramePool`和`FrameHandle`管理：

- 不使用裸指针管理帧生命周期；
- 最后一个句柄释放后缓冲自动归还内存池；
- 内存池耗尽时丢帧，不阻塞采集线程；
- 视频延迟探针会独占摄像头、NPU和本地RTSP路径，不能与正式程序同时运行。

## 7. PX4链路

`Px4Link`负责：

- 串口或UDP传输；
- MAVLink 1/2解析；
- 目标PX4身份过滤；
- 心跳、GPS、全局/局部位置、姿态、电池、Home等快照；
- 命令ACK关联；
- `Px4Setpoint`编码为`SET_POSITION_TARGET_LOCAL_NED`的底层能力。

当前正式应用只绑定：

```text
Px4Link::StateOutput()
```

没有调用：

```cpp
px4_link_->SetInput(...);
```

因此即使`Px4Link`包含setpoint能力，正式程序也没有数据进入该出口。

PX4 **未连接**时（串口松动等仍可能出现）：

- `/dev/ttyS1`连接失败或串口读错误后按 `reconnect_interval` 自动重连属于预期降级；
  重连期间发布 `connected=false` 快照，控制器授权链撤权停发，进程不退出；
- `FlightStateSnapshot.home_valid`不会成立；
- MissionStateMachine停留在自检；
- TargetEstimator等待 EKF 锚点（`GPS_GLOBAL_ORIGIN` #49 流），不发布有效NED状态；
- 禁止在正式程序中自动伪造PX4状态。

PX4 **已连接**时（2026-10-10 起现场具备：装机体 + GPS）：

- 心跳/遥测建立，`home_valid` 可成立，状态机可越过自检，TargetEstimator 出有效 NED 影子状态；
- 若仍停留自检/等待锚点：先看「PX4 心跳已连接」是否出现——**室内拿不到 GPS fix/Home/锚点
  时停留自检属预期，不是通信问题**；有心跳后按 心跳 → GPS fix → Home 顺序排查
  （见`docs/故障排查手册.md` 与`docs/PX4实链验证清单.md`）；
- 控制出口仍不绑定 setpoint。

## 8. 地面站链路

`GroundStationLink`通过`/dev/ttyS6`和地面站通信。

下行：

- 标准心跳、GPS、全局/局部位置、姿态、电池、Home等；
- 65012健康状态；
- 65013任务状态。

上行：

- 固定来源身份`255/190`的GCS心跳；
- 标准TIMESYNC；
- 65010 `TRACK_TARGET_UPDATE`；
- 65011 `TRACK_TARGET_ACK`。

合法目标发布为`GroundStationTarget`。通信层只负责协议、身份、序号和时效校验，不负责目标滤波或飞行控制。

## 9. 影子链路

### 9.1 MissionStateMachine

当前状态机输入（阶段四 Task 7/8/9）：

```text
PX4导航状态 + 地面站目标 + 健康状态
  +（可选）TargetEstimator.TargetState / VisualTargetMonitor.Status / StereoRanger.Distance
  +（可选）估计器诊断（最近一次视觉创新，交接门限用）
```

可以发布任务状态并影子进入`GPS_APPROACH`（S5）：绑定估计输入后发布`kPositionGuide`
位置引导意图（影子意图，是否到 PX4 由`enable_control`门禁决定）；再注入估计器诊断后，
交接判据（`handover` 配置节）驱动 S5→S6→S7 与回退（LOCKED 连续帧/测距/视场余量/
创新门限进入，S6 超时或判据失效撤销，S7 四条独立退出路径：视觉断流超龄、
测距失效达 `distance_lost_ms`、LOST 连续帧迟滞、伺服未启动超时）。

Task 9 起意图全链补齐：S6 驻留期续发进入时刻冻结的最后位置目标（`valid_until`
逐拍滚动，防交接点意图超龄刹车；S7 首拍伺服未接续前同样续发，以
`handover.timeout_ms` 封顶——超时未见首条有效视觉意图即收口回 S5，防姿态持续
降级时无限续期）；S7 由状态机内视觉伺服协作者（复用
`TrackingControlLaw`）发布`control_source=1`速度航向意图（NED，带 bit31），
短期视觉 LOST 按判丢语义映射零速刹车意图（主链路无预测坐标，coast 以刹车
形态落地），控制律降级保持时不发布意图（控制器意图超时刹停收口）；S7 期间
每秒核对卡尔曼热备份年龄，断粮节流 WARN + MissionStatus 告警位 bit2（不退出 S7）；
S7 本拍未发出视觉伺服意图（伺服未启动或控制律降级停发）时置告警位 bit3，标注
"报告状态与实际控制输出背离"；捕网执行器故障时置 bit4 并进入 S16（见下段）。
告警位地面站可观测（65013 全量下发；Web UI 渲染待补）。
`VisualTrackingShadow`保留并存（输出为独立 Topic、无消费者），控制律正规调用点
在状态机。**仍不执行 ARM、起飞**；整机接线（`SetEstimationInputs`）按 T12 裁决
维持不接线（G3 验收走独立装配工具 `--sitl-stage4-mission`），与 `enable_control`
打开一并做。

P3（2026-10-19）：S5 位置意图可携带逐轴速度前馈（`TargetState.velocity_valid_mask`
→`ControlIntent.feedforward_*`→`Px4Setpoint.feedforward_*`），`Px4Link` 以位置+速度
同时有效的 type mask 下发，PX4 位置环把速度作为前馈叠加。控制器开关
`controller.enable_position_velocity_feedforward` 默认 **false**，关闭时输出与旧版
逐位等价；S6 冻结段与 S7 速度意图不带前馈；前馈不做 slew、不参与位置围栏
（PX4 geofence 兜底）。SITL 匀速运动目标 A/B 已完成（2026-10-19）：
FF 关闭 p95 滞后 1.49m → 开启 0.40m（降低 73%），脚本与证据见
`tools/px4_link_smoke.md` §2.3.1 / `tools/feedforward_evidence/`。

Task 10 起捕网执行器接通，2026-10-21 抽象为 `INetActuator`（`Trigger/Reset/Update/
Type`）。Task 5 集成时序：状态机每拍调用 `Update(ActuatorFeedback)` 推进执行器内部
ACK/保持/复位/稳定时序；S10 INTERCEPT_EXECUTING 内 `Trigger()` 只调一次（`Fired()`
防重复，入队失败下拍重试，超过 `fire_timeout` 判故障）；**无飞行快照不触发**，
快照存在但 `connected=false` 判故障。**S10→S11 以 `Fired()`（命令已入队）为准，
不等发射 ACK**；复位不再由离开拦截序列触发——触发 ACK 后执行器按 `reset_delay`
保持再发复位，复位 ACK 后按 `reset_settle` 稳定回 Ready；未触发即离开不发命令。
执行器 187 ACK 超时/非 ACCEPTED/PX4 断连/触发入队超时 → S16 FAILSAFE：告警位
bit4、`CancelPendingCommands()` 恰好一次、停发一切控制意图（不重试/不补发复位）。
当前
`single_pwm` 实现经命令窄接口发 `MAV_CMD_DO_SET_ACTUATOR`，机载只发归一化量
（默认 -0.7/0.0），输出功能/对应 PWM 映射区间（当前 MAIN5 为
`PWM_MAIN_MIN5/MAX5`）/舵机行程由 PX4/QGC 配置（当前装机 MAIN5 =
`Peripheral via Actuator Set 1`，机载 `net_channel=1`）；
后续多发实现按 `actuator.type` 工厂切换。未注入命令接口（`enable_control=false`）
时零调用。**拦截序列入口判据（授权/射程）已配置化**（`interception` 节，默认
`enabled=false`；射程占位待实机冻结）——触发路径由配置显式开启后可达，未开启时
`DroneApplication`不驱动 S9/S10。

2026-10-19 起 S11~S14 单发返航闭环（V1）：S10 触发命令入队（`Fired()`，不等 ACK）→
S11 只记录（不判命中；发射超时/ACK 故障/断连走 S16，不返航）→ S12 算力板位置设定值飞回 Home（Home 局部 NED 由 Home 经纬度+EKF
锚点换算；<5m 先爬升到 5m，≥5m 保持当前高度；到达判据 2m/0.5m/0.5mps 持续 1s；
Home/锚点无效原地悬停）→ S13 AUTO.LAND（4/6）→ S14 DISARM。正常返航不使用
PX4 自动 RTL；PX4 离开 Offboard 时状态机停发让权。S9/S10 入口已由
`interception` 配置节实现（默认关闭，射程占位待实机）；多发成功判据 V2。实现文档
`include/state_machine/mission_state_machine.md`、设计口径 `docs/状态机设计.md` §6。

### 9.2 TargetEstimator

第一阶段数据流：

```text
EKF 锚点（#49 ref_*）+ GroundStationTarget
  → WGS-84到局部NED（锚点为原点 = PX4 设定值执行帧，方案 C 2026-10-16）
  → [N,E,D,VN,VE,VD]恒速度线性卡尔曼
  → TargetState
```

当前输出没有接入状态机或控制器。高度不是有效MSL时，Z/VZ使用NaN，不伪造为0。目标过期、目标ID变化或**锚点变化**会按规则失效或重置（Home 变化仅记录、不重置）。

### 9.3 StereoRanger 双目测距 v2（稀疏 Census，影子；实机精度验证在独立测试工程）

```text
kDetection（基准图检测框，原始左图坐标）
  + kDecodedFrameLeft（基准=SBS右半=物理左目）+ kDecodedFrameRight（辅助=SBS左半）
  → 检测按 frame_sequence 成批（新序号或 settle 超时闭合）；左右帧 ±pair_window 配对
  → 预置矩阵校正（以 cam2/SBS 右半为基准）→ 行带 remap
  → Shi-Tomasi 关键点 + Census 7×7 稀疏匹配（粗/精/亚像素/唯一性/左右一致）
  → bbox 近端簇聚合 Z = fxB/d（fxB=63.57 m·px，量程≈0.4~7.9m）+ EMA
  → StereoTargetDistance
```

输出只接 `VisualTrackingShadow` 距离通道（可选输入）：valid 且未超龄的距离透传给控制律距离 PID 做影子观察，无效/未接线回落 `no_distance_action=kSlowApproach` 定速接近。不产生真实控制输出，不注册健康源；只在基准图跑检测（无右目检测实例）。校正矩阵由 `tools/camera_calibration/export_rectify.py` 预置（C++ 不依赖 OpenCV）。实现细节见 `include/perception/stereo_ranger.md`。

## 10. 控制数据流与装配门禁（阶段四）

设计上的控制链是：

```text
MissionStateMachine/策略
  → ControlIntent
  → FlightController
  → Px4Setpoint
  → Px4Link
  → PX4
```

当前实际情况（2026-10-13，阶段四 Task 6 装配门禁落地）：

```text
MissionStateMachine.IntentOutput() → FlightController.SetInput()   （唯一意图来源，纪律见下）
FlightController：正式实现已装配，影子/正式由 enable_control 门禁决定
  enable_control=false（仓库生产基线）：影子运行——不注入 PX4 快照源
    （SetPx4LinkSource），授权链恒不通过、保持 IDLE 停发；Px4Setpoint 无消费者
  enable_control=true（仅现场本地副本，永不入库）：SetPx4LinkSource 注入 +
    Px4Link::SetInput(FlightController::SetpointOutput()) 绑定 + WARN
    「正式控制输出已启用」；同分支注入状态机命令窄接口
    （Task 10 捕网执行器经 INetActuator/single_pwm 下发 DO_SET_ACTUATOR）
runtime.enable_control：false
```

### 自动起飞数据流（2026-10-22，Task 5/6）

```text
65014 任务分配 → MissionStateMachine S2 预检 → S3(kArming)
  → 每决策拍发布 kTakeoff 意图（起飞原点 x0/y0/z0，reason_code bit31）
  → FlightController：门禁全通进入 kBootstrap，每拍发布原点保持 kPosition 流
  → Px4Link → PX4（Offboard 前置 setpoint 流先于模式/解锁建立）
  → 状态机等待 bootstrap_lead → 发 176(Offboard) → 400(arm)
  → PX4 快照 armed && Offboard(6/0) → FlightController 转 kActive
  → S4 每决策拍抬升 z 目标（climb_rate_mps）直至任务高度
```

- `kBootstrap` 门禁**不读取 RC 字段**（`rc_state_valid`/`rc_connected`/
  `manual_override_active`），RC 由 PX4 自己管理；
- bootstrap 条件失效/意图撤销/超时只回 IDLE 停流（`valid=false`），
  不进入 COAST；
- 控制器 `bootstrap_timeout` 是状态机 S3 模式/解锁超时之外的防卡死兜底；
  实现细节见 `include/control/flight_controller.md`「自动起飞预授权」。

意图输入纪律：FlightController 只接 `MissionStateMachine::IntentOutput()`；`VisualTrackingShadow` 的影子意图不带授权请求位（`reason_code` bit31，`common::kControlIntentReasonRequestControl`），若接入控制器会每拍清锁存压死授权门禁，永不接线。装配状态可用 `DroneApplication::ControlAssembly()` 快照断言（`drone_application_test` 覆盖两种模式）。

任何修改只要让`Px4Setpoint`进入`Px4Link`，都属于安全边界变化，必须先完成代码评审、SITL、拆桨台架和明确授权。

## 11. 当前实际线程

项目早期文档中的“7个线程”是逻辑规划。当前实现按组件拆分，全部启用时可能存在以下工作线程：

| 线程 | 所属组件 | 主要工作 |
|---|---|---|
| 摄像头线程 | CameraReceiver或UvcCameraReceiver（按`camera_source`二选一） | RTSP读取或V4L2 UVC采集与码流发布 |
| 解码线程 | VideoDecoder | 解码和帧池输出 |
| 双目拆分线程 | StereoFrameSplitter（仅stereo_split=true） | SBS左右目裁剪和各自帧池输出 |
| YOLO线程 | YoloDetector | 预处理、RKNN推理、检测发布和帧级观测发布 |
| 双目测距线程 | StereoRanger（仅enable_stereo_ranging=true） | 帧/检测批次配对、稀疏 Census 测距、影子距离发布 |
| 视觉跟踪影子节拍线程 | VisualTrackingShadow（影子） | 20Hz固定节拍（control.frequency_hz）跑跟踪控制律，影子发布kControlIntent |
| 视觉稳定性判定线程 | VisualTargetMonitor | 连续检测/丢失计数与锁定状态影子发布 |
| 叠加线程 | FrameCompositor | 帧与检测聚合、画框 |
| 图传线程 | VideoSender | 编码和RTSP写出 |
| PX4线程 | Px4Link | MAVLink收发、状态和ACK |
| 地面站线程 | GroundStationLink | MAVLink收发、TIMESYNC和遥测 |
| 目标估计线程 | TargetEstimator | 单目标线性卡尔曼和周期影子输出 |
| 状态机线程 | MissionStateMachine | 周期影子决策和任务状态发布 |
| 飞行控制线程 | FlightController（阶段四正式实现，影子/正式由enable_control门禁） | 固定周期（controller.period_ms）消费意图、门禁链+限幅流水线、Px4Setpoint发布 |
| 健康监控线程 | HealthManager | 新鲜度和CPU负载汇总 |
| 健康采样桥接线程 | DroneApplication | 把模块计数变化转换为健康上报 |
| 主线程 | main.cpp | 信号等待和进程生命周期 |

辅助纯算法对象如`MavlinkHandler`、`LinearTargetKalmanFilter`、`GeodeticToLocalNed`、`VideoFramePool`本身不创建线程。
