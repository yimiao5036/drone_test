# 通信与数据定义

## 1. 目标

本文定义模块之间必须保持稳定的数据语义。具体 MAVLink 消息编号、TCP 码流封装和串口参数尚未确认，进入实现前必须结合 PX4 1.17.0、地面站设计和摄像头协议文档补齐。

> 代码级接口契约（消息类型、部件接口签名、Topic 一览）见 [数据接口文档](数据接口文档.md)；
> 本文聚焦物理链路与字段语义，两文互补，修改任一涉及接口的内容需同步更新另一篇。

## 2. 物理链路

| 链路 | 介质 | 协议 | 方向 |
|------|------|------|------|
| 算力板—PX4 | 串口 | MAVLink | 双向 |
| 算力板—地面站 | 电台 | MAVLink | 双向 |
| 双目摄像头—算力板 | 待新硬件确认 | 双路视频/拼接流/厂商深度协议待定 | 摄像头到算力板为主 |
| 算力板—图传 | RJ45 | 待定 | 算力板到地面站方向 |

每条链路独立维护连接、解析状态、序号、最后有效数据时间和错误计数。

## 3. 通用消息头

所有内部控制相关消息至少包含：

| 字段 | 含义 |
|------|------|
| sequence | 来源内单调递增序号 |
| source_time | 设备或地面站产生数据的时间 |
| receive_time | 算力板收到数据的单调时钟时间 |
| valid_for | 数据允许使用的最长时间 |
| source_id | 数据来源标识 |
| health | 来源健康和数据质量 |
| frame_id | 坐标系标识，适用于空间数据 |

超时判断使用 `receive_time` 对应的单调时钟；跨设备融合同时参考 `source_time`。设备没有可靠源时间时必须显式标记，不能伪造同步时间。

## 4. 地面站目标状态

目标消息必须能表达：

| 字段 | 单位/语义 |
|------|-----------|
| target_id | 目标唯一编号 |
| latitude | WGS-84 纬度，建议使用定点整数传输 |
| longitude | WGS-84 经度，建议使用定点整数传输 |
| altitude | 高度，必须带高度基准 |
| velocity_north/east/down | 目标速度，m/s；无效时带有效标志 |
| heading | 航向角，定义范围和真北/磁北基准 |
| horizontal_accuracy | 水平定位精度，m |
| vertical_accuracy | 垂直定位精度，m |
| source_time | 目标状态产生时间 |
| sequence | 目标更新序号 |
| valid_for | 本条状态有效期 |
| validity_flags | 各可选字段是否有效 |

目标位置消息用于动态目标引导，不能按静态航点永久保存。乱序、重复、过期、精度不足或跳变异常的消息不得直接进入控制器。标准MAVLink TIMESYNC第一阶段已实现，目标位置字段、boot ID、更新序号、有效期扣减和ACK语义见`地面站目标位置与时间同步协议.md`；当前尚未发布目标。

## 5. PX4 飞行状态快照

算力板至少需要维护：

- PX4 心跳、版本和连接状态。
- armed、landed、飞行模式和控制模式。
- GPS/全局位置、局部位置、速度和位置有效性。
- 姿态、角速度和航向。
- 气压高度及其参考信息。
- Home 点经纬度、高度和有效性。
- 动力电池电压、电流、剩余量和告警状态。
- 遥控器链路和人工接管状态。
- MAVLink 命令 ACK 及其对应命令。

状态机使用不可变快照，避免一次决策读取到不同时间的零散字段。ACK 不能代替 PX4 实际状态确认。

PX4 标准消息、Offboard 设定值消息和具体模式切换过程必须按 1.17.0 版本验证。不得直接套用其他版本的参数或默认行为。

当前已实现 HEARTBEAT、`AUTOPILOT_VERSION`、`EXTENDED_SYS_STATE`、
`GLOBAL_POSITION_INT`、`LOCAL_POSITION_NED`、`ATTITUDE`、`GPS_RAW_INT`、
`SYS_STATUS/BATTERY_STATUS`、`HOME_POSITION` 和 `RC_CHANNELS`。按配置过滤目标
system/component ID，分别维护连接与各类遥测新鲜度；超时后只清除有效标志，不把旧值继续用于
控制。HEARTBEAT 不包含可靠设备源时间，因此快照 `source_time_ms=0`。当前已实现有界命令队列、
`COMMAND_LONG/COMMAND_ACK` 单条在途关联和超时统计，并在首次连接后安全请求版本/Home 与各类
遥测频率。飞行设定值已实现本地 NED 位置/速度和可选 yaw/yaw rate：只发送最新、合法且未
过期的值，过期或 `valid=false` 时停止发送；姿态、机体系和全局设定值仍待后续评审。

## 6. 视觉消息

### 6.1 图像帧

| 字段 | 含义 |
|------|------|
| frame_sequence | 采集/解码帧序号 |
| capture_time | 摄像头时间；不可用时明确标记 |
| receive_time | 码流到达算力板的时间 |
| decode_time | 解码完成时间 |
| width/height | V1 为 1080p，仍由消息携带 |
| pixel_format | 解码后像素格式 |
| buffer_handle | 内存池句柄，不传递裸指针所有权 |

### 6.2 检测结果

| 字段 | 含义 |
|------|------|
| frame_sequence | 对应图像帧 |
| class_id | 无人机、障碍物或未来类别 |
| confidence | 检测置信度 |
| bounding_box | 像素坐标框 |
| center_pixel | 目标中心像素 |
| track_id | 跟踪器目标编号；V1 可选 |
| inference_time | 推理耗时和完成时间 |

### 6.3 光流结果

光流必须关联相邻帧序号和时间间隔，输出使用的算法、有效区域、质量指标及运动向量。低纹理、强压缩、运动模糊或光照异常时应降低质量状态。

## 7. 双目深度消息

当前取消独立激光雷达，距离计划由双目摄像头深度模块输出。消息至少包含：

- 对应左右图或基准帧序号；
- 目标区域/前向区域距离和单位；
- 设备源时间与算力板接收时间；
- 测量有效标志；
- 有效像素比例、视差/深度置信度或错误码；
- 标定版本、量程和连续异常计数。

双目距离必须与校正后的图像区域、检测目标和时间戳关联。低纹理、反光、远距离、左右图不同步或遮挡时必须标记无效。已有`LaserRangeSample`只作为兼容预留，待双目接口确认后再决定替换或复用。

## 8. 控制意图

状态机和策略模块产生控制意图，由飞行控制器转换成 PX4 设定值。控制意图至少分为：

- 位置引导意图。
- 速度与航向意图。
- 刹停/悬停意图。
- 起飞、降落和返航意图。
- 禁止自动输出/人工接管意图。

每条意图包含生成状态、优先级、有效期、坐标系、限制条件和产生原因。PX4 通信线程发送前再次检查控制权和有效期。

## 9. 任务和拦截状态回传

地面站至少能获得：

- 当前任务状态和进入时间。
- 当前控制来源：位置、视觉、安全、遥控器或 PX4 保护。
- 目标状态及数据年龄。
- 双目摄像头、YOLO、光流、深度和PX4健康状态。
- 障碍物告警和前向距离。
- 拦截授权请求、设备状态和执行结果。
- 正常返航、后备 RTL、悬停等待和人工接管原因。
- PX4动力电池电压、电流、剩余量和新鲜度；不回传独立算力板电池状态。

## 10. 队列策略

| 数据 | 建议队列策略 | 原因 |
|------|--------------|------|
| 原始/解码图像 | 有界，丢弃最旧帧 | 新鲜度优先 |
| 标注图像 | 有界，丢弃最旧帧 | 图传不得反压感知 |
| 检测/光流 | 最新快照加必要事件 | 控制使用最新数据 |
| PX4 遥测 | 分类最新快照 | 避免积压旧姿态 |
| 地面站目标 | 按 target_id 保留最新有效状态 | 移动目标只使用最新状态 |
| 控制命令 | 小容量、优先级、严格有效期 | 禁止发送旧命令 |
| 状态转移/故障 | 可靠事件队列 | 需要审计和上报 |

## 11. TCP 视频连接

当前单目使用RJ45 RTSP H.265；准备更换的双目摄像头尚需厂商资料确认：

- 物理接口、客户端/服务端角色和是否兼容RTSP；
- 左右图是双路码流、拼接帧还是直接提供深度；
- 编码格式、NAL/帧边界和左右图同步方式；
- 是否有自定义包头、长度、校验、心跳和鉴权。
- SPS/PPS/VPS 发送时机和断线重连后的关键帧恢复。
- 网络断开、半包、粘包和超大包处理。
- 摄像头控制命令和视频流是否共用连接。

实现前必须取得协议说明或录制真实网络流量验证，不能把“TCP”误认为天然具有视频帧边界。

## 12. 待定协议事项

- 地面站当前下行遥测使用MAVLink `common`标准消息；标准`TIMESYNC`第一阶段已实现。目标位置`TRACK_TARGET_UPDATE/ACK`因`42000/42001`与ICAROUS冲突，当前通过标准`V2_EXTENSION.message_type=65010/65011`实现接收、ACK和`GroundStationTarget` Topic发布；Python命令行工具及Web页面均已完成HM30实链验证，UPDATE短帧固定为`mavlink_payload_len=60`；任务状态、健康状态和功能命令协议仍按后续阶段冻结。
- PX4链路身份已冻结为本机独立网络：Orange Pi使用`1/191`，PX4使用`1/1`，不因多机扩展修改PX4默认ID。
- 地面站链路已按`多机身份与功能寻址设计.md`拆分独立身份：地面站来源固定`255/190`，捕网类N号=`N/25`，火箭类N号=`N/26`；`27～99`全部预留且未定义。system/component二元组共同构成飞机地址，地面站及中间层不得只保留system ID。
- 图传RTSP路径也绑定同一二元身份，正式路径为`/drone_<component_id>_<system_id>`，例如捕网-01=`/drone_25_1`、火箭-01=`/drone_26_1`；旧`/drone_out`仅作为单机调试或兼容路径。
- MAVLink 版本、签名、序号和链路认证策略。
- PX4 串口设备已确认为 `/dev/ttyS1`；JSON 当前配置 115200、8N1、读写超时和重连间隔。
  波特率如需调整只修改配置，不修改串口实现。
- 图传承载协议当前为RTSP/MediaMTX中转；后续若替换图传设备，仍需保留二元身份路径或提供等价的二元身份绑定机制。
- 时间同步已确定使用双方单调时钟和标准TIMESYNC；当前配置门限仍需HM30实链采样后冻结。
- 高度参考、局部坐标系和航向基准。
