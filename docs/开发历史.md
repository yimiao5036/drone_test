### HealthManager 功能说明（2026-09-07 文档补充）

`HealthManager`是系统级健康状态汇总器，当前负责把双目摄像头（切换前仍为单路适配器）、PX4、地面站、解码器、NPU/YOLO和图传等模块的连接状态、数据新鲜度、错误状态和算力负载统一汇总为`common::HealthStatus`，通过`Topic<HealthStatus>`提供给任务状态机和地面站。

它的核心流程是：

```text
各模块上报最近一次有效数据到达时间/错误事实
        → HealthManager 按单调时钟检查是否超时
        → 汇总 link_health_bits、device_health_bits、data_freshness_bits、error_bits
        → 发布 HealthStatus
        → 状态机进行安全门禁和降级判断，地面站进行诊断展示
```

HealthManager **不负责**打开硬件、重连串口、切换 PX4 模式、ARM/DISARM、返航、降落或发送 setpoint；它只提供健康事实，任务严重度和控制决策由状态机/控制器负责。当前已经完成 `HealthManager` 独立实现：支持标准数据源注册、新鲜度监控、链路/设备健康位、超时恢复和健康快照发布；`HealthManagerStub` 仍保留给骨架测试。真实 HealthManager 已接入 `DroneApplication`，HealthStatus 已连接状态机并通过65012下行，MissionStatus通过65013下行，应用级监控线程已覆盖视频、PX4、地面站、解码器、YOLO和图传的数据/错误计数变化；CPU负载和现有模块活动`error_bits`已接入；独立激光雷达和电源管理已取消，兼容位不注册。

详细接口、位定义、日志和测试要求见 `include/health/health_manager.md`；本次新增 `tests/health/health_manager_test.cpp`。

## 三、关键技术决策

- 视频帧用 `Topic` 发布**内存池 RAII 句柄**而非像素数据，多订阅者零拷贝共享；底层缓冲最后引用释放时归还内存池。
- 解码输出通过 RGA 将完整 NV12 原图缩放/转换为 RGB letterbox，并写入 RKNN 预分配输入内存，避免 CPU 色彩转换。
- 原型为单线程串行（解码→推理→编码），正式工程必须拆独立线程 + Topic 解耦才能逼近 25fps。
