# 新增设备接入指南

> 用途：增加或替换摄像头、串口设备、传感器、通信链路和算法后端时，按统一步骤接入正式工程。  
> 核心原则：先冻结硬件事实和数据契约，再写驱动；先影子输出，再进入决策；最后才可能连接控制。  
> 最后更新：2026-09-11。

## 1. 接入前必须确认的信息

不得根据宣传页、旧型号或相似设备猜测接口。至少确认：

### 通用信息

- 品牌和完整型号；
- 硬件版本、固件版本；
- 物理接口和电平；
- 供电、电流、接地和连接器；
- Linux ARM64/RK3588驱动或SDK；
- 协议文档和示例；
- 数据频率、时间戳来源和同步方式；
- 数据单位、坐标系、有效值和错误码；
- 精度、量程、延迟和失效表现；
- SDK/库许可证和产品分发限制。

### 双目摄像头还必须确认

- 双路独立流、左右拼接流还是厂商深度流；
- USB、网口、MIPI或其他接口；
- MJPEG/H.264/H.265/RAW等编码；
- 分辨率和帧率；
- 左右硬件同步或软件同步方式；
- 帧时间戳；
- 左右相机内参、畸变和外参；
- 基线；
- 深度输出格式、无效值和质量指标；
- 是否支持DMA-BUF/RGA/MPP；
- ARM64 SDK及可重新分发文件；
- 有效距离和精度实测方式。

资料未齐时，只能写接口草案和Mock测试，不能宣称完成硬件实现。

## 2. 判断设备属于哪一层

| 类型 | 放置位置 | 示例 |
|---|---|---|
| 物理传输 | `communication/`或设备模块内部适配器 | 串口、UDP、USB |
| 原始采集 | `video/`或新设备目录 | 摄像头码流、原始传感器包 |
| 协议解析 | `communication/`或设备模块 | MAVLink、厂商二进制协议 |
| 纯算法 | `perception/`、`control/` | 深度、滤波、检测后处理 |
| 任务决策 | `state_machine/` | 状态转移、降级 |
| PX4输出 | 只能经`FlightController→Px4Link` | setpoint、命令 |

禁止把串口读写、算法、状态机决策和PX4输出全部写进一个类。

## 3. 标准接入流程

```text
硬件事实确认
→ 定义公共消息
→ 定义抽象接口
→ 实现设备适配器
→ 增加强类型配置
→ 接入DroneApplication
→ 注册健康源
→ 增加日志和计数
→ Mock/纯算法/集成测试
→ 编写实现文档
→ WSL2 Ubuntu 24.04验证
→ 香橙派影子验证
→ 决策门禁验证
→ 控制接入（如需要，最后进行）
```

每一步都要能单独编译和测试。

## 4. 第一步：定义公共消息

跨模块消息统一放在：

```text
include/common/types.h
```

消息至少考虑：

```cpp
struct ExampleSample {
    MessageHeader header;
    float value = std::numeric_limits<float>::quiet_NaN();
    bool valid = false;
    uint8_t quality = 0;
    uint32_t error_code = 0;
};
```

必须明确：

- 单位；
- 坐标系和`frame_id`；
- 时间戳属于设备时间还是本机单调时钟；
- `valid_for_ms`；
- 无效值表示方式；
- 质量或协方差；
- 序号和乱序规则；
- 大数据是否允许放进消息。

规则：

- 无效浮点优先使用NaN并配合显式有效位；
- 不用0同时表示“真实0”和“无效”；
- 图像大缓冲使用RAII句柄，不复制到普通消息结构；
- 公共类型只表达数据，不持有设备对象和线程。

同步更新：

- `docs/数据接口文档.md`；
- `docs/通信与数据定义.md`；
- 本指南涉及的模块实现文档。

## 5. 第二步：定义Topic名称

在`include/common/types.h`的`common::topics`中增加：

```cpp
inline constexpr char kExampleSample[] = "example_sample";
```

Topic名称只用于统一契约，不是全局Topic实例。通常由生产组件拥有：

```cpp
common::Topic<common::ExampleSample> output_;
```

消费者通过生产者接口获取并订阅：

```cpp
consumer.SetInput(producer.Output());
```

不要在不同模块中散落相同字符串或创建多个互不相连的同名Topic。

## 6. 第三步：定义抽象接口

新头文件使用`#pragma once`。

示例：

```cpp
class IExampleDevice {
public:
    virtual ~IExampleDevice() = default;

    virtual bool Start() = 0;
    virtual void Stop() = 0;
    virtual bool IsRunning() const = 0;

    virtual common::Topic<common::ExampleSample>& Output() = 0;

    virtual uint64_t SampleCount() const = 0;
    virtual uint64_t ErrorCount() const = 0;
};
```

接口只暴露业务需要的能力，不暴露厂商SDK裸句柄。

如果硬件还没到，可以提供Stub，但必须明确：

- Stub不是正式实现；
- Stub不能生成看似真实的控制数据；
- Stub只用于接口和生命周期冒烟。

## 7. 第四步：实现设备适配器

文件位置：

```text
include/<模块>/example_device.h
src/<模块>/example_device.cpp
```

推荐使用PIMPL隐藏第三方库和系统头：

```cpp
class ExampleDevice final : public IExampleDevice {
private:
    struct Impl;
    std::unique_ptr<Impl> impl_;
};
```

实现必须遵守：

- RAII管理文件描述符、SDK上下文和缓冲；
- 构造/配置错误抛异常；
- 运行期错误返回错误码或计数，不在热路径抛异常；
- 独立物理链路使用独立线程；
- 队列有界；
- Stop幂等；
- 先设置停止标志，再唤醒阻塞等待，最后join；
- 不在持锁状态执行设备阻塞I/O或耗时算法；
- 不用裸指针承担资源所有权。

## 8. 第五步：增加配置

配置必须同时修改：

```text
config/config.json
include/config/config.h
src/config/config.cpp
tests/config/config_test.cpp
include/config/配置管理.md
```

示例：

```cpp
struct ExampleDeviceConfig {
    std::string device;
    int baud_rate = 115200;
    std::chrono::milliseconds timeout{100};

    void Validate() const;
};
```

配置原则：

- 设备节点、地址、频率、超时和阈值不能散落硬编码；
- 非法危险配置在启动前拒绝；
- 不确定参数明确标为影子初值，并记录整定方式；
- 缺少关键配置不能静默使用危险默认值；
- 开关之间的依赖在`LoadAppConfig()`中校验。

## 9. 第六步：接入DroneApplication

只在以下位置接线：

### 创建组件

```text
DroneApplication::BuildComponents()
```

### 连接Topic

```text
DroneApplication::BindTopics()
```

### 启动和停止

```text
DroneApplication::Start()
DroneApplication::Stop()
```

顺序规则：

```text
消费者先Start
生产者后Start

生产者先Stop
消费者后Stop
```

例：

```cpp
example_consumer_->SetInput(example_device_->Output());
```

`DroneApplication`只接线，不把协议解析或算法写进去。

## 10. 第七步：健康监控

需要监控的数据源在：

```text
DroneApplication::RegisterHealthSources()
DroneApplication::HealthReportLoop()
```

设备至少提供：

- 成功数据计数；
- 错误计数；
- 连接状态（如果适用）。

只有计数或连接事实变化时调用：

```cpp
HealthManager::ReportData(...)
HealthManager::ReportError(...)
```

不要每帧重新注册健康源。需要增加健康位时必须先检查65012协议和Web解析是否有兼容空间，不能擅自改位定义。

## 11. 第八步：日志和可观测性

### INFO

- 模块创建、启动、停止、销毁；
- 连接状态变化；
- 模式或降级状态变化；
- 首次和低频关键统计。

### WARN

- 设备断开；
- 数据过期；
- 丢帧或队列满；
- 自动回退；
- 可恢复异常。

### ERROR

- 配置错误；
- 不可恢复初始化失败；
- 违反内部不变量。

高频异常必须：

```text
第1次和每100次打印
```

日志携带：

- 设备名；
- 错误原因；
- 累计计数；
- 时间或数据年龄；
- 队列容量；
- 必要的身份/帧序号。

不能只打印“失败”而没有上下文，也不能每帧打印成功日志。

## 12. 第九步：测试

### 纯算法测试

不依赖硬件，直接验证：

- 数学结果；
- 边界值；
- NaN/Inf；
- 时间和坐标符号；
- 收敛和重置。

### 协议测试

使用：

- Linux PTY模拟串口；
- UDP回环；
- 录制字节流；
- CRC错误、半包、粘包、乱序。

### 设备Mock测试

通过接口注入Mock，验证：

- Start/Stop/Restart；
- 输入未绑定；
- 队列满；
- 后端抛错或返回失败；
- 输出计数；
- 错误后继续处理。

### 硬件测试

按级别执行：

```text
开发机单测
→ 香橙派单设备
→ 香橙派影子链路
→ 多设备台架
→ SITL
→ 拆桨PX4台架
→ 受控实飞
```

禁止跳过中间阶段直接实飞。

CMake中增加测试目标并执行：

```bash
cmake -S . -B build
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
```

## 13. 第十步：实现文档

每个正式模块必须在头文件同级编写中文实现文档，内容至少包括：

- 功能职责和边界；
- 接口与数据流；
- 关键实现点；
- 线程和资源管理；
- 日志行为；
- 配置；
- 测试方式；
- 硬件验证；
- 常见故障；
- 修改关联点。

例如：

```text
include/video/video_decoder.md
include/communication/ground_station_link.md
include/perception/目标估计器.md
```

同时更新：

- `docs/项目总览与数据流.md`；
- `docs/模块索引.md`；
- `docs/故障排查手册.md`；
- `docs/开发进度.md`；
- README文档导航。

## 14. 替换现有设备时的额外要求

替换摄像头或串口设备时，不要直接删除旧路径。先确认：

- 新旧消息语义是否一致；
- 编码和像素格式是否变化；
- 时间戳和同步方式是否变化；
- DMA-BUF布局是否变化；
- 原配置能否兼容；
- 是否需要迁移或弃用字段；
- 回退路径是否仍有效；
- Web和通信协议是否受影响。

对外接口不变时优先替换实现或增加适配器；语义已经变化时应修改公共契约，不能在旧字段中偷偷塞入新含义。

## 15. 接入双目摄像头时的计划边界

当前双目资料未齐，暂不实现。资料到位后的建议层次：

```text
双目物理接收适配器
→ 左/右带时间戳帧
→ 同步质量检查
→ 立体校正
→ 深度/视差及质量
→ 与YOLO目标区域按帧关联
→ 相机坐标目标位置
→ 相机到机体外参 + 对应时刻PX4姿态
→ 局部NED TargetPositionObservation
→ TargetEstimator线性卡尔曼
```

任何一步无效都必须显式降级，不能输出0距离。

## 16. 涉及控制输出时的额外安全门禁

只有以下链路允许进入PX4：

```text
状态机/策略
→ ControlIntent
→ FlightController
→ Px4Setpoint
→ Px4Link
```

禁止：

- 算法模块直接写串口；
- 新设备模块直接发送MAVLink控制；
- 绕过FlightController限幅；
- 在`enable_control=false`时绑定Px4Setpoint；
- 用模拟数据驱动正式Px4Link；
- 未完成SITL和拆桨台架就开放控制。

任何新增控制接线都必须全局搜索并评审：

```bash
grep -RIn 'px4_link_->SetInput\|SendCommand\|Px4Setpoint' src include main.cpp
```
