# 项目文件结构与命名规划

> 状态：2026-10-19 更新为当前实际结构。本文早期版本是骨架期规划（大量
> "接口+Stub"命名尚未落地）；现行实现以本文件与 `docs/模块索引.md` 为准。
> 命名规则、模块边界、Topic 与资源管理约定继续有效。

## 1. 模块边界

正式工程按业务职责拆分，视频链路不属于 YOLO 模块：

- `application`：组件装配根 `DroneApplication`，只做创建、绑定 Topic、启停；
- `video`：RTSP/UVC 接收、解码、帧内存池、SBS 拆分、RGA 转存、叠加；
- `video_transmission`：编码与图传协议可替换边界、推流；
- `perception`：YOLO/RKNN、双目测距、WGS84→NED、目标估计、视觉稳定性判定；
- `communication`：串口、MAVLink 字节流、PX4 与地面站链路；
- `control`：飞行控制接口/实现、视觉跟踪控制律与影子；
- `state_machine`：任务状态与控制权管理（S0~S16）；
- `health`：健康状态汇总；
- `config`：JSON 配置解析与校验；
- `common`：Topic 发布订阅、公共消息类型、日志、延迟统计。

根目录中的 `videoPart` 为视频/RKNN 历史验证原型，保持不动；正式实现已独立完成，
不再从原型批量迁移。

## 3. 命名与文件组织规则

- 文件：小写下划线，如 `video_decoder.cpp`、`mission_state_machine.h`；
- 类/函数：大驼峰，如 `SerialPort`、`SendCommand()`；
- 变量：小写下划线；成员变量尾下划线，如 `running_`；
- 常量：`k` 前缀，如 `kMaxRetryCount`；
- 新头文件统一 `#pragma once`；
- 一个模块的接口、实现与实现文档同目录维护：`include/<module>/<name>.h` +
  `include/<module>/<name>.md` + `src/<module>/<name>.cpp`；
- 测试放 `tests/<module>/`，文件名与被测模块对应；
- 跨模块公共消息只放 `include/common/types.h`，Topic 名称常量只放
  `drone::common::topics`；
- 禁止在 `main.cpp`/`DroneApplication` 中写业务算法。

## 5. 发布订阅约定

当前提供 `drone::common::Topic<Message>`：

- 消息类型在编译期确定，禁止 `void*` 和无类型字节指针。
- 每个订阅者拥有独立有界队列。
- 默认队列满时丢弃最旧消息，适合视频帧和无人机最新状态。
- 可选择拒绝最新消息，用于不能覆盖旧消息的场景。
- 消息通过 `std::shared_ptr<const Message>` 分发，多订阅者间不复制消息对象。
- `Subscription` 使用 RAII 管理订阅生命周期，析构后自动取消订阅。
- 慢订阅者不会在发布者线程执行回调，也不会阻塞其他订阅者。
- 主题关闭会唤醒等待线程，支持确定性停机。

示例：

```cpp
struct DroneState {
    std::uint64_t sequence = 0;
    double latitude = 0.0;
    double longitude = 0.0;
};

drone::common::Topic<DroneState> drone_state_topic;
auto controller = drone_state_topic.Subscribe(1);
auto logger = drone_state_topic.Subscribe(32);

auto state = std::make_shared<const DroneState>(DroneState{1, 30.0, 120.0});
drone_state_topic.Publish(state);
```

视频帧主题发布内存池返回的 RAII 帧句柄。多个订阅者只共享句柄；底层缓冲在最后一个
消费者释放句柄时自动归还内存池。

## 6. 内存与资源管理规则

- 业务代码不使用 `malloc`、`calloc`、`realloc`、`free`、裸 `new` 或裸 `delete`。
- 独占资源使用 `std::unique_ptr`，共享不可变消息使用 `std::shared_ptr<const T>`。
- FFmpeg、MPP、RGA、RKNN 等 C 接口必须使用带自定义 deleter 的智能指针或独立
  RAII 包装类。
- 不把 C 接口返回的裸句柄直接暴露到模块外。
- 视频缓冲使用固定容量内存池，不在逐帧热路径中反复申请大块内存。
- 跨线程消息默认不可变；确需修改时创建新的所有权明确的输出帧。
- 构造和初始化失败可以抛异常；运行期单帧失败使用状态码或 `std::optional`。
- 容器和队列必须有容量上限，并记录丢弃计数和最大深度。
