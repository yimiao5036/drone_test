# 数据接口文档

> 最后更新：2026-08-12
> 本文定义模块间的**代码级接口契约**：公共消息类型、部件接口签名、Topic 一览。
> 与 `docs/通信与数据定义.md`（物理链路与字段语义）互补：
> 本文聚焦 C++ 代码接口，保证各部件事先对齐、并行开发不冲突。

## 1. 目的与范围

- 骨架期先冻结接口，各部件（13 个核心模块）独立开发时数据接口保持一致。
- 公共消息类型集中在 `include/common/types.h`，禁止在模块头文件中重复定义
  跨模块消息。
- 接口以 `I` 前缀命名（`ICameraReceiver`、`IVideoDecoder` 等），实现类在
  业务逻辑阶段接入；骨架期提供 `XxxStub` 占位实现。
- 消息经 `Topic<Message>`（`include/common/topic.h`）线程间传递，编译期
  类型安全、多订阅者独立有界队列、零拷贝多播。

## 2. 通用约定

### 2.1 命名空间

| 模块 | 命名空间 | 目录 |
|------|----------|------|
| 公共 | `drone::common` | `include/common/` |
| 视频 | `drone::video` | `include/video/` |
| 图传 | `drone::video_transmission` | `include/video_transmission/` |
| 感知 | `drone::perception` | `include/perception/` |
| 通信 | `drone::communication` | `include/communication/` |
| 状态机 | `drone::state_machine` | `include/state_machine/` |
| 控制 | `drone::control` | `include/control/` |
| 健康 | `drone::health` | `include/health/` |

### 2.2 字段语义约定

- 时间戳统一使用**单调时钟毫秒**（`receive_time_ms` / `valid_until_ms`）；
  设备源时间（`source_time_ms`）不可用时显式置 0，不得伪造。
- 无效数值（float 距离、精度等）使用 `NaN`；无效标志用布尔或位标志显式表达。
- `frame_id` 坐标系编码：`0=未知 1=WGS84 经纬度 2=机体(前右下) 3=局部NED 4=局部ENU`。
- `header.health`：`0=未知 1=良好 2=降级 3=故障`。
- 视频帧不直接内嵌像素数据：使用 `video::FrameHandle` 句柄经
  `Topic<video::FrameHandle>` 传递，底层缓冲由内存池管理，最后引用释放自动归还。

### 2.3 接口模式

所有部件接口统一提供：

- 生命周期：`bool Start()` / `void Stop()`（幂等）/ `bool IsRunning() const`。
- 输入绑定：`SetInput(Topic<X>&)` 或 `SetInputs(...)`（依赖注入，装配在根 `main.cpp` 完成）。
- 输出暴露：`Topic<Y>& XxxOutput()`（实现内部持有 Topic，消费者 `Subscribe` 绑定）。
- 状态查询：`uint64_t ErrorCount() const` 等计数（高频查询不打日志）。

## 3. 公共消息类型（include/common/types.h）

所有字段默认值与详细注释以头文件为准，此处列语义要点。

### 3.1 MessageHeader（通用头）

| 字段 | 语义 |
|------|------|
| sequence | 来源内单调递增序号 |
| source_time_ms | 设备/地面站产生数据时间；不可用为 0 |
| receive_time_ms | 算力板收到数据的单调时钟时间 |
| valid_for_ms | 数据允许使用时长；超时判断用 receive_time_ms |
| source_id | 数据来源标识 |
| health | 0=未知 1=良好 2=降级 3=故障 |
| frame_id | 坐标系标识（见 2.2） |

### 3.2 消息类型一览

| 类型 | 生产者 → 消费者 | 要点 |
|------|------------------|------|
| `EncodedFrame` | ICameraReceiver → IVideoDecoder | 码流块（H.264/H.265）、编码类型、流序号、关键帧标志、流级参数集（SPS/PPS）、摄像头时间 |
| `DetectionResult` | IYoloDetector → 融合/估计 | 类别、置信度、像素框、中心像素、跟踪 id、推理耗时 |
| `OpticalFlowResult` | IOpticalFlowEstimator → 融合 | 当前/参考帧序号、像素位移、质量 [0,1] |
| `LaserRangeSample` | ILaserRangeFinder → 融合 | 单点距离、质量、错误码、更新频率、连续异常计数 |
| `GroundStationTarget` | IGroundStationLink → 估计/状态机 | WGS-84 定点（×1e7）、速度、航向、精度、有效性标志 |
| `FlightStateSnapshot` | IPx4Link → 状态机/控制/融合 | 连接/解锁/落地、GPS、局部位置速度、姿态、Home、电池、RC、最近 ACK |
| `ControlIntent` | IMissionStateMachine → IFlightController | 意图类型（位置/速度/刹停/起降/返航/接管）、优先级、有效期、原因 |
| `Px4Setpoint` | IFlightController → IPx4Link | 本地 NED 位置/速度、yaw/yaw rate 选择、有效期；姿态预留 |
| `HealthStatus` | IHealthManager → 状态机/地面站 | 链路/设备健康位、数据新鲜度位、错误位、负载 |
| `MissionStatus` | IMissionStateMachine → IGroundStationLink | 当前任务状态（S0~S16）、控制来源、告警、拦截授权、电源状态 |
| `TargetState` | 融合/估计 → 状态机与控制 | 目标位置/速度、置信度、最近观测时间、有效标志 |

### 3.3 枚举

| 枚举 | 取值 |
|------|------|
| `MissionState` | S0~S16 共 17 态（`kBoot`~`kFailsafe`），与 `docs/状态机设计.md` 一致 |
| `ControlIntentType` | `kNone / kPositionGuide / kVelocityHeading / kBrakeHover / kTakeoff / kLand / kRtl / kManualOverride` |
| `SetpointType` | `kNone / kPosition / kVelocity / kAttitude` |
| `VideoCodec` | `kUnknown / kH264 / kH265` |

### 3.3.1 EncodedFrame 参数集说明

- `codec`：码流编码类型（H.264/H.265），解码器据此选择解码器。
- `parameter_sets`：流级参数集（RTSP 从 SDP/容器头提取的 SPS/PPS 等，annexb 或 avcC/hvcC 原始字节）。
  RTSP/容器流的参数集不在逐帧码流中，由 `ICameraReceiver` 在连接建立后单独发布一条
  **仅含参数集的消息**（`data` 为空）；裸码流无独立参数集时留空，解码器从关键帧内嵌
  参数集解析。
- 解码器在参数集就绪前**跳过非关键帧**（等待关键帧同步），队列丢帧不会破坏解码链路。

### 3.4 位标志定义

- `GroundStationTarget.validity_flags`：bit0=vN bit1=vE bit2=vD bit3=heading
  bit4=horizontal_accuracy bit5=vertical_accuracy。
- `HealthStatus.link_health_bits`：bit0=摄像头 bit1=PX4 bit2=地面站电台
  bit3=激光雷达 bit4=图传；`data_freshness_bits` 同序（0=新鲜 1=超时）。
- `HealthStatus.device_health_bits`：bit0=解码器 bit1=NPU/YOLO bit2=电源A bit3=电源B。
- `MissionStatus.power_status_bits`：bit0=电源A可用 bit1=电源B可用。

### 3.5 附录：ControlIntent.reason_code 编码（骨架期草案，实现期确认）

| code | 含义 |
|------|------|
| 0 | 未知 |
| 1 | 目标丢失（估计超龄） |
| 2 | 前方障碍物 |
| 3 | 任务完成 |
| 4 | 拦截授权被拒 |
| 5 | 电源低 |
| 6 | 遥控器人工接管 |
| 7 | 地面站任务下发 |

## 4. 部件接口契约

> 骨架期接口方法签名、输入输出类型以此为准；业务逻辑阶段实现类必须
> 保持签名不变，仅替换 Stub 实现。

### 4.1 ICameraReceiver（drone::video）

- 职责：TCP 建连、接收 H.265 码流、断线重连。
- 生命周期：Start / Stop / IsRunning。
- 状态：IsConnected / ConnectCount / ReceivedBytes / ErrorCount。
- 输出：`Topic<common::EncodedFrame>& StreamOutput()`。
- 可替换边界：视频协议适配器。

### 4.2 IVideoDecoder（drone::video）

- 职责：订阅码流，解码为帧（NV12），发布 FrameHandle（零拷贝、池回收）。
- 输入：`SetInput(Topic<common::EncodedFrame>&)`；输出：`Topic<video::FrameHandle>& FrameOutput()`。
- 状态：DecodedFrameCount / DroppedFrameCount / ErrorCount。
- 可替换边界：软件/硬件解码后端。

### 4.3 IVideoSender（drone::video_transmission）

- 职责：订阅标注帧，编码推图传；拥塞只丢图传帧，不反压上游。
- 输入：`SetInput(Topic<video::FrameHandle>&)`。
- 状态：SentFrameCount / DroppedFrameCount / ErrorCount。
- 图传地址：`VideoSenderConfig.encode.url`由配置模块注入；正式多机配置使用`video.output_rtsp`身份模板，运行时展开为`/drone_<component_id>_<system_id>`，例如捕网-01为`/drone_25_1`。
- 可替换边界：图传协议适配器（实现见 `IVideoEncoderBackend`，`include/video_transmission/video_encoder.h`；
  `VideoSender` 构造 `VideoSenderConfig` 含 `encode` 后端配置，测试经 `backend_factory` 注入）。

### 4.4 IYoloDetector（drone::perception）

- 职责：订阅解码帧，YOLO 推理，输出结构化检测结果。
- 输入：`SetInput(Topic<video::FrameHandle>&)`；输出：`Topic<common::DetectionResult>& DetectionOutput()`。
- 状态：ProcessedFrameCount / InferenceTimeMsAvg / ErrorCount。
- 可替换边界：模型与推理后端。

### 4.5 IOpticalFlowEstimator（drone::perception）

- 职责：订阅相邻帧，估计光流与质量。
- 输入：`SetInput(Topic<video::FrameHandle>&)`；输出：`Topic<common::OpticalFlowResult>& FlowOutput()`。
- 可替换边界：光流算法。

### 4.6 ILaserRangeFinder（drone::perception）

- 职责：串口读取、校验、时间标记单点距离（机头前向）。
- 输出：`Topic<common::LaserRangeSample>& RangeOutput()`；LastDistanceM。
- 可替换边界：雷达型号适配器。

### 4.7 IPerceptionFusion（drone::perception）

- 职责：对齐检测/光流/雷达/机体姿态，输出目标状态。
- 输入：`SetInputs(Detection, Flow, Range, Flight)`；
  输出：`Topic<common::TargetState>& TargetOutput()`。
- 可替换边界：融合算法。

### 4.8 ITargetEstimator（drone::perception）

- 职责：融合感知目标与地面站目标，平滑/预测维护目标状态。
- 输入：`SetInputs(Topic<TargetState>&, Topic<GroundStationTarget>&)`；
  输出：`Topic<common::TargetState>& EstimatedOutput()`。
- 可替换边界：卡尔曼或其他估计器。

### 4.9 IPx4Link（drone::communication）

- 职责：PX4 MAVLink 双向通信、飞行状态快照、设定值/命令发送与 ACK 关联；
  只有本链路线程可写飞控串口。
- 输入：`SetInput(Topic<common::Px4Setpoint>&)`；
  输出：`Topic<common::FlightStateSnapshot>& StateOutput()`。
- 命令：`SendCommand(mavlink_command, param1~param7)`。
- 状态：SetpointSendCount / ReceiveCount / AckMatchCount / AckTimeoutCount / ErrorCount。
- 当前适配固件：PX4 1.17.0；版本标识由 `Px4LinkConfig.firmware_version`/JSON 配置记录，
  后续使用 `AUTOPILOT_VERSION` 与实机上报版本核验。
- 当前实现：真实 `Px4Link` 已完成心跳/版本/遥测、新鲜度、可靠命令/ACK 和安全消息请求；
  已支持最新有效 `Px4Setpoint` 按固定周期编码为 `SET_POSITION_TARGET_LOCAL_NED`，包括本地
  NED 位置/速度、可选 yaw/yaw rate、type mask 和过期停止。姿态/全局设定值及串口自动重连
  后续实现。Stub 继续用于冒烟测试。
- `FlightStateSnapshot` 心跳阶段新增 `base_mode/custom_mode/flight_mode/flight_sub_mode/system_status`；
  `landed` 只有 `landed_state_valid=true` 时可用。
- 可替换边界：PX4 版本适配层。

### 4.10 IGroundStationLink（drone::communication）

- 职责：地面站 MAVLink 双向通信——当前订阅PX4飞行快照并下发标准遥测，使用标准TIMESYNC维护地面站时钟offset/RTT/jitter，上行目标消息仍预留。
- 状态：`GroundStationTimeSyncStatus GetTimeSyncStatus() const`返回`UNSYNCHRONIZED/ACQUIRING/SYNCHRONIZED/DEGRADED`、offset、RTT、jitter、样本年龄和统计计数。
- 上行输出：`Topic<common::GroundStationTarget>& TargetOutput()`（`TRACK_TARGET_UPDATE`通过`V2_EXTENSION.message_type=65010`解析，合法目标发布；不产生控制输出）；
- 下行输入：`SetFlightStateInput(Topic<FlightStateSnapshot>&)`；
  `SetMissionStatusInput(Topic<MissionStatus>&)`与`SetHealthInput(Topic<HealthStatus>&)`当前预留。
- 当前真实实现使用独立串口线程和MAVLink 2，发送HEARTBEAT、ATTITUDE、LOCAL/GLOBAL_POSITION、GPS、EXTENDED_SYS_STATE、SYS_STATUS、BATTERY_STATUS、HOME_POSITION和定向TIMESYNC；频率由JSON配置。
- 不做PX4原始字节透明转发，不接收地面站飞行控制命令。实现文档见`include/communication/ground_station_link.md`。
- 多机身份与寻址以`docs/多机身份与功能寻址设计.md`为准且C++侧已实施：PX4链路维持`1/191→1/1`，地面站链路使用`(system,component)`二元身份，捕网类N号=`N/25`、火箭类N号=`N/26`，地面站来源固定`255/190`。
- 可替换边界：MAVLink dialect/电台适配器。

### 4.11 IMissionStateMachine（drone::state_machine）

- 职责：按 S0~S16 状态机决策，输出控制意图与任务状态回传。
- 输入：`SetInputs(Topic<TargetState>&, Topic<FlightStateSnapshot>&, Topic<HealthStatus>&)`。
- 输出：`Topic<common::ControlIntent>& IntentOutput()`；
  `Topic<common::MissionStatus>& StatusOutput()`。
- 状态：CurrentState / TransitionCount / ErrorCount。
- 可替换边界：不依赖具体设备。

### 4.12 IFlightController（drone::control）

- 职责：控制意图 → PX4 设定值。
- 输入：`SetInput(Topic<common::ControlIntent>&)`；
  输出：`Topic<common::Px4Setpoint>& SetpointOutput()`。
- 可替换边界：控制算法。

### 4.13 IHealthManager（drone::health）

- 职责：数据源新鲜度与健康监控，汇总发布。
- 监控：`RegisterSource(name, max_age_ms)` / `ReportData(name, receive_time_ms)`。
- 输出：`Topic<common::HealthStatus>& Output()`。
- 可替换边界：健康规则。

### 4.14 SerialPort（drone::communication，基础支撑，真实实现）

- 所有串口链路（PX4、地面站电台、激光雷达）统一封装。
- `Open()` 失败抛 `std::system_error`；`Read/Write` 运行时错误返回码，
  经 `ErrorCount()` 监控；创建/销毁/打开/读写错误均按日志规范记录。
- 非阻塞 fd + `poll()` 单调时钟控制读写超时，每条物理链路独占一个实例。

### 4.15 CommunicationTransport（drone::communication，物理传输边界）

- `ICommunicationTransport` 统一 `Open/Close/Read/Write/Flush`；
- `SerialTransport` 用于香橙派 `/dev/ttyS1`，`UdpTransport` 用于 PX4 SITL；
- `Px4Link` 的 MAVLink/Topic/状态逻辑不依赖具体传输；地面站后续可复用该边界。

### 4.16 MavlinkHandler（drone::communication，协议基础支撑）

- 每条 MAVLink 物理链路独占一个实例，负责增量字节流解析和完整帧序列化。
- 接收同时兼容 MAVLink 1/2，支持半包、粘包、CRC/签名错误拒绝和坏帧后恢复。
- 发送使用实例私有 `mavlink_status_t` 维护序号，禁止 PX4/地面站链路共享全局 channel 状态。
- 不解释 PX4/地面站业务字段；具体消息转换由对应 Link 完成。
- 实现与测试说明见 `include/communication/mavlink_handler.md`。

## 6. 骨架实现说明

- 骨架期所有业务接口为纯虚抽象；`XxxStub` 为占位实现。
- Stub 行为：
  - 生命周期可运行：Start 返回 true、Stop 幂等，均打 INFO 日志。
  - 未实现业务方法（如 `Px4LinkStub::SendCommand`、`HealthManagerStub::RegisterSource`）
    返回默认失败值，打 WARN 节流日志（第 1 次 + 每满 100 次）。
  - 输出 Topic 可发布/订阅，供装配联调验证。
- 实现期替换规则：实现类继承接口、保持签名不变；输入绑定在根 `main.cpp`
  统一装配；删除 Stub 或保留用于测试由实现期决定。
- 冒烟测试 `tests/skeleton/stub_smoke_test.cpp`：验证 Stub 构造/启停/输出
  主题/默认值，作为装配基线。
