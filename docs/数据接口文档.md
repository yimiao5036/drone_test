# 数据接口文档

> 最后更新：2026-10-19（P3 速度前馈字段、S12 返航 reason=8、S11~S14 状态链）。
> 本文定义模块间的**代码级接口契约**：公共消息类型、部件接口签名、Topic 一览。
> 与 `docs/archive/早期设计/通信与数据定义.md`（物理链路与字段语义）互补：
> 本文聚焦 C++ 代码接口，保证各部件事先对齐、并行开发不冲突。

## 1. 目的与范围

- 骨架期先冻结接口，各部件（13 个核心模块）独立开发时数据接口保持一致。
- 公共消息类型集中在 `include/common/types.h`，禁止在模块头文件中重复定义
  跨模块消息。
- 接口以 `I` 前缀命名（`ICameraReceiver`、`IVideoDecoder` 等），实现类在
  业务逻辑阶段接入；骨架期提供 `XxxStub` 占位实现。
- 消息经 `Topic<Message>`（`include/common/topic.h`）线程间传递，编译期
  类型安全、多订阅者独立有界队列、零拷贝多播。

## 2. 通用约定

### 2.1 命名空间

| 模块 | 命名空间 | 目录 |
|------|----------|------|
| 公共 | `drone::common` | `include/common/` |
| 视频 | `drone::video` | `include/video/` |
| 图传 | `drone::video_transmission` | `include/video_transmission/` |
| 感知 | `drone::perception` | `include/perception/` |
| 通信 | `drone::communication` | `include/communication/` |
| 状态机 | `drone::state_machine` | `include/state_machine/` |
| 控制 | `drone::control` | `include/control/` |
| 健康 | `drone::health` | `include/health/` |

### 2.2 字段语义约定

- 时间戳统一使用**单调时钟毫秒**（`receive_time_ms` / `valid_until_ms`）；
  设备源时间（`source_time_ms`）不可用时显式置 0，不得伪造。
- 无效数值（float 距离、精度等）使用 `NaN`；无效标志用布尔或位标志显式表达。
- `frame_id` 坐标系编码：`0=未知 1=WGS84 经纬度 2=机体(前右下) 3=局部NED 4=局部ENU`。
- `header.health`：`0=未知 1=良好 2=降级 3=故障`。
- 视频帧不直接内嵌像素数据：使用 `video::FrameHandle` 句柄经
  `Topic<video::FrameHandle>` 传递，底层缓冲由内存池管理，最后引用释放自动归还。

### 2.3 接口模式

所有部件接口统一提供：

- 生命周期：`bool Start()` / `void Stop()`（幂等）/ `bool IsRunning() const`。
- 输入绑定：`SetInput(Topic<X>&)` 或 `SetInputs(...)`（依赖注入，装配在根 `main.cpp` 完成）。
- 输出暴露：`Topic<Y>& XxxOutput()`（实现内部持有 Topic，消费者 `Subscribe` 绑定）。
- 状态查询：`uint64_t ErrorCount() const` 等计数（高频查询不打日志）。

## 3. 公共消息类型（include/common/types.h）

所有字段默认值与详细注释以头文件为准，此处列语义要点。

### 3.1 MessageHeader（通用头）

| 字段 | 语义 |
|------|------|
| sequence | 来源内单调递增序号 |
| source_time_ms | 设备/地面站产生数据时间；不可用为 0 |
| receive_time_ms | 算力板收到数据的单调时钟时间 |
| valid_for_ms | 数据允许使用时长；超时判断用 receive_time_ms |
| source_id | 数据来源标识 |
| health | 0=未知 1=良好 2=降级 3=故障 |
| frame_id | 坐标系标识（见 2.2） |

### 3.2 消息类型一览

| 类型 | 生产者 → 消费者 | 要点 |
|------|------------------|------|
| `EncodedFrame` | ICameraReceiver → IVideoDecoder | 码流块（H.264/H.265）、编码类型、流序号、关键帧标志、流级参数集（SPS/PPS）、摄像头时间 |
| `DetectionResult` | IYoloDetector → 叠加 | 类别、置信度、像素框、中心像素、跟踪 id、推理耗时；每目标一条 |
| `VisualTargetObservation` | IYoloDetector → 视觉稳定性判定 | 帧级单目标观测；每成功推理帧一条，`detected=false` 表示本帧无目标 |
| `VisualTargetStatus` | 视觉稳定性判定 → VisualTrackingShadow（影子） | `SEARCHING/ACQUIRING/LOCKED/LOST`、连续检测/丢失帧数、平滑中心与置信度 |
| `StereoTargetDistance` | StereoRanger（影子）→ VisualTrackingShadow 距离通道（可选）、TargetEstimator 视觉融合（可选） | 每左目检测框一条；前向距离/斜距（EMA 后）、近端簇中位视差与 IQR、基准相机系三维位置（camera_x/y_m，z=forward_distance_m）、valid；无效时距离/相机系字段 NaN（v2 语义，2026-10-10；相机系字段 2026-10-12 增） |
| `OpticalFlowResult` | IOpticalFlowEstimator → 融合 | 当前/参考帧序号、像素位移、质量 [0,1] |
| `LaserRangeSample` | 兼容预留；后续可由双目深度适配层替代/复用 | 距离、质量、错误码、更新频率、连续异常计数；当前不接独立激光雷达 |
| `GroundStationTarget` | IGroundStationLink → 估计/状态机 | WGS-84 定点（×1e7）、速度、航向、精度、有效性标志 |
| `FlightStateSnapshot` | IPx4Link → 状态机/控制/融合 | 连接/解锁/落地、GPS、局部位置速度、姿态、Home、**EKF 锚点（`ned_ref_*`，2026-10-15 增）**、电池、**PX4 电池参数（`battery_low_threshold_*`/`low_battery_action_*`，2026-10-22 增）**、RC、最近 ACK |
| `ControlIntent` | IMissionStateMachine → IFlightController | 意图类型（位置/速度/刹停/起降/返航/接管）、优先级、有效期、原因、**位置型逐轴速度前馈（P3）** |
| `Px4Setpoint` | IFlightController → IPx4Link | 本地 NED 位置/速度、yaw/yaw rate 选择、有效期；姿态预留、**位置型逐轴速度前馈（P3）** |
| `HealthStatus` | IHealthManager → 状态机/地面站 | 链路/设备健康位、数据新鲜度位、错误位、负载 |
| `MissionStatus` | IMissionStateMachine → IGroundStationLink | 当前任务状态（S0~S16）、控制来源、告警、拦截授权、电源状态；65013 v2 附带 assignment_id/target_id/availability/interceptor_type |
| `MissionAssignment` | IGroundStationLink → IMissionStateMachine | 65014 任务分配：assignment_id、target_id、interceptor_type、flags（bit0=授权自动起飞、bit1=取消当前分配）、valid_for_ms；仅地址双字段匹配后发布 |
| `MissionAssignmentAck` | IMissionStateMachine → IGroundStationLink | 65015 分配回执：assignment_id、target_id、result、reason、mission_state、availability |
| `TargetState` | 融合/估计 → 状态机与控制 | 局部NED目标位置/速度、时效置信度、最近观测时间、有效标志、**逐轴速度前馈可用位（P3）**；垂直无效时Z/VZ为NaN |

### 3.2.1 位置速度前馈字段（P3，2026-10-19）

| 结构 | 字段 | 语义 |
|---|---|---|
| `TargetState` | `velocity_valid_mask` | 逐轴速度前馈可用位（0=不可用）；地面站速度位优先，缺失轴回退 KF（≥5 次位置更新），过期/重置清零 |
| `ControlIntent` | `feedforward_vx/vy/vz_mps` | 位置型意图的 N/E/D 速度前馈（局部 NED，m/s） |
| | `feedforward_valid_mask` | 逐轴有效位；仅 `kPositionGuide` 使用，速度型为 0 |
| `Px4Setpoint` | `feedforward_vx/vy/vz_mps` | 位置型设定值的前馈速度（局部 NED，m/s） |
| | `feedforward_valid_mask` | 0=无前馈（旧行为）；位置型按位放行对应速度轴，速度型必须为 0 |

逐轴位定义（`common::kVelocityValid*`）：bit0=N、bit1=E、bit2=D，合法域 `0x07`。
**不要与 `GroundStationTarget.validity_flags` 的 bit1/2/3 混用**（后者在
`TargetEstimator` 内显式映射为 bit0/1/2）。控制器侧开关
`controller.enable_position_velocity_feedforward` 默认关闭，关闭时全部清零。

### 3.2.2 FlightStateSnapshot 电池参数字段（2026-10-22 增）

PX4 参数 `BAT_LOW_THR` / `COM_LOW_BAT_ACT` 经 `PARAM_REQUEST_READ`/`PARAM_VALUE`
读取后写入快照，用于自动分配/起飞与机载低电守卫。参数是**静态配置**，不参与
`telemetry_timeout`；断连/Stop 时两个 valid 立即清零。

| 字段 | 类型 | 语义 |
|---|---|---|
| `battery_low_threshold_valid` | bool | `BAT_LOW_THR` 已读取且当前连接有效 |
| `battery_low_threshold_pct` | float | `BAT_LOW_THR` 百分比（PX4 norm×100，如 0.15→15.0）；`valid=false` 时不可用，不得当作 0 |
| `low_battery_action_valid` | bool | `COM_LOW_BAT_ACT` 已读取且当前连接有效 |
| `low_battery_action` | uint8_t | `COM_LOW_BAT_ACT` 枚举（float 四舍五入并夹紧到 0~255）；0=Warning Only |
| `battery_parameter_time_ms` | uint64_t | 最近一次电池参数回包的算力板单调时钟毫秒；断连清零 |

### 3.3.2 65014 取消与目标编号过滤（2026-10-22 Task 10）

- `flags.bit1=1` 表示取消 `assignment_id` 对应的当前分配；取消消息**不要求**
  `flags.bit0`。状态机先于重复/普通预检处理取消，`assignment_id` 必须匹配
  当前活动分配；重复取消幂等重发最近结果（地面取消后回 READY，空中取消
  `AbortAirborne` → S12），500ms 内不重复下发命令。
- 65015 回执：`result=kCancelledOrAborted`，`reason=cancelled_by_gcs`；
  无活动分配且 id 从未处理 → `rejected(not_ready)`。
- 控制任务下 65010 与 `TargetState` 均按 `target_id == assignment.target_id`
  过滤：非匹配目标不进入 S5、不更新位置引导、不参与交接；GroundStationLink
  仍可照常做链路 ACK。影子模式不过滤。

### 3.3.1 EncodedFrame 参数集说明

- `codec`：码流编码类型（H.264/H.265/MJPEG），解码器据此选择解码器。
- `parameter_sets`：流级参数集（RTSP 从 SDP/容器头提取的 SPS/PPS 等，annexb 或 avcC/hvcC 原始字节）。
  RTSP/容器流的参数集不在逐帧码流中，由 `ICameraReceiver` 在连接建立后单独发布一条
  **仅含参数集的消息**（`data` 为空）；裸码流无独立参数集时留空，解码器从关键帧内嵌
  参数集解析。
- MJPEG（USB UVC 双目）语义：一帧一个访问单元、`is_key_frame` 恒为 true、无参数集、
  帧间无依赖；单帧解码失败仅丢该帧，无 H.26x 的参数集同步问题。
- 解码器送包策略：解码器未创建时用首个数据帧（任意类型）创建并一并送包，此后全量送包，
  由解码器自行完成参数集同步与关键帧等待（不按"未初始化跳过非关键帧"，见
  `include/video/video_decoder.md`）；队列丢帧不会破坏解码链路。

### 3.4 位标志定义

- `GroundStationTarget.validity_flags`：bit0=altitude bit1=vN bit2=vE bit3=vD
  bit4=heading bit5=horizontal_accuracy bit6=vertical_accuracy。
- `TargetState.velocity_valid_mask` / `ControlIntent.feedforward_valid_mask` /
  `Px4Setpoint.feedforward_valid_mask`：bit0=N bit1=E bit2=D（P3，2026-10-19）；
  与上一条地面站 flags 位号不同，估计器负责映射。
- `HealthStatus.link_health_bits`：bit0=双目摄像头 bit1=PX4 bit2=地面站电台
  bit3=兼容预留（原激光雷达）bit4=图传；`1=已注册且健康`，未注册或不可用为0；
  `data_freshness_bits` 同序（0=新鲜 1=超时）。
- `HealthStatus.device_health_bits`：bit0=解码器 bit1=NPU/YOLO bit2~3=兼容预留（取消独立电源管理）；
  `1=已注册且健康`，未注册或不可用为0。
- `HealthStatus.error_bits`为活动错误：bit0=摄像头 bit1=视频解码器 bit2=NPU/YOLO
  bit3=PX4通信 bit4=地面站通信 bit5=图传 bit6~7=兼容预留；
  模块错误事件置位，收到时间更新的有效数据后清除。
- `HealthStatus.timeout_event_count`：HealthManager累计进入数据超时状态的事件次数。
- `HealthStatus.cpu_load_pct`由`/proc/stat`差分采样，预热/失败时为NaN；状态回传编码为`cpu_load_x100`并使用`status_flags.bit0`标识有效性。
- `MissionStatus.active_warning_bits`（状态机告警位；2026-10-13 阶段四 Task 12 冻结）：
  bit0=尚未收到满足 GPS 引导要求的 PX4 导航快照；bit1=已进入 `GPS_APPROACH` 但最新地面站
  目标超过剩余有效期（目标过期）；bit2=VISUAL_TRACKING 期间卡尔曼热备份断粮（状态年龄超窗，
  只提示"假备份"风险、不退出 S7）；bit3=**S7 伺服停发中**（`VISUAL_TRACKING` 且本拍未发出
  视觉伺服意图——伺服尚未启动仍在续发冻结位置意图，或控制律降级停发，标注"报告状态与实际
  控制输出背离"）；bit4=**捕网执行器 ACK 故障**（187 ACK 超时/非 ACCEPTED/PX4 断连/S10
  触发命令入队超时，状态机同时进入 S16 FAILSAFE 并停发一切控制意图，2026-10-21 Task 5）；
  bit5=**S5 目标失效保持中**（目标不可用且正在发原地保持位置意图，原因码 9，2026-10-22）。
  bit0~bit3、bit5 为"当前活动"语义：条件解除即清除，离开对应状态即清零；bit4 为故障终态，
  置位保持到程序重启。
  定义源：`src/state_machine/mission_state_machine.cpp`（`kWarning*` 常量）；
  下行编码见 `docs/地面站目标位置与时间同步协议.md` §14.3（65013 `active_warning_bits`）。
- `MissionStatus.power_status_bits`：兼容保留，当前产品不使用；电量统一读取`FlightStateSnapshot`中的PX4动力电池状态。

## 4. 部件接口契约

> 骨架期接口方法签名、输入输出类型以此为准；业务逻辑阶段实现类必须
> 保持签名不变，仅替换 Stub 实现。

### 4.1 ICameraReceiver（drone::video）

- 职责：摄像头码流接入与断线重连。实现二选一（`video.camera_source`）：
  `CameraReceiver`（RTSP建连、接收H.264/H.265码流）、
  `UvcCameraReceiver`（V4L2 UVC采集MJPG SBS帧，`codec=kMjpeg`、无参数集）。
- 生命周期：Start / Stop / IsRunning。
- 状态：IsConnected / ConnectCount / ReceivedBytes / ErrorCount。
- 输出：`Topic<common::EncodedFrame>& StreamOutput()`。
- 可替换边界：视频协议适配器。

### 4.2 IVideoDecoder（drone::video）

- 职责：订阅码流，解码为帧（NV12），发布 FrameHandle（零拷贝、池回收）。
- 输入：`SetInput(Topic<common::EncodedFrame>&)`；输出：`Topic<video::FrameHandle>& FrameOutput()`。
- 状态：DecodedFrameCount / DroppedFrameCount / ErrorCount；延迟诊断提供总解码统计、五项解码细分、实际输入编码/解码模式及访问单元/字节/关键帧累计值。
- 可替换边界：软件/硬件解码后端。

### 4.3 IVideoSender（drone::video_transmission）

- 职责：订阅标注帧，编码推图传；拥塞只丢图传帧，不反压上游。
- 输入：`SetInput(Topic<video::FrameHandle>&)`。
- 状态：SentFrameCount / DroppedFrameCount / ErrorCount。

### 4.9 ITargetEstimator（drone::perception）

- 当前职责：单目标第一阶段，以 **EKF 投影参考锚点**（#49 `ref_*` = PX4 `MAV_FRAME_LOCAL_NED` 原点）为局部NED原点，将地面站目标经纬度转换为NED并通过恒速度线性卡尔曼平滑/预测。
  **✅ 方案 C 已落地（2026-10-16）**：换算基准 = 锚点 = 设定值执行帧原点（"原点即执行帧"成立，不再有 Home 基准差 H）；重置触发改为锚点变化。背景与边界见 `docs/方案C锚点基准实施清单.md`、`docs/故障排查手册.md` §12.1。
- 输入：`SetGroundTargetInput(Topic<GroundStationTarget>&)`、`SetFlightStateInput(Topic<FlightStateSnapshot>&)`；
  输出：`Topic<common::TargetState>& EstimatedOutput()`，并提供线程安全`LastState()`快照。
- 当前状态：生产 `DroneApplication` 尚未调用 `SetEstimationInputs`（影子）；stage4 验收工具已把本输出绑定状态机（S5/S6/S7），仍不直接产生 `ControlIntent`/`Px4Setpoint`。
- 速度前馈字段（P3）：`velocity_valid_mask` 逐轴标注 `vel_*_mps` 是否可用于前馈（地面站速度位优先，KF 自算速度 ≥5 次位置更新兜底），详见 §3.2.1。
- 地面站高度无效或不是MSL时只发布水平状态，`pos_z_m/vel_z_mps=NaN`。
- 后续双目观测必须先结合相机标定、PX4对应时刻姿态和深度转换为局部NED位置，再进入线性滤波器。

### 4.9 IPx4Link（drone::communication）

- 职责：PX4 MAVLink 双向通信、飞行状态快照、设定值/命令发送与 ACK 关联；
  只有本链路线程可写飞控串口。
- 输入：`SetInput(Topic<common::Px4Setpoint>&)`；
  输出：`Topic<common::FlightStateSnapshot>& StateOutput()`。
- 命令：`SendCommand(mavlink_command, param1~param7)`；
  `CancelPendingCommands()` 清空排队与在途命令（线程安全：只置取消标志，由链路通信线程
  在下一次循环执行；已写入串口的命令无法撤回，取消 ≤ 一次读超时内生效）。
- 状态：SetpointSendCount / ReceiveCount / AckMatchCount / AckTimeoutCount / ErrorCount；
  `AckStatus()` 返回 `common::CommandAckStatus{matched_count, timeout_count,
  last_command, last_result, last_time_ms, last_timeout_command,
  do_set_actuator_ack_count, do_set_actuator_last_result,
  do_set_actuator_last_time_ms, do_set_actuator_timeout_count}` 快照，计数单调递增，
  供状态机判断最近命令是否被接受。`do_set_actuator_*` 只统计
  `MAV_CMD_DO_SET_ACTUATOR(187)`，避免复位等待期间 AUTO.LAND(176)/DISARM(400)
  的 ACK 覆盖 187 终态；捕网执行器只消费这组字段。
- 当前适配固件：PX4 1.17.0；版本标识由 `Px4LinkConfig.firmware_version`/JSON 配置记录，
  后续使用 `AUTOPILOT_VERSION` 与实机上报版本核验。
- 当前实现：真实 `Px4Link` 已完成心跳/版本/遥测、新鲜度、可靠命令/ACK 和安全消息请求；
  已支持最新有效 `Px4Setpoint` 按固定周期编码为 `SET_POSITION_TARGET_LOCAL_NED`，包括本地
  NED 位置/速度、位置+逐轴速度前馈（P3）、可选 yaw/yaw rate、type mask 和过期停止。
  串口连续读错误时关闭端口并按 `reconnect_interval` 自动重开，重连期间发布
  `connected=false` 快照；姿态/全局设定值尚未实现。Stub 继续用于冒烟测试。
- `FlightStateSnapshot` 心跳阶段新增 `base_mode/custom_mode/flight_mode/flight_sub_mode/system_status`；
  `landed` 只有 `landed_state_valid=true` 时可用。
- 可替换边界：PX4 版本适配层。

### 4.10 IGroundStationLink（drone::communication）

- 职责：地面站 MAVLink 双向通信——订阅PX4飞行快照并下发标准遥测，使用标准TIMESYNC维护地面站时钟offset/RTT/jitter，通过`V2_EXTENSION.message_type=65010/65011`完成上行目标UPDATE/ACK，并通过`65014/65015`完成任务分配接收与回执发送。
- 状态：`GroundStationTimeSyncStatus GetTimeSyncStatus() const`返回`UNSYNCHRONIZED/ACQUIRING/SYNCHRONIZED/DEGRADED`、offset、RTT、jitter、样本年龄和统计计数。
- 上行输出：`Topic<common::GroundStationTarget>& TargetOutput()`（65010 合法目标发布；不产生控制输出）；
  `Topic<common::MissionAssignment>& MissionAssignmentOutput()`（65014 帧头与 payload 地址双字段匹配本机后原样发布，语义校验在状态机；不匹配直接丢弃且不回 65015）。
- 下行输入：`SetFlightStateInput(Topic<FlightStateSnapshot>&)`；
  `SetMissionStatusInput(Topic<MissionStatus>&)`（65013 v2）、`SetHealthInput(Topic<HealthStatus>&)`（65012 v1）；
  `SetMissionAssignmentAckInput(Topic<MissionAssignmentAck>&)`（每条回执编码为 65015 发往 255/190，不要求地面站 ACK）。
- 当前真实实现使用独立串口线程和MAVLink 2，发送HEARTBEAT、ATTITUDE、LOCAL/GLOBAL_POSITION、GPS、EXTENDED_SYS_STATE、SYS_STATUS、BATTERY_STATUS、HOME_POSITION和定向TIMESYNC；频率由JSON配置。
- 不做PX4原始字节透明转发，不接收地面站飞行控制命令。实现文档见`include/communication/ground_station_link.md`。
- 多机身份与寻址以`docs/多机身份与功能寻址设计.md`为准且C++侧已实施：PX4链路维持`1/191→1/1`，地面站链路使用`(system,component)`二元身份，捕网类N号=`N/25`、火箭类N号=`N/26`，地面站来源固定`255/190`。
- 可替换边界：MAVLink dialect/电台适配器。

### 4.11 IMissionStateMachine（drone::state_machine）

- 职责：按 S0~S16 状态机决策，输出控制意图与任务状态回传。
- 输入：`SetInputs(Topic<GroundStationTarget>&, Topic<FlightStateSnapshot>&, Topic<HealthStatus>&)`。
- 输出：`Topic<common::ControlIntent>& IntentOutput()`；
  `Topic<common::MissionStatus>& StatusOutput()`。
- 当前状态：绑定 `SetEstimationInputs` 后，导航快照与目标有效时进入 `GPS_APPROACH` 并发布 S5 位置意图（P3 起携带逐轴速度前馈）；S6 冻结续发纯位置、S7 发布视觉速度意图。生产 `DroneApplication` 尚未调用 `SetEstimationInputs`（保持影子），完整链路在 stage4 验收工具中装配；`enable_control` 为 false 时意图不会到达 PX4。
- S11~S14（2026-10-19 V1）：S10 发射命令入队/超时→S11 记录（不判命中）→S12 位置设定值返航 Home（reason=8；Home 局部 NED 由 Home 经纬度+EKF 锚点换算）→S13 AUTO.LAND（4/6）→S14 DISARMED。S9/S10 入口已由 `interception` 配置节实现（默认 `enabled=false`；射程占位待实机冻结），自动授权后进入 S10；测试钩子仍可用于自动授权之外场景。
- 状态：CurrentState / TransitionCount / ErrorCount。
- 可替换边界：不依赖具体设备。

  输出：`Topic<common::Px4Setpoint>& SetpointOutput()`。

### 4.13 IHealthManager（drone::health）

- 职责：系统级健康状态汇总器。按单调时钟检查双目摄像头、PX4、地面站、图传、解码器和NPU/YOLO等当前数据源的新鲜度，汇总链路/设备健康位、数据新鲜度位、错误位和算力负载。
- 监控：`RegisterSource(name, max_age_ms)` / `ReportData(name, receive_time_ms)`。
- 输出：`Topic<common::HealthStatus>& Output()`，供任务状态机做安全门禁与降级判断，供地面站做诊断回传。
- 边界：不负责硬件读写、重连、任务状态转移或 PX4 控制输出；真实实现由各模块提供事实，状态机负责结合任务阶段做决策。
- 当前状态：`HealthManager`已实现数据源注册、新鲜度检查、`/proc/stat`整机CPU负载和现有模块活动错误位发布；`HealthManagerStub`继续保留供骨架测试。独立激光雷达和电源监测已取消，兼容位不注册；详细说明见`include/health/health_manager.md`。

### 4.14 SerialPort（drone::communication，基础支撑，真实实现）

- 所有串口链路（PX4、地面站电台、激光雷达）统一封装。
- `Open()` 失败抛 `std::system_error`；`Read/Write` 运行时错误返回码，
  经 `ErrorCount()` 监控；创建/销毁/打开/读写错误均按日志规范记录。
- 非阻塞 fd + `poll()` 单调时钟控制读写超时，每条物理链路独占一个实例。

### 4.15 CommunicationTransport（drone::communication，物理传输边界）

- `ICommunicationTransport` 统一 `Open/Close/Read/Write/Flush`；
- `SerialTransport` 用于香橙派 `/dev/ttyS1`，`UdpTransport` 用于 PX4 SITL；
- `Px4Link` 的 MAVLink/Topic/状态逻辑不依赖具体传输；地面站后续可复用该边界。

### 4.16 MavlinkHandler（drone::communication，协议基础支撑）

- 每条 MAVLink 物理链路独占一个实例，负责增量字节流解析和完整帧序列化。
- 接收同时兼容 MAVLink 1/2，支持半包、粘包、CRC/签名错误拒绝和坏帧后恢复。
- 发送使用实例私有 `mavlink_status_t` 维护序号，禁止 PX4/地面站链路共享全局 channel 状态。
- 不解释 PX4/地面站业务字段；具体消息转换由对应 Link 完成。
- 实现与测试说明见 `include/communication/mavlink_handler.md`。
