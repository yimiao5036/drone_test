# 电源与失效保护设计

## 1. 设计原则

动力飞行安全不能依赖单一计算机。香橙派负责正常任务和正常返航，PX4保留底层飞控与算力板失效后的最后保护，遥控器保留人工接管能力。

## 2. 当前供电方案

当前硬件方案已确认：

- 无人机使用一套动力电池；
- PX4、动力系统和香橙派RK3588均由该动力电池系统供电；
- 香橙派输入要求为5V/4A，由机上稳压供电模块从动力电池转换；
- 不再使用原华为算力板所需的12V独立供电方案；
- 不设置算力板独立电池、独立BMS或`ICompanionPowerMonitor`；
- 软件中的电量、电流、剩余量和电池有效性统一读取PX4 MAVLink遥测。

供电共用不表示可以忽略稳压和瞬态问题。5V供电模块仍需覆盖RK3588、NPU、双目摄像头、网络和存储峰值负载，并验证起飞电压波动下不会导致香橙派重启。

## 3. 电池数据来源

唯一软件电池来源：

```text
动力电池
→ PX4电源模块/ADC
→ SYS_STATUS / BATTERY_STATUS
→ Px4Link::FlightStateSnapshot
→ 状态机 / HealthManager / GroundStationLink
→ Web地面站
```

使用字段包括：

- `battery_valid`与总电压；
- `battery_current_valid`与电流；
- `battery_remaining_valid`与剩余百分比；
- 对应消息接收时间和新鲜度。

不得把无效电池字段伪造为0，也不得在PX4电池数据超时后继续按旧电量进行任务决策。

## 4. 上电和起飞检查

自动起飞（65014 分配，S2 预检）起飞前至少检查：

- PX4动力电池参数可判定：`BAT_LOW_THR` 有效且换算后的百分比
  `0 < BAT_LOW_THR < 100`（PX4 1.17 参数为 norm，机载读取时×100，默认
  0.15→15.0），`COM_LOW_BAT_ACT == 0`（Warning Only），否则回
  `battery_config_unknown`；
- 电池遥测有效（`battery_valid && battery_remaining_valid`，百分比为有限值），
  否则回 `battery_telemetry_invalid`；
- `battery_remaining_pct > BAT_LOW_THR`，否则回 `battery_low` 且
  availability=unavailable。**机载不设本地百分比阈值，不估算剩余飞行时间**；
  `interception.min_battery_percent` 保持 **0（不启用）**，不用于自动起飞；
- PX4 GPS/位置、姿态、航向和Home有效；
- 香橙派与PX4串口稳定；
- 双目摄像头、解码、YOLO及任务所需感知能力正常；
- 香橙派未发生欠压、重启或系统级异常。

任一飞行安全必需能力失败时，不得由香橙派请求解锁。

生产装配 `enable_control=false` 时命令接口不注入，65014 在任何电池检查之前即回
`rejected/control_disabled`；电池守卫只在显式启用控制的 SITL/台架/现场本地副本
中实际运行。`enable_control` 与 `interception.enabled` 的生产配置仍须保持 false。

## 5. 正常返航与后备RTL

### 5.1 正常返航

- V1 拦截结束后默认返回（S11 只记录，不判命中）；
- 香橙派使用 PX4 上报的 Home 点，不自行记录独立 GPS；Home 局部 NED 由 Home
  经纬度 + EKF 锚点（#49）换算，不依赖 `HOME_POSITION.x/y/z`；
- S12 以位置设定值返航：相对 Home <5m 先原地爬升至 5m，≥5m 保持当前高度；
  到达判据为水平 ≤2m、垂直 ≤0.5m、水平速度 ≤0.5m/s 持续 1s；
- 到达后 S13 发 AUTO.LAND，落地后 S14 发 DISARM；正常返航**不使用 PX4 自动 RTL**；
  PX4 离开 Offboard（failsafe/人工）时状态机立即停发、只监控不争控；
- Home/锚点无效或返航超 60s：原地悬停并告警，不盲目返航；
- 双目视觉和光流继续运行；
- 当前避障策略只允许减速、刹停和悬停，不自动绕行（S8 休眠）。

### 5.2 后备RTL

以下情况由PX4执行最终保护：

- 香橙派死机、重启或断电；
- 5V稳压供电异常导致算力板掉电；
- 控制进程崩溃或卡死；
- 香橙派与PX4串口中断；
- Offboard设定值停止或失效。

PX4 1.17.0 SITL已实测：`COM_OF_LOSS_T=1.0s`、`COM_OBL_RC_ACT=0`；仅停止setpoint、保持HEARTBEAT时，应用约1270ms后观测到模式从Offboard 6/0切换到AUTO/RTL 4/5。真实Pixhawk仍需在拆桨台架复核参数、触发时间和实际动作。

### 5.3 低电与电池遥测失效（Task 8）

- 门禁与阈值唯一来源是 PX4 `BAT_LOW_THR`（低电百分比）与
  `COM_LOW_BAT_ACT`（低电动作），经 `PARAM_REQUEST_READ`/`PARAM_VALUE` 读取，
  启动与重连后重试；读取失败或值非法 → `battery_config_unknown`；
  `BAT_CRIT_THR`/`BAT_EMERGEN_THR` 仍由 PX4 最后保护；
- 地面 READY 低电/遥测失效：availability=unavailable，65014 回 rejected
  `battery_low`/`battery_telemetry_invalid`；电量恢复且未执行空中任务后自然
  回 ready（不锁存 terminal）；
- 飞行中（S3/S4、S5~S10）：遥测失效 → **立即**中止；`pct <= BAT_LOW_THR`
  连续 `takeoff.battery_low_debounce` → 中止；S3/S4 已离地或 S5~S10 →
  **S12 机载位置设定值返航**，65015 aborted（reason 同上），**不使用 PX4
  自动 RTL、不空中 disarm、不触发新的拦截/发射**；
- 空中触发过低电/遥测失效的任务视为已执行，落地后 terminal，本次上电不再
  分配；不新增自动恢复；
- PX4 低电动作导致离开 Offboard 时，状态机立即停发、让权并只监控。

## 6. 控制权和遥控器

```text
PX4内部安全保护
  > 遥控器人工接管
  > 香橙派安全控制
  > 香橙派正常任务控制
  > 地面站任务指令
```

- 遥控器用于测试、故障处置和人工接管；
- **机载不读取 RC、不要求 RC 在线、不要求每机配遥控器**；调度器/65013 的
  availability 不包含 RC 状态；
- RC 人工接管导致 PX4 离开 Offboard 时，机载停发设定值让权、只监控；
- 人工控制期间仍可记录和回传健康状态；
- 恢复自动控制必须经过明确操作，并重新检查模式、位置、Home、目标、双目深度和电池状态。

## 7. 失效矩阵

| 故障 | 香橙派还能工作 | 当前处置 |
|------|----------------|----------|
| 地面站目标过期 | 是 | 停止使用旧目标；按任务阶段搜索、悬停或返回 |
| 地面站链路断开 | 是 | 上报告警；按配置保持、继续安全动作或返回 |
| 双目摄像头/图像失效 | 是 | 禁止视觉接管和深度测距；跟踪阶段退出正常视觉控制 |
| 双目深度无效 | 是 | 禁止依赖绝对距离，降低速度并保守处置 |
| PX4动力电池低（`pct <= BAT_LOW_THR`） | 是 | 地面：阻止新任务（unavailable）；飞行中持续防抖后中止，S12 机载位置返航，65015 aborted `battery_low` |
| PX4电池参数读取失败/非法 | 是 | 回 `battery_config_unknown`，地面 unavailable，不自动起飞 |
| PX4电池数据失效/超时 | 是 | 电量按未知处理；地面拒绝分配，飞行中**立即**中止 → S12，65015 aborted `battery_telemetry_invalid`，禁止依赖旧值 |
| PX4串口中断 | 部分 | 香橙派无法控制；PX4执行自身保护 |
| 5V稳压输出异常 | 可能否 | 香橙派可能重启/断电，PX4执行自身保护 |
| 控制进程卡死 | 否 | PX4根据设定值丢失执行自身保护 |
| 香橙派断电/重启 | 否 | PX4执行自身保护，香橙派重启后不得恢复旧控制状态 |
| 遥控器接管 | 是 | 进入人工控制，停止正常任务输出 |
| 返航遇障碍 | 是 | 刹停悬停，等待人工处置或危险解除 |

## 8. 香橙派重启规则

香橙派启动时一律进入`BOOT/SELF_CHECK`，即使检测到无人机已经在空中，也不得根据本地持久化状态直接恢复之前的速度或位置控制。

空中重启后的允许行为需要单独设计。V1应以读取PX4当前状态、保持不冲突和请求人工处置为原则，不能自动重新解锁或重复执行拦截动作。

## 9. 看门狗与运行监控

后续实现应包含：

- 控制循环心跳和最大延迟；
- PX4设定值发送连续性；
- 线程存活、队列积压和内存池耗尽；
- 系统温度、整机CPU负载、NPU状态和推理延迟；
- Linux欠压/重启原因与系统日志诊断；
- 硬件或系统级看门狗可行性；
- 最后任务状态持久化仅用于诊断，不用于自动恢复控制。

## 10. 电源硬件验证

虽然软件不设置独立电源管理模块，仍必须完成以下台架验证：

1. 测量动力电池最高/最低电压下5V稳压模块输出；
2. 验证5V/4A持续能力和瞬态余量；
3. 视频解码、YOLO、编码推流和双目深度同时运行时测量峰值电流；
4. 起飞、电机快速变速和低电量场景观察香橙派是否欠压或重启；
5. 拔断香橙派供电，确认PX4后备保护不依赖香橙派继续工作；
6. PX4电池消息失效/超时测试必须触发未知或降级，不能保留旧电量。

## 11. 待定项

- 地面站断联后的最终任务策略。
