# 电源与失效保护设计

## 1. 设计原则

动力飞行安全不能依赖单一计算机。算力板负责正常任务和正常返航，PX4 保留底层飞控与算力板失效后的最后保护，遥控器保留人工接管能力。

## 2. 两套供电

### 动力电池

- 为无人机动力系统和飞控相关设备供电。
- 起飞时电压可能出现明显波动。
- 由 PX4 测量并通过 MAVLink向算力板提供电压、电流、剩余量和告警状态。
- 用于判断起飞条件、任务余量、拦截后是否继续以及返航安全余量。

### 算力板独立电池

- 独立为香橙派及其计算负载供电，避免动力电池压降导致算力板重启。
- 负载预算需要覆盖 RK3588、硬件解码、NPU/CPU 推理、摄像头接口和相关外设的峰值功耗。
- 电压、电流、容量和健康监测硬件尚未设计。
- 软件预留 `ICompanionPowerMonitor`，硬件未安装时明确上报“不支持”，不得假定电量充足。

两套电池状态不能互相替代。动力电池决定飞行能力，算力板电池决定任务计算和正常返航控制能否持续。

## 3. 上电和起飞检查

起飞前至少检查：

- PX4 动力电池状态满足配置要求。
- 算力板电池监测能力可用；硬件未完成期间采用明确的测试限制和人工确认流程。
- PX4 GPS/位置、姿态、航向和 Home 有效。
- 遥控器链路和接管开关状态符合起飞条件。
- 算力板与 PX4 串口稳定。
- 摄像头、雷达和任务所需感知能力正常。

任一必需能力失败时不得由算力板请求解锁。

## 4. 正常返航与后备 RTL

### 正常返航

- V1 拦截结束后默认返回。
- 算力板使用 PX4 上报的 Home 点，不自行记录独立 GPS。
- 算力板持续生成位置或速度设定值，控制无人机返回 Home。
- 摄像头、光流和单点雷达继续运行。
- V1 发现障碍物后刹停悬停，不自动绕行，等待遥控器或地面站处置。

### 后备 RTL

如果出现以下故障，算力板无法继续发送正常返航指令：

- 算力板死机、重启或断电。
- 控制进程崩溃或卡死。
- 算力板与 PX4 串口中断。
- Offboard 设定值停止或失效。

此时由 PX4 检测 Offboard 控制丢失并执行配置的后备保护。首选动作可配置为 RTL；在定位无效等情况下可能需要悬停或降落。这里的 PX4 RTL 不是正常任务返航方式，而是算力板已经无法工作的最后保障。

PX4 1.17.0 的具体参数名称、触发时间和动作必须查阅对应版本资料并实测后写入配置清单。

## 5. 控制权和遥控器

```text
PX4 内部安全保护
  > 遥控器人工接管
  > 算力板安全控制
  > 算力板正常任务控制
  > 地面站任务指令
```

- 遥控器用于测试、故障处置和人工接管。
- 接管触发后，算力板停止正常任务输出，避免控制冲突。
- 人工控制期间仍可记录和回传健康状态，但不得自动夺回控制权。
- 恢复自动控制必须经过明确操作，并重新检查模式、位置、Home、目标和障碍物状态。
- PX4 和遥控器的具体接管开关、模式以及失联动作尚待确认。

## 6. 失效矩阵

| 故障 | 算力板还能工作 | V1 处置 |
|------|----------------|---------|
| 地面站目标过期 | 是 | 停止使用旧目标；按任务阶段搜索、悬停或返回 |
| 地面站链路断开 | 是 | 上报告警；按配置保持、继续已有安全动作或返回 |
| 摄像头失效 | 是 | 禁止视觉接管；跟踪阶段退出正常视觉控制 |
| 雷达失效 | 是 | 禁止依赖前向绝对距离，降低速度并保守处置 |
| 算力板电池低 | 是 | 停止新任务并尽早执行正常返航 |
| 动力电池低 | 是 | 取消继续拦截并执行正常返航或安全降落 |
| PX4 串口中断 | 部分 | 算力板无法控制；PX4 执行自身保护 |
| 控制进程卡死 | 否 | PX4 根据设定值丢失执行自身保护 |
| 算力板断电/重启 | 否 | PX4 执行自身保护，算力板重启后不得恢复旧控制状态 |
| 遥控器接管 | 是 | 进入人工控制，停止正常任务输出 |
| 返航遇障碍 | 是 | 刹停悬停，等待人工处置或危险解除 |

## 7. 算力板重启规则

算力板启动时一律进入 `BOOT/SELF_CHECK`，即使检测到无人机已经在空中，也不得根据本地持久化状态直接恢复之前的速度或位置控制。

空中重启后的允许行为需要单独设计。V1 应以读取 PX4 当前状态、保持不冲突和请求人工处置为原则，不能自动重新解锁或重复执行拦截动作。

## 8. 看门狗与运行监控

后续实现应包含：

- 控制循环心跳和最大延迟监测。
- PX4 设定值发送连续性监测。
- 线程存活、队列积压和内存池耗尽监测。
- 温度、CPU/NPU负载和推理延迟监测。
- 算力板硬件或系统级看门狗可行性评估。
- 重启原因和最后任务状态持久化，仅用于诊断，不用于自动恢复控制。

## 9. 电源监测硬件接口要求

算力板电池硬件确定后，适配器至少应输出：

- 电压、电流和功率。
- 剩余容量或荷电状态。
- 温度和健康状态（硬件支持时）。
- 低电、临界电量和通信故障标志。
- 测量时间和数据质量。

监测器必须与具体电量计、BMS 或 UPS 板隔离，使硬件替换不影响状态机。

## 10. 验证顺序

1. PX4 1.17.0 SITL 验证 Offboard 进入、设定值中断、返航和遥控器接管。
2. Pixhawk 台架验证串口断开、进程终止和算力板重启。
3. 电源台架测量 RK3588 推理峰值功耗、独立电池压降和续航。
4. 无桨或安全约束条件下验证 armed、模式和 Home 判定。
5. 低速、空旷、受控环境验证正常返航和前向刹停。
6. 在确认 PX4 后备动作可靠前，不进入依赖算力板自动控制的真实任务测试。

## 11. 待定项

- 两套电池的起飞、返航和临界阈值。
- 遥控器接管开关、恢复流程和失联动作。
- PX4 1.17.0 Offboard 丢失、数据链丢失和 RTL 参数清单。
- Home 高度基准、返航高度和降落策略。
- 地面站断联后的最终任务策略。
