### RTSP 接收与解码迁入 video（实施顺序第 3 步）

- **CameraReceiver**（实现 ICameraReceiver）：FFmpeg avformat RTSP 拉流（TCP/UDP），
  逐访问单元读取 H.264/H.265 码流发布 Topic<EncodedFrame>；断流自动重连
  （重连间隔可配置）；中断回调保证确定性停机；连接成功后单独发布流级参数集消息
  （SPS/PPS，RTSP 从 SDP/容器头提取）。
- **VideoDecoder**（实现 IVideoDecoder）：订阅码流，解码为 **NV12** 帧并从
  VideoFramePool 分配 FrameHandle 发布（零拷贝共享、最后引用归还内存池）；
  解码器优先 rkmpp 硬解（香橙派，DRM 硬件路径），不可用时回退 FFmpeg 软解
  （开发机验证路径）；参数集就绪前跳过非关键帧（等关键帧同步），队列丢帧不破坏链路；
  池满丢帧不阻塞（WARN 节流）。
- **消息类型扩展** EncodedFrame：新增 codec（VideoCodec 枚举）与
  parameter_sets（流级参数集）字段。
- **依赖**：FFmpeg dev 包（avformat/avcodec/avutil/swscale），开发机 Ubuntu 24.04
  已安装；香橙派需 ffmpeg-rockchip。
- **测试** tests/video/video_decoder_test.cpp：libx264 软编 → VideoDecoder 软解
  全链路，验证 NV12 输出/分辨率/缓冲可写/确定性停机；**42/42 测试通过、0 警告**。
- 说明：RTSP 接收端（CameraReceiver）依赖真实 RTSP 源，自动化集成测试留待
  香橙派实机验证；开发机以解码器软解测试覆盖核心链路。

### YOLO 迁入 perception（实施顺序第 4 步）

- **YoloDetector**（实现 IYoloDetector，替换 Stub 为真实实现；Stub 保留供冒烟测试）：
  独立消费线程订阅解码帧（NV12），逐帧调用推理后端，将检测结果转换为
  `common::DetectionResult` 发布（每目标一条，同帧共享 frame_sequence 与
  inference_time_ms；无检测不发布）。Start/Stop 幂等，停止后可重启（自动重新订阅）；
  后端加载失败防刷屏（load_failed 标志）。
- **IDetectionBackend 后端抽象**：依赖注入解耦推理后端（测试注入 Mock，香橙派注入
  RKNN 后端），`CreateDefaultDetectionBackend` 工厂按编译配置创建；无后端时
  Start 返回 false 并打 ERROR，不静默空转。
- **yolo_postprocess 后处理纯函数模块**：移植原型 common.cpp 的量化解码（含
  score_sum 快速过滤、DFL 分支）、按类 NMS、letterbox 逆变换，参数化类别数/
  分支结构，零硬件依赖、开发机可单测。
- **RknnDetectionBackend**（DRONE_HAVE_RKNN=ON 条件编译，仅香橙派）：整合原型
  rknn_model/rga_utils/yolo26_detector——RGA 预处理（NV12 居中裁剪 16 对齐正方形
  → NV12→RGB letterbox 写入模型输入内存，不引入 OpenCV）、3 核上下文
  （rknn_dup_context + NPU_CORE_ALL）、输入输出零拷贝内存、NC1HWC2→NCHW 转换、
  后处理 + 裁剪偏移还原原图坐标。模型类别数/输入尺寸/分支结构从张量属性动态解析。
- **RKNN 头文件入库**：third_party/rknn/include（rknn_api.h 等 3 个），CMake
  选项 DRONE_HAVE_RKNN / DRONE_RKNN_API_DIR / DRONE_RGA_DIR 控制。
- **测试**：yolo_postprocess_test（8 用例：解码/过滤/NMS/letterbox 逆变换）+
  yolo_detector_test（9 用例：Mock 后端验证线程/发布/统计/错误处理/重启）；

### 视频叠加、编码、RTSP 输出（实施顺序第 5 步）（2026-08-13）

- **FrameCompositor**（`include/video/frame_compositor.h`，新建）：订阅解码帧
  （NV12）与检测结果，叠加检测框 + 类型/置信度文字，产出 `kAnnotatedFrame`。
  - 输出用**独立内存池**拷贝后再叠加，避免就地改共享解码帧被 YOLO/RGA 并发读脏（防竞态）；
  - 零外部依赖：NV12 描框 + 内置 5×7 点阵 ASCII 字模渲染类型/置信度（如 `UAV 85%`），
    不引 OpenCV/FreeType；
  - 异步帧-检测对齐（取帧时应用此前最新检测）；Start/Stop 幂等、重启可恢复。
- **VideoSender 真实实现**（替换 `IVideoSender` 的 Stub，签名不变）：订阅
  `kAnnotatedFrame`，编码并 RTSP 推流给图传；拥塞只丢图传帧、不反压上游。
- **IVideoEncoderBackend 编码后端抽象**（`include/video_transmission/video_encoder.h`）：

### 根 main.cpp 视频链路装配（第 7 步子集，超前测试用）（2026-08-13）

- **main.cpp 视频链路装配版**：把已完成的第 3/4/5 步部件接成一条可出图链路：
  CameraReceiver(RTSP拉流) → VideoDecoder(解码) → YoloDetector(识别) →
  FrameCompositor(叠加) → VideoSender(编码RTSP推流)。
- **路径解析**：按 docs/部署与打包.md 约定用 `/proc/self/exe` 定位程序目录，config 与
  模型路径相对解析（候选链：程序目录旁 → 当前目录）；日志目录同理。
- **配置**：config/config.json 新增 `video` 配置节（input_rtsp / output_rtsp / width /
  height / fps / bitrate），yolo 配置节由 main 读取并拼接模型路径。
- **停机**：Ctrl+C / SIGTERM 置位停止标志 → 按依赖逆序 Stop（camera→decoder→compositor→
  sender），并验证了各部件析构顺序；单个部件失败（RTSP 不可达、无 RKNN 后端）仅记 ERROR
  不崩，便于现场排查。
- **测试**：开发机启动验证通过——各部件按序启动、RTSP 推流不可达/YOLO 无 RKNN 后端均按
  预期记录 ERROR 并继续、SIGTERM 完整逆序停机；原有 73/73 测试仍通过。
- 说明：build 目录直接运行时模型路径解析到 build/models（`/proc/self/exe` 指向 build），
  需在待测试的部署目录中正确摆放模型与配置（见 部署与打包.md）；RKNN/RGA/rkmpp 硬编硬解
  链路待香橙派实机验证。
- **2026-08-24 实机修复**：修正根 `main.cpp` 的视频 Topic 装配。此前下游错误订阅了
  无生产者的全局临时 Topic，导致解码器虽持续出帧，`FrameCompositor` 与 `VideoSender`
  收不到数据，MediaMTX 仅完成 H.264 轨道发布握手后因无 RTP 数据超时。现改为直接连接
  `decoder->FrameOutput()` → YOLO/叠加、`detector->DetectionOutput()` → 叠加、
  `compositor->AnnotatedOutput()` → 图传，并删除无用全局 Topic。

## 三、关键技术决策

- 视频帧用 `Topic` 发布**内存池 RAII 句柄**而非像素数据，多订阅者零拷贝共享；底层缓冲最后引用释放时归还内存池。
- 解码输出直接走 RGA 写入 RKNN 预分配输入内存（BGR→RGB + letterbox 一次完成），避免 CPU 色彩转换。
- 原型为单线程串行（解码→推理→编码），正式工程必须拆独立线程 + Topic 解耦才能逼近 25fps。
