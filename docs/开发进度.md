### RTSP 接收与解码迁入 video（实施顺序第 3 步）

- **CameraReceiver**（实现 ICameraReceiver）：FFmpeg avformat RTSP 拉流（TCP/UDP），
  逐访问单元读取 H.264/H.265 码流发布 Topic<EncodedFrame>；断流自动重连
  （重连间隔可配置）；中断回调保证确定性停机；连接成功后单独发布流级参数集消息
  （SPS/PPS，RTSP 从 SDP/容器头提取）。
- **VideoDecoder**（实现 IVideoDecoder）：订阅码流，解码为 **NV12** 帧并从
  VideoFramePool 分配 FrameHandle 发布（零拷贝共享、最后引用归还内存池）；
  解码器优先 rkmpp 硬解（香橙派，DRM 硬件路径），不可用时回退 FFmpeg 软解
  （开发机验证路径）；参数集就绪前跳过非关键帧（等关键帧同步），队列丢帧不破坏链路；
  池满丢帧不阻塞（WARN 节流）。
- **消息类型扩展** EncodedFrame：新增 codec（VideoCodec 枚举）与
  parameter_sets（流级参数集）字段。
- **依赖**：FFmpeg dev 包（avformat/avcodec/avutil/swscale），开发机 Ubuntu 24.04
  已安装；香橙派需 ffmpeg-rockchip。
- **测试** tests/video/video_decoder_test.cpp：libx264 软编 → VideoDecoder 软解
  全链路，验证 NV12 输出/分辨率/缓冲可写/确定性停机；**42/42 测试通过、0 警告**。
- 说明：RTSP 接收端（CameraReceiver）依赖真实 RTSP 源，自动化集成测试留待
  香橙派实机验证；开发机以解码器软解测试覆盖核心链路。

## 三、关键技术决策

- 视频帧用 `Topic` 发布**内存池 RAII 句柄**而非像素数据，多订阅者零拷贝共享；底层缓冲最后引用释放时归还内存池。
- 解码输出直接走 RGA 写入 RKNN 预分配输入内存（BGR→RGB + letterbox 一次完成），避免 CPU 色彩转换。
- 原型为单线程串行（解码→推理→编码），正式工程必须拆独立线程 + Topic 解耦才能逼近 25fps。
