# 多机任务分配与自动起飞设计

> 日期：2026-10-22
>
> 状态：设计已确认，待实现
>
> 范围：多机身份寻址、65014/65015 任务分配协议、65013 状态扩展、机载任务分配助手、S2→S3→S4→S5 自动起飞、`FlightController` 预授权 bootstrap 流、低电返航触发。
>
> 不在本规格：Web/Node 调度器与界面、目标类型自动分类、多发弹仓/命中判定、多机编队与同时多目标协同、PX4 路径规划。
>
> 安全基线：`runtime.enable_control=false`、`interception.enabled=false` 保持不变；本规格实现后也不得单独打开生产控制。

## 0. 背景

当前系统已经具备：

- PX4 MAVLink 遥测、模式/解锁/执行器命令、ACK 与串口重连；
- 地面站 `65010/65011` 目标 UPDATE/ACK、`65012/65013` 健康与任务状态；
- 多机身份二元组与定向寻址：`(aircraft_system_id, aircraft_component_id)`；
- 单机 S5~S14 控制链与算力板位置返航（S12 不使用 PX4 自动 RTL）；
- 捕网执行器 ACK 保持/复位时序。

缺少的是：

1. **任务分配**：65010 只是目标位置流，不是“这架飞机执行这个任务”的授权；
2. **空闲机选择**：地面站还没有按拦截类型选机、按可用状态调度的协议；
3. **自动起飞**：状态机只有 S3/S4 名称，没有解锁、Offboard、爬升编排；
4. **预授权控制流**：PX4 进入 Offboard 前需要已有 setpoint 流，当前生产路径没有合法的 bootstrap 流；
5. **低电主动返航**：当前 S12 只在拦截结束/授权超时触发，低电没有机载触发点。

## 1. 目标与非目标

### 1.1 目标

- 飞机按 `(system_id, component_id)` 区分，禁止广播分配；
- 地面站按拦截类型选择同类飞机，再由调度器选择空闲机；
- 分配消息只携带 `assignment_id + target_id + 拦截类型 + 授权`，目标位置继续走 65010；
- 飞机在 S2 READY 接受分配后，自动完成 Offboard 建立、解锁、原地爬升到任务高度；
- 起飞点水平坐标保持当前点，只改变高度；
- 任务只接受分配指定的 `target_id`；
- 一次上电最多执行一次空中任务，S14/S16 后不再分配；
- 失败不重试，明确中止并回报原因；
- 低电或电池遥测失效时由机载主动 S12 返航，不依赖 PX4 盲目 RTL；
- 全程不要求机载读取 RC 状态，不要求每架飞机配置遥控器。

### 1.2 非目标

- Web/Node 调度器、选机算法、状态显示界面（另立规格）；
- 目标类型自动分类；本规格由操作员选择拦截类型；
- 多发弹仓、装填、命中/脱靶判定、再交战；
- 多机编队、去冲突、同时多目标协同；
- PX4 RTL 路径规划、避障绕行；
- 每机 RC 管理、RC 在线门禁；
- 25/26 之外的拦截类型；
- 生产配置打开 `enable_control`。

## 2. 已确认决策

| 决策 | 结论 |
|---|---|
| 本次范围 | 协议 + 机载；Web/Node 调度器另立规格 |
| 调度策略 | 操作员选拦截类型 → 调度器自动选同类空闲机 |
| 空闲定义 | 仅未执行任务的 S2 READY；一次上电一次空中任务 |
| 分配内容 | 只带 `target_id + assignment_id + 授权`，位置仍走 65010 |
| 起飞基准 | 保持当前起飞点 `x/y`，只上升高度 |
| bootstrap 流 | `FlightController` 新增 `kBootstrap` 预授权态 |
| 失败策略 | 不自动重试，中止分配并回报 |
| 分配归属 | 状态机 + 小型 `MissionAssignment` 纯逻辑助手 |
| RC | 仅测试保险，由 PX4 管理；机载不读取、不作为门禁 |
| 电池 | 不估时间、不设本地百分比；读取 PX4 `BAT_LOW_THR`，机载主动 S12 |
| 寻址 | 所有任务/目标/命令必须双字段定向，禁止广播 |

## 3. 总体架构

```text
地面站 255/190
   │  65014 MISSION_ASSIGN（定向 N/25 或 N/26）
   ▼
GroundStationLink ──► Topic<MissionAssignment> ──► MissionStateMachine
   ▲                                                   │
   │  65015 MISSION_ASSIGN_ACK                         │  MissionAssignment 助手
   └───────────────────────────────────────────────────┤
   ▲                                                   │
   │  65013 MISSION_STATUS（assignment/availability）   │
   └───────────────────────────────────────────────────┤
                                                       ▼
                                         ControlIntent（kTakeoff / kPositionGuide）
                                                       │
                                                       ▼
                                             FlightController
                                                       │
                                      kBootstrap 原点保持流 / kActive 控制
                                                       ▼
                                                   Px4Link
                                                       │
                                      176 Offboard / 400 ARM / setpoint
                                                       ▼
                                                     PX4
```

目标位置链保持独立：

```text
地面站 65010 目标 UPDATE
  → GroundStationLink 地址校验
  → Topic<GroundStationTarget>
  → MissionStateMachine 按 assignment.target_id 过滤
  → TargetEstimator / S5 位置引导
```

## 4. 身份与寻址

身份二元组：

```text
aircraft_system_id   = 同类飞机编号（1..254）
aircraft_component_id = 功能类别（25=捕网，26=火箭）
```

- 捕网类：`N/25`；火箭类：`N/26`；
- 地面站来源固定 `255/190`；
- 65014 的 `V2_EXTENSION.target_system/target_component` 与 payload 尾部地址字段必须同时匹配本机；
- 65015 以本机身份为 source，目标固定 `255/190`；
- 65010/65011 继续按现有地址规则；
- 地址不匹配：**直接忽略，不回 65015**；禁止“收到广播就起飞”。

## 5. 协议

三类消息均通过 MAVLink2 `V2_EXTENSION` 承载，短帧 `mavlink_payload_len=60`，协议有效数据 55 字节；偏移相对 `v2_extension.payload[0]`；`offset 54 = 1` 为短帧长度标记。

### 5.1 65014 MISSION_ASSIGN

方向：地面站 → 指定飞机。

| offset | size | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | `protocol_version` | 固定 1 |
| 1 | 4 | `assignment_id` | 地面站生成的分配编号，小端 |
| 5 | 4 | `target_id` | 指定目标编号，小端；0 非法 |
| 9 | 1 | `interceptor_type` | 25=捕网，26=火箭；必须等于本机 component |
| 10 | 1 | `flags` | bit0=授权自动起飞；bit1=取消当前分配 |
| 11 | 4 | `valid_for_ms` | 分配有效期，小端；只约束起飞开始，不约束空中任务时长 |
| 15~49 | 35 | `reserved` | 0 |
| 50 | 1 | `target_system` | 必须与本机 system_id 一致 |
| 51 | 1 | `target_component` | 必须与本机 component_id 一致 |
| 52~53 | 2 | `reserved` | 0 |
| 54 | 1 | `frame_length_marker` | 固定 1 |

规则：

- `flags` 只允许 bit0/bit1；未知位拒绝；
- `flags.bit0=0` 时拒绝起飞请求；
- `flags.bit1=1` 表示取消 `assignment_id` 对应的当前分配；
- 同一 `assignment_id` 重发必须幂等：已接受则重发 65015 accepted，不重复起飞；已 terminal 则回 rejected；
- 目标位置不在 65014 中携带，继续由 65010 提供。

### 5.2 65015 MISSION_ASSIGN_ACK

方向：飞机 → 地面站 255/190。65014 的应用层回执，不依赖 MAVLink `COMMAND_ACK`。

| offset | size | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | `protocol_version` | 固定 1 |
| 1 | 4 | `assignment_id` | 回显 |
| 5 | 4 | `target_id` | 回显 |
| 9 | 1 | `result` | 0=accepted，1=rejected，2=cancelled/aborted |
| 10 | 1 | `reason` | 原因码，见 5.4 |
| 11 | 1 | `mission_state` | 发送时 MissionState 枚举值 |
| 12 | 1 | `availability` | 发送时可用状态 |
| 13~25 | 13 | `reserved` | 0 |
| 26 | 1 | `aircraft_system_id` | 本机 system_id |
| 27 | 1 | `aircraft_component_id` | 本机 component_id |
| 28~53 | 26 | `reserved` | 0 |
| 54 | 1 | `frame_length_marker` | 固定 1 |

发送时机：

- 接受分配、拒绝分配、取消、飞行中中止时各发送一次；
- 同一 `assignment_id` 的重复请求可重发同一结果；
- 不要求地面站 ACK 65015。

### 5.3 65013 MISSION_STATUS 扩展

65013 的 `protocol_version` 从 1 升为 2；65012 保持版本 1（实现时拆分现有共享常量）。旧字段偏移不变，新字段复用原保留区：

| offset | size | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 1 | `protocol_version` | 65013 固定 2 |
| 40 | 4 | `assignment_id` | 当前分配编号；无分配为 0 |
| 44 | 4 | `target_id` | 当前目标编号；无分配为 0 |
| 48 | 1 | `availability` | 见 5.4 |
| 49 | 1 | `interceptor_type` | 25/26；未知为 0 |
| 50~53 | 4 | `reserved` | 0 |
| 54 | 1 | `frame_length_marker` | 固定 1 |

65013 原有字段（offset 0~39）不变；地面站解析器必须兼容版本 1 的旧帧，版本 2 才读取扩展字段。

### 5.4 结果、原因与可用状态

`availability`：

| 值 | 含义 | 可被调度 |
|---:|---|---|
| 0 | unavailable：未就绪/故障/状态不确定 | 否 |
| 1 | ready：S2，未执行任务，可分配 | 是 |
| 2 | assigned：已接受分配，S3/S4 | 否 |
| 3 | engaged：S5~S10 任务中 | 否 |
| 4 | returning：S11~S13 返航/降落 | 否 |
| 5 | terminal：S14/S16 或空中任务已结束 | 否 |

`reason` 建议值：

| 值 | 原因 |
|---:|---|
| 0 | none |
| 1 | invalid_message |
| 2 | unsupported_version |
| 3 | unsupported_interceptor_type |
| 4 | not_ready |
| 5 | already_assigned |
| 6 | preflight_failed |
| 7 | control_disabled（无控制装配） |
| 8 | mode_timeout |
| 9 | arm_timeout |
| 10 | bootstrap_timeout |
| 11 | takeoff_timeout |
| 12 | cancelled_by_gcs |
| 13 | target_wait_timeout |
| 14 | target_lost |
| 15 | battery_low |
| 16 | battery_telemetry_invalid |
| 17 | battery_config_unknown |
| 18 | px4_disconnected |
| 19 | mission_fault |
| 20 | internal_error |

### 5.5 校验

- 65014 来源必须是地面站 `255/190`；
- `target_system/target_component`（帧头与 payload）必须同时匹配本机；
- 不匹配：忽略，不回 65015；
- 版本不支持、字段非法、拦截类型不匹配、目标为 0：地址匹配时回 65015 rejected；
- 未分配/已 terminal 时收到取消：回 rejected；
- 所有多字节字段小端；
- 任何任务/目标/命令不得广播。

## 6. MissionAssignmentTracker 助手

新建 `MissionAssignmentTracker` 纯逻辑助手，不启动线程、不直接访问 Topic；`common::MissionAssignment` 是分配消息，`MissionAssignmentTracker` 是状态机持有的分配状态：

```cpp
enum class AssignmentPhase : uint8_t {
    kIdle,       // 无活动分配，可接受
    kAssigned,   // 已接受，等待 S3
    kTakingOff,  // S3/S4
    kAirborne,   // 已离地，进入 S5
    kEngaged,    // S5~S10
    kReturning,  // S11~S13
    kTerminal,   // S14/S16 或空中任务结束
};

struct MissionAssignment {
    common::MessageHeader header;
    uint32_t assignment_id = 0;
    uint32_t target_id = 0;
    uint8_t interceptor_type = 0;
    uint8_t flags = 0;
    uint32_t valid_for_ms = 0;
    uint64_t received_ms = 0;
};
```

`MissionAssignmentTracker` 以 `AssignmentPhase` 为内部阶段，提供以下方法：

- `Accept()`：仅 `kIdle` 且预检通过；记录 `assignment_id/target_id`；
- `BeginTakeoff()`：`kAssigned → kTakingOff`；记录原点 `x0/y0/z0`；
- `TakeoffComplete()`：`kTakingOff → kAirborne`；
- `BeginEngage()`：`kAirborne → kEngaged`；
- `BeginReturn()`：`kEngaged → kReturning`；
- `Terminal()`：`kReturning → kTerminal`，或 S16 直接 terminal；
- `AbortOnGround()`：起飞前中止，`→ kIdle`，允许操作员用新 `assignment_id` 重新分配；机载不自动重试；
- `AbortAirborne()`：已离地后的中止，`kTakingOff/kAirborne/kEngaged → kReturning → kTerminal`；实际离地以 PX4 `armed && !landed` 判定，不依赖是否已进入 S5；
- `AllowsTarget(target_id)`：仅活动分配且 `target_id` 匹配；
- `Availability()`：映射到 5.4；
- `RememberResult(assignment_id, result, reason)`：重复 `assignment_id` 只重发 65015，不重新进入 S3；
- 所有时间由调用方显式传入，助手不读系统时钟。

一次上电语义：

- 预检拒绝不消耗任务机会；
- 已接受但未离地的失败可回到 `kIdle`，但必须由地面站发起新分配；
- 一旦观测到 `armed && !landed`（实际离地），本次任务机会消耗，之后即使返回 READY 也不再接受新分配；仅进入 S4 但始终未离地不算执行空中任务；
- S14/S16 后 `kTerminal`，直到重启。

## 7. 状态机集成

### 7.1 新增输入/输出

`IMissionStateMachine` 增加：

```cpp
void SetAssignmentInput(common::Topic<common::MissionAssignment>& assignment);
common::Topic<common::MissionAssignmentAck>& AssignmentAckOutput();
```

- 输入：`MissionAssignment`；
- 输出：`MissionAssignmentAck`（`assignment_id`、`target_id`、`result`、`reason`、`mission_state`、`availability`）；
- `MissionStateMachineConfig` 增加 `takeoff` 配置；
- 构造期对 `takeoff` 做 `Validate()`；
- 未注入命令接口（`command_sender_==nullptr`）或未绑定估计输入时，S2 收到分配必须拒绝，原因 `control_disabled`，不得进入 S3。

### 7.2 S2 READY → S3 预检

全部满足才进入 S3：

| 检查 | 条件 |
|---|---|
| 控制路径 | `command_sender_ != nullptr` 且估计输入已绑定 |
| 分配有效性 | `flags.bit0=1`、`target_id != 0`、`interceptor_type == 本机 component`、未超 `valid_for_ms` |
| 任务机会 | `MissionAssignmentTracker` 为 `kIdle` 或尚未执行空中任务 |
| PX4 连接 | `connected=true` |
| 地面状态 | `landed_state_valid && landed && !armed` |
| 导航 | `local_position_valid && attitude_valid && home_valid` |
| 电池 | 参数读取有效、`COM_LOW_BAT_ACT=0`、`battery_valid && battery_remaining_valid && pct > BAT_LOW_THR` |
| 设备 | 无 MissionStateMachine 故障、无执行器故障 |
| 目标 | `target_id` 合法；65010 目标可在起飞后到达 |

不满足：

- 回 65015 `rejected`，带具体 reason；
- 保持 S2；若当前状态不确定，`availability=unavailable`；
- 不自动重试，不自动起飞。

### 7.3 S3 解锁与 Offboard

进入 S3 时：

1. `MissionAssignmentTracker::BeginTakeoff()`，记录 `x0=local_x_m`、`y0=local_y_m`、`z0=local_z_m`；
2. 状态机每决策拍发布 `kTakeoff` 位置意图：目标 `x0/y0/z0`，`reason_code` 带 bit31 控制权请求位；
3. `FlightController` 进入 `kBootstrap`，发布原点保持位置设定值，建立 Offboard 前置流；
4. 等待 `bootstrap_lead_ms`（默认 300ms），确保控制器已发布若干帧原点保持设定值；
5. 发送 `MAV_CMD_DO_SET_MODE(176)`：`param1=1`（custom mode enable）、`param2=6`、`param3=0`；
6. 等待真实 `flight_mode=6 && flight_sub_mode=0`，超时 `mode_timeout_ms`（默认 2000ms）；
7. 发送 `MAV_CMD_COMPONENT_ARM_DISARM(400)`：`param1=1`；
8. 等待真实 `armed=true`，超时 `arm_timeout_ms`（默认 3000ms）；
9. 成功 → S4；`FlightController` 在 armed+Offboard 后由 `kBootstrap` 转 `kActive`。

约束：

- 176/400 各只发一次；不自动重发；
- 176/400 的 ACK 非 `ACCEPTED` 立即中止；实际模式/armed 状态仍为最终判据；
- `kBootstrap` 的总超时 `bootstrap_timeout_ms`（初值 6000ms）必须大于 `bootstrap_lead + mode_timeout + arm_timeout`，作为控制器侧兜底；
- 失败不重试、不进入 S4、不继续发布控制意图。

失败处置：

| 情况 | 动作 |
|---|---|
| 模式超时/ACK 拒绝 | 65015 aborted `mode_timeout`；停 bootstrap；仍在地面且 armed 则发一次 DISARM；回 S2 或 unavailable |
| 解锁超时/ACK 拒绝 | 65015 aborted `arm_timeout`；同上 |
| bootstrap 超时 | 65015 aborted `bootstrap_timeout`；控制器停流回 IDLE |
| 已离地但流程失败 | 不空中 disarm；转 S12 返航/降落 |
| PX4 状态不确定 | `availability=unavailable`，不分配；等待人工处置 |

### 7.4 S4 起飞到任务高度

- 水平保持 `x0/y0`；
- 目标高度 `z_target = z0 - takeoff.height_m`（NED，向上为负）；
- 每决策拍按 `climb_rate_mps` 递增高度目标，避免阶跃；
- 位置意图继续带 bit31 控制权请求位；
- 航向保持进入 S3 时的当前航向；
- 到达判据同时满足并保持 `stable_time_ms`：
  - `|z - z_target| <= z_tolerance_m`；
  - `sqrt((x-x0)^2 + (y-y0)^2) <= xy_tolerance_m`；
  - `|vz_mps| <= max_vz_mps`；
- 成功 → S5，`MissionAssignmentTracker::TakeoffComplete()`/`BeginEngage()`，availability=engaged；
- 空中超时 `height_timeout_ms`：若 PX4 仍在 Offboard，转 S13 发 AUTO.LAND；若 PX4 已离开 Offboard，停发让权，转 S13 仅监控，不再争控；
- 地面超时 → 停流；若仍 armed 且 landed，发一次 DISARM；回 S2 READY；若状态不确定则 unavailable；
- 失败不重试。

### 7.5 S5 目标与任务

- 仅接受 `target_id == assignment.target_id` 的 65010 目标；
- 其他 `target_id` 直接忽略，不影响本机；
- 起飞后、首个目标到达前，在 `x0/y0` 悬停等待；
- 超过 `target_wait_timeout_ms` 仍无目标 → 中止分配，S12 返航，65015 aborted `target_wait_timeout`；
- 目标到达后走现有 S5 位置引导链；
- 目标失效超过 `target_lost_timeout_ms` → S12 返航，65015 aborted `target_lost`；
- S5 起 availability=engaged；S11 起 returning；S14/S16 terminal；
- 取消分配：
  - 未离地：停流/上锁，回 READY（未执行空中任务）或 unavailable，65015 cancelled；
  - 已离地：S12→S13→S14，65015 cancelled；
  - 不自动重试。

### 7.6 决策拍顺序

在现有顺序上增加：

```text
Evaluate(now_ms):
  1. 更新 assignment / 分配输入
  2. 更新 PX4 快照、电池守卫
  3. 处理取消 / 超期
  4. EvaluateAssignmentEntry()     // S2→S3
  5. EvaluateTakeoffSequence()      // S3 模式/解锁，S4 爬升
  6. 现有目标/交接/视觉/拦截逻辑
  7. 发布 MissionStatus / AssignmentAck
```

- 故障/中止当拍不得继续发布控制意图；
- `MissionAssignmentAck` 在状态迁移的同一拍或下一拍发布，具体由输出队列保证不丢失；
- 日志只打生命周期/状态变化，禁止每拍日志。

## 8. FlightController `kBootstrap`

### 8.1 控制权状态

`ControlAuthority` 增加：

```cpp
enum class ControlAuthority : uint8_t {
    kIdle,
    kBootstrap,
    kActive,
    kCoast,
};
```

语义：

- `kIdle`：无控制权，停发；
- `kBootstrap`：自动起飞预授权态，发布原点保持位置设定值，等待 armed+Offboard；
- `kActive`：正常 Offboard 控制；
- `kCoast`：意图短期超龄刹车/保持；
- `kBootstrap` 失败只回 `kIdle`，不进入 `kCoast`。

### 8.2 进入门禁

从 `kIdle` 进入 `kBootstrap` 必须同时满足：

- 最新意图 `type=kTakeoff`；
- `reason_code` bit31 置位；
- 意图未超龄（`valid_until_ms`）；
- PX4 `connected`；
- `landed_state_valid && landed`；
- `!armed`；
- `local_position_valid`；
- `attitude_valid`；
- `home_valid`；
- 未超过 `bootstrap_timeout`（由 `DroneApplication` 从 `takeoff.bootstrap_timeout_ms` 注入控制器配置）。

**不检查 RC**：机载不读取 RC 在线、RSSI 或接管开关；RC 由 PX4 自己管理。

### 8.3 输出与迁移

`kBootstrap`：

- 发布 `kPosition` 原点保持设定值：`x=起飞原点 x`、`y=起飞原点 y`、`z=起飞原点 z`；
- 航向保持当前航向；
- 不带速度前馈；
- 周期与现有控制器周期一致；
- 设定值必须 `valid=true`，确保 PX4 有持续 Offboard 流。

迁移：

| 当前 | 条件 | 下一状态 | 动作 |
|---|---|---|---|
| kIdle | 进入门禁全满足 | kBootstrap | 开始原点保持流 |
| kBootstrap | `armed && Offboard(6/0)` | kActive | 保持当前设定值，进入正常门禁 |
| kBootstrap | 条件失效/超时/意图撤销 | kIdle | 停流，不进入 COAST |
| kActive | 现有授权链断开 | kIdle/COAST | 沿用现有逻辑 |

说明：

- 进入 Offboard 前必须有 setpoint 流，因此 `kBootstrap` 先于 176/400；
- `kBootstrap` 不发送零速“假流”，而是发送合法的原点位置保持；
- `kBootstrap` 的意图来源只能是状态机 S3，禁止外部直接注入生产路径；
- S3 的状态机超时是权威；控制器 `bootstrap_timeout` 只做防卡死兜底。

## 9. 电池守卫与主动返航

### 9.1 数据来源

唯一来源：PX4 `SYS_STATUS` / `BATTERY_STATUS` → `FlightStateSnapshot`：

- `battery_valid`；
- `battery_remaining_valid`；
- `battery_remaining_pct`；
- 遥测新鲜度。

新增 PX4 参数读取：

- `BAT_LOW_THR`：低电百分比阈值；
- `COM_LOW_BAT_ACT`：低电动作；
- 通过 `PARAM_REQUEST_READ` / `PARAM_VALUE` 读取，启动与重连后重试；
- 读取结果写入快照或独立参数快照，带有效性；
- 读取失败 → `battery_config_unknown`。

### 9.2 门禁

自动分配/起飞要求：

- `BAT_LOW_THR` 有效且 `0 < BAT_LOW_THR < 100`；
- `COM_LOW_BAT_ACT == 0`（Warning Only）；
- `battery_valid && battery_remaining_valid`；
- `battery_remaining_pct > BAT_LOW_THR`。

不满足：65015 rejected，availability=unavailable。机载不设本地百分比阈值，不估算剩余飞行时间。

### 9.3 飞行中触发

- 电池有效且 `pct <= BAT_LOW_THR` 连续 `battery_low_debounce_ms` → 中止任务，S12 机载位置返航，65015 aborted `battery_low`；
- 电池遥测失效/超时 → 立即中止任务，S12 返航，65015 aborted `battery_telemetry_invalid`；
- 地面 READY 低电/失效 → availability=unavailable，不分配；恢复且未执行空中任务后可回 ready；
- 空中触发过低电/遥测失效的任务机会视为已执行，落地后 terminal；
- `BAT_CRIT_THR` / `BAT_EMERGEN_THR` 仍由 PX4 最后保护；
- PX4 低电动作导致离开 Offboard → 状态机立即停发、让权，只监控；
- 正常返航用 S12 位置设定值，不使用 PX4 自动 RTL；
- 地面站可显示电量，但选机以飞机上报的 availability 为准。

### 9.4 RC 边界

- RC 是测试时的人工接管保险，接 PX4；
- 机载不读 RC、不要求 RC 在线、不要求每机配遥控器；
- RC 人工接管导致 PX4 离开 Offboard 时，机载停发让权；
- PX4 因自身解锁检查拒绝 arm，机载表现为 arm 超时并中止；
- 调度器/65013 不包含 RC 状态。

## 10. 配置

新增 `takeoff` 节：

```json
"takeoff": {
  "height_m": 2.0,
  "climb_rate_mps": 0.5,
  "bootstrap_lead_ms": 300,
  "mode_timeout_ms": 2000,
  "arm_timeout_ms": 3000,
  "bootstrap_timeout_ms": 6000,
  "height_timeout_ms": 15000,
  "stable_time_ms": 1000,
  "z_tolerance_m": 0.2,
  "xy_tolerance_m": 0.5,
  "max_vz_mps": 0.3,
  "target_wait_timeout_ms": 10000,
  "target_lost_timeout_ms": 10000,
  "battery_low_debounce_ms": 1000
}
```

校验：

- `height_m > 0`；
- `climb_rate_mps > 0`；
- 所有 timeout > 0；
- `bootstrap_lead_ms >= 0`；
- `bootstrap_timeout_ms > bootstrap_lead_ms + mode_timeout_ms + arm_timeout_ms`；
- 容差/防抖 ≥ 0；
- 不新增本地 `min_battery_percent`；
- 现有 `interception.min_battery_percent` 保持 0，不用于自动起飞；自动起飞电池门禁由 PX4 参数 + BatteryGuard 统一负责。

安全默认：

- `runtime.enable_control=false`；
- `interception.enabled=false`；
- 自动起飞只在 SITL/台架/现场本地副本的测试配置中实际可达。

## 11. GroundStationLink

新增/修改：

- 65014 解析：只接受地面站来源；地址双字段校验；发布 `Topic<MissionAssignment>`；
- 65015 发送：订阅 `Topic<MissionAssignmentAck>`，以本机身份发往 255/190；
- 65013 扩展：写入 `assignment_id/target_id/availability/interceptor_type`；65013 版本 2；
- 65010 地址校验保持现状；

- 错误地址不回 65015；非法内容在地址匹配时回 rejected；
- 地面站链路未就绪时，分配消息仍可在本机解析，但 S2 预检会因控制路径/健康条件拒绝。

## 12. DroneApplication 接线

`BuildComponents` / `BindTopics` 增加：

- `ground_station->MissionAssignmentOutput()` → `mission_state_machine->SetAssignmentInput()`；
- `mission_state_machine->AssignmentAckOutput()` → `ground_station->SetMissionAssignmentAckInput()`；
- 生产装配调用 `mission_state_machine->SetEstimationInputs(...)`，S5 才具备位置引导输出；
- 需要时注入 `SetEstimationDiagnostics`；
- `enable_control=true` 时：
  - 绑定 `px4_link_->SetInput(flight_controller_->SetpointOutput())`；
  - 注入 `SetCommandSender(px4_link_.get())`；
- `enable_control=false` 时不绑定控制出口、不注入命令接口；状态机对 65014 回 `control_disabled`；
- 状态机、控制器、地面站 Topic 的生命周期仍由 `DroneApplication` 按依赖序管理，禁止把业务逻辑写进装配层。

## 13. 安全与失效处置

| 事件 | 处置 |
|---|---|
| 无分配/分配非法 | 不起飞，回 65015 rejected |
| 地址不匹配 | 忽略，不回 65015 |
| 预检失败 | 拒绝，保持 READY/ unavailable |
| 模式请求超时 | 中止分配，停 bootstrap，地面 disarm，回 65015 aborted |
| 解锁超时 | 同上 |
| bootstrap 超时 | 控制器停流回 IDLE，状态机中止 |
| 起飞超时 | 空中 S13，地面停流/READY |
| 目标等待超时 | S12 返航 |
| 目标丢失 | S12 返航 |
| 低电 | S12 返航，不走 PX4 RTL |
| 电池遥测失效 | 立即中止，S12 返航 |
| PX4 断连 | 不继续任务；保持最终保护，availability unavailable |
| 执行器故障 | 现有 S16，terminal |
| 取消 | 未离地 READY/ unavailable；已离地 S12→S13→S14 |
| RC 接管 | PX4 离开 Offboard，机载停发让权 |

原则：

- 失败不自动重试；
- 不广播、不抢占其它飞机的控制；
- 机载不把 PX4 RTL 当作正常返航；
- 任何中止都不在未知空中状态下 disarm。

## 19. 风险与待实测

1. `BAT_LOW_THR`/`COM_LOW_BAT_ACT` 参数读取稳定性与 PX4 1.17 行为需台架确认；读取失败时自动任务不可用；
2. `COM_LOW_BAT_ACT=0` 是机载主动返航的前提；若现场未配置，自动分配必须拒绝；
3. 电池百分比在 PX4 电池模型未学习/电压波动时可能不稳定，需防抖与实飞数据；
4. PX4 无 RC 时的解锁/任务配置需台架确认；机载不把 RC 作为门禁；
5. `bootstrap_lead/mode_timeout/arm_timeout/bootstrap_timeout/height_timeout` 为初始值，必须由 SITL/台架冻结；`bootstrap_timeout` 必须大于前导等待+模式+解锁超时；
6. 65013 版本 2 需要地面站解析兼容；Web/Node 调度器另立规格；
7. 一次上电一次空中任务的语义需要调度器配合；地面中止后的重新分配必须由操作员显式发起；
8. 目标估计生产接线后，S5 的位置引导才有效；未接线时自动分配应拒绝或只保持悬停，不得假装执行。
