# 探针首尾统计模式（--end-to-end-only）设计

日期：2026-09-30　状态：已获用户确认

## 背景与目的

`video_latency_probe` 复用正式 `DroneApplication` 视频链路做延迟统计，但中间阶段统计（01/02/04/05/07/08/10/11/12/13、D1-D5、Y1-Y4）每帧约 20+ 次取时钟 + 互斥锁 Add，存在观察者效应；探针还强制开启慢帧关联日志（`slow_frame_threshold_ms=10`），慢帧触发热路径日志 I/O。

目的：新增"首尾模式"，关闭全部中间统计与慢帧日志，只测四条入口→出口端到端链，得到接近无探针状态的真实一帧处理时间。

## 需求（已确认）

1. 保留四条 ingress→出口统计：03 入口→解码输出、06 入口→YOLO完成、09 入口→标注输出、14 入口→本地RTSP发布完成。
2. 开关形态：仅探针 CLI 参数 `--end-to-end-only`；正式 `config.json` 不新增字段，正式程序始终全量统计。
3. 首尾模式下慢帧关联日志一并关闭（`slow_frame_threshold_ms=0`）。

## 方案

各组件配置增加 `collect_detailed_latency` 布尔字段（默认 `true`，行为不变）：

| 配置 | 为 false 时关闭 | 保留 |
|---|---|---|
| `VideoDecoderConfig` | 01 输入队列、02 解码+转存、D1-D5 细分 | 03 ingress→decoded |
| `YoloDetectorConfig` | 04 队列、05 推理、Y1-Y4 细分 | 06 ingress→inference |
| `CompositorConfig` | 07 队列、08 叠加 | 09 ingress→annotated |
| `VideoSenderConfig`（透传编码后端） | 10 队列、12 编码+推送、11 帧准备、13 包写入 | 14 ingress→rtsp |

热路径用 `if (config.collect_detailed_latency)` 包住中间统计的 `Add` 调用；false 时这些统计为空。取时钟保留（与慢帧诊断、功能字段 `inference_time_ms` 共用，单次约几十纳秒，开销可忽略）。ingress→出口链利用帧信息已有的 `pipeline_ingress_time_ms`，只在出口做一次减法，始终开启。

编码后端（`video_encoder.cpp` 的 11/13）通过编码配置透传同一开关。

## 探针改动（tools/video_latency_probe.cpp）

- 新增 `--end-to-end-only` 参数：置四个组件 `collect_detailed_latency=false`，`decoder.slow_frame_threshold_ms=0`。
- 配置回显行追加模式标识。
- 首尾模式打印：区间 FPS/Mbps/关键帧头 + 03/06/09/14 四条 + 说明行；不打印中间统计段落。

## 测试

- decoder/yolo/compositor/sender 各补单测：`collect_detailed_latency=false` 时中间统计 Snapshot 为空（total_count=0）、ingress→出口链仍正常计数。
- 现有 206 项基线 + 装配回归测试不得破坏（默认值不变）。
- 探针参数解析与实机效果在香橙派验证。
