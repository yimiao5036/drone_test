# 主程序集成与数据链路实施计划

> 创建日期：2026-08-28  
> 当前阶段：PX4只读遥测已装入正式主程序；GroundStationLink标准遥测下行已实现并接入，等待香橙派串口6与Vue3地面站联调。  
> 用途：跨会话恢复工作的主任务文档。后续每完成一个阶段，必须同步更新“当前检查点”和“下一步”。

## 1. 背景与目标

当前正式 `main.cpp` 只装配视频链路：

```text
CameraReceiver
→ VideoDecoder
→ YoloDetector
→ FrameCompositor
→ VideoSender
```

PX4 通信能力已经在独立模块和 smoke 中实现并验证，但尚未装入正式主程序。地面站通信、状态机和飞行控制器仍为 Stub。

本计划的目标是先建立稳定、可观察、可独立测试的数据平面：

```text
PX4遥测 → 内部Topic → 地面站下行
地面站目标 → 内部Topic → 后续目标估计/状态机
```

再在此基础上接入健康管理、状态机、目标估计和控制算法，避免算法完成后一次性进行大范围装配联调。

## 2. 核心决策

### 2.1 先数据链路，后控制算法

实施顺序：

1. 正式主程序装配 PX4 只读遥测；
2. 实现地面站双向数传；
3. 装配健康、目标和任务状态数据；
4. 实现状态机与飞行控制算法；
5. 最后显式开启 `Px4Setpoint` 控制输出。

### 2.2 当前严禁正式主程序输出飞行控制

第一阶段不得调用：

```cpp
px4_link_->SetInput(flight_controller_->SetpointOutput());
px4_link_->SendCommand(...);
```

正式主程序当前只允许 PX4 链路发送：

- 机载电脑 `HEARTBEAT`；
- `MAV_CMD_REQUEST_MESSAGE`；
- `MAV_CMD_SET_MESSAGE_INTERVAL`。

不得发送 ARM、DISARM、模式切换、Offboard setpoint、起飞、降落或 RTL。

### 2.3 `main.cpp` 只保留进程入口职责

不继续把组件创建、配置解析、Topic 接线和启停逻辑堆入 `main.cpp`。计划新增应用装配层：

```text
include/application/drone_application.h
src/application/drone_application.cpp
include/application/主程序集成.md
```

`main.cpp` 最终只负责：

```text
定位配置
→ 加载强类型配置
→ 初始化日志
→ 注册信号
→ 创建 DroneApplication
→ Start
→ 等待停止
→ Stop
```

### 2.4 不做 PX4 原始 MAVLink 透明转发

地面站链路不能直接转发 PX4 原始字节流。必须使用：

```text
PX4 MAVLink
→ Px4Link解析
→ FlightStateSnapshot
→ GroundStationLink选择和编码
→ 地面站协议
```

原因：

- 防止地面站绕过状态机直接控制 PX4；
- 避免 system/component ID 冲突；
- 控制电台带宽；
- 隔离 PX4 固件与自研地面站协议；
- 后续可以加入命令白名单、权限和有效期检查。

## 4. 分阶段实施

## 4.1 第一阶段：正式主程序装配 PX4 只读遥测

### 目标

正式程序同时运行：

```text
视频链路
+
PX4串口遥测链路
```

PX4 数据通过现有：

```cpp
common::Topic<common::FlightStateSnapshot>& Px4Link::StateOutput();
```

发布，供后续地面站、状态机、控制器和感知模块订阅。

### 实现内容

1. 建立统一强类型配置加载；
2. 新增 `DroneApplication` 应用装配层；
3. 将当前视频组件所有权和接线迁入应用层；
4. 按 `config/config.json` 创建真实 `Px4Link`；
5. 启动 `/dev/ttyS1 @115200` 串口链路；
6. 不绑定任何 `Px4Setpoint` 输入；
7. 视频和 PX4 可以独立降级运行；
8. 增加启动/停止/配置测试；
9. 更新实现文档和部署说明。

### 第一阶段验收

开发机：

```bash
cmake -S . -B build
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
```

香橙派：

- 视频链路继续正常出图；
- `/dev/ttyS1` 正常打开；
- PX4 心跳建立；
- `FlightStateSnapshot` 持续发布；
- 停机顺序正确；
- 没有 ARM、模式、setpoint 或其他飞行控制消息；
- PX4 断开时视频链路仍可继续运行并记录降级状态。

## 4.2 第二阶段：地面站通信基础和 PX4 遥测下行

### GroundStationLink 接口调整

当前接口只有：

```cpp
TargetOutput();
SetInput(Topic<MissionStatus>&);
```

计划改为语义明确的多输入：

```cpp
virtual void SetFlightStateInput(
    common::Topic<common::FlightStateSnapshot>& flight) = 0;

virtual void SetMissionStatusInput(
    common::Topic<common::MissionStatus>& mission) = 0;

virtual void SetHealthInput(
    common::Topic<common::HealthStatus>& health) = 0;
```

上行输出保持：

```cpp
virtual common::Topic<common::GroundStationTarget>& TargetOutput() = 0;
```

### 地面站双向数据流

```text
PX4
→ FlightStateSnapshot
→ GroundStationLink
→ 电台
→ 地面站

地面站
→ GroundStationLink
→ GroundStationTarget
→ TargetEstimator（后续）
```

### 下行建议频率

5~10Hz：

- armed、landed、flight mode；
- local NED 位置和速度；
- 姿态；
- GPS fix。

1~2Hz：

- 经纬度和高度；
- Home；
- 电池；
- PX4/RC连接状态；
- 任务状态与健康状态。

事件触发：

- armed、landed、模式变化；
- GPS/位置有效性变化；
- 电池告警；
- failsafe；
- 地面站断联；
- 状态机转移。

频率控制必须在 `GroundStationLink` 内完成，`main.cpp` 不逐消息转换或发送。

### 第二阶段已确认信息（2026-09-01）

- 数传使用香橙派串口6，JSON暂配`/dev/ttyS6`；实际节点不符时只改配置；
- 当前115200、8N1、无校验、无流控，全部可配置；
- MAVLink 2，不做PX4原始字节透传；
- 发送身份复用机载电脑身份；地面站发送`MAV_TYPE_GCS`心跳；
- 地面站为Vue3自研测试地面站，不依赖QGC；
- 当前发送GPS、位置、姿态、电池、模式、landed和Home等标准状态；频率由链路内部限频且可配置；
- 目标位置协议暂不实现，只预留`TargetOutput()`；
- 当前不启用MAVLink signing或其他鉴权。

## 4.3 第三阶段：健康、目标和任务状态数据装配

接入：

```text
HealthManager::Output()       → GroundStationLink
MissionStateMachine::Status() → GroundStationLink
GroundStationTarget           → TargetEstimator
FlightStateSnapshot           → Health/StateMachine/Fusion
```

该阶段先保证状态数据流通，不启用控制输出。

## 4.4 第四阶段：状态机和控制算法

计划装配：

```cpp
perception_fusion_->SetInputs(
    detector_->DetectionOutput(),
    optical_flow_->FlowOutput(),
    laser_->RangeOutput(),
    px4_link_->StateOutput());

target_estimator_->SetInputs(
    perception_fusion_->TargetOutput(),
    ground_station_link_->TargetOutput());

state_machine_->SetInputs(
    target_estimator_->EstimatedOutput(),
    px4_link_->StateOutput(),
    health_manager_->Output());

flight_controller_->SetInput(
    state_machine_->IntentOutput());
```

正式控制器必须实现：

- 速度、加速度和 jerk 限制；
- Position/Velocity 平滑切换；
- 刹停和悬停；
- setpoint 新鲜度和连续性监控；
- 最大速度、倾角和高度限制；
- 控制权和人工接管门禁。

只有该阶段完成台架验证后，才允许：

```cpp
px4_link_->SetInput(flight_controller_->SetpointOutput());
```

## 5. 配置设计

计划新增统一配置类型：

```text
include/config/config.h
src/config/config.cpp
include/config/配置管理.md
```

建议结构：

```cpp
struct RuntimeConfig {
    bool enable_video = true;
    bool enable_px4 = true;
    bool enable_ground_station = true;
    bool enable_control = false;
};

struct AppConfig {
    LogConfig log;
    VideoConfig video;
    YoloDetectorConfig yolo;
    communication::Px4LinkConfig px4;
    GroundStationLinkConfig ground_station;
    RuntimeConfig runtime;
};
```

JSON 计划新增：

```json
"runtime": {
    "enable_video": true,
    "enable_px4": true,
    "enable_ground_station": true,
    "enable_control": false
}
```

安全约束：

- 当前 `enable_control` 必须为 false；
- `enable_control=true` 但 PX4 未启用时配置校验失败；
- 真实串口配置不得使用任何 SITL smoke 高风险参数；
- 路径继续按 `/proc/self/exe` 目录和当前目录候选链解析。

## 6. 生命周期和线程模型

### 启动原则

1. 创建全部组件；
2. 在任何 `Start()` 前完成 Topic 绑定；
3. 先启动消费者，后启动生产者；
4. 单模块失败只使系统降级，不恢复旧控制状态；
5. 状态机完成前，PX4断开不应使视频链路崩溃。

示例：

```text
GroundStationLink（消费者）
→ Px4Link（FlightState生产者）
```

### 停止原则

先停止生产者，再停止消费者：

```text
Px4Link
→ GroundStationLink
```

视频链路：

```text
CameraReceiver
→ VideoDecoder
→ YoloDetector/FrameCompositor
→ VideoSender
```

所有 Stop 必须幂等，线程退出后再销毁 Topic 和依赖对象。
