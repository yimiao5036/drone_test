## 1. 背景与目标

本计划创建时正式`main.cpp`只装配视频链路；当前相关组件已迁入`DroneApplication`统一装配：

```text
CameraReceiver
→ VideoDecoder
→ YoloDetector
→ FrameCompositor
→ VideoSender
```

PX4通信和地面站通信已经装入正式主程序并完成实机验证；标准TIMESYNC、目标UPDATE/ACK以及健康/任务状态回传均已接入`GroundStationLink`。状态机已替换为安全影子实现，飞行控制器仍为Stub；独立`target_tracker`和`visual_track_control`库已实现但尚未接入主应用。

本计划的目标是先建立稳定、可观察、可独立测试的数据平面：

```text
PX4遥测 → 内部Topic → 地面站下行
地面站目标 → 内部Topic → 后续目标估计/状态机
```

再在此基础上接入健康管理、状态机、目标估计和控制算法，避免算法完成后一次性进行大范围装配联调。

## 2. 核心决策

### 2.1 先数据链路，后控制算法

实施顺序：

1. 正式主程序装配 PX4 只读遥测；
2. 实现地面站双向数传；
3. 装配健康、目标和任务状态数据；
4. 实现状态机与飞行控制算法；
5. 最后显式开启 `Px4Setpoint` 控制输出。

### 2.2 当前严禁正式主程序输出飞行控制

第一阶段不得调用：

```cpp
px4_link_->SetInput(flight_controller_->SetpointOutput());
px4_link_->SendCommand(...);
```

正式主程序当前只允许 PX4 链路发送：

- 机载电脑 `HEARTBEAT`；
- `MAV_CMD_REQUEST_MESSAGE`；
- `MAV_CMD_SET_MESSAGE_INTERVAL`。

不得发送 ARM、DISARM、模式切换、Offboard setpoint、起飞、降落或 RTL。

### 2.3 `main.cpp` 只保留进程入口职责

不继续把组件创建、配置解析、Topic 接线和启停逻辑堆入 `main.cpp`。计划新增应用装配层：

```text
include/application/drone_application.h
src/application/drone_application.cpp
include/application/主程序集成.md
```

`main.cpp` 最终只负责：

```text
定位配置
→ 加载强类型配置
→ 初始化日志
→ 注册信号
→ 创建 DroneApplication
→ Start
→ 等待停止
→ Stop
```

### 2.4 不做 PX4 原始 MAVLink 透明转发

地面站链路不能直接转发 PX4 原始字节流。必须使用：

```text
PX4 MAVLink
→ Px4Link解析
→ FlightStateSnapshot
→ GroundStationLink选择和编码
→ 地面站协议
```

原因：

- 防止地面站绕过状态机直接控制 PX4；
- 避免 system/component ID 冲突；
- 控制电台带宽；
- 隔离 PX4 固件与自研地面站协议；
- 后续可以加入命令白名单、权限和有效期检查。

```text

→ FlightStateSnapshot
→ GroundStationLink
→ 电台

→ GroundStationLink
```

- 经纬度和高度；

## 4.3 第三阶段：健康、目标和任务状态数据装配

`HealthManager` 是系统健康状态汇总器：各模块上报最近一次有效数据到达时间和必要的错误/连接事实，HealthManager 按单调时钟执行新鲜度检查，汇总链路健康位、设备健康位、数据新鲜度位、错误位和算力板负载，发布 `HealthStatus`。它不负责硬件读写、重连、任务状态转移或 PX4 控制输出；这些职责仍属于对应通信模块、状态机和控制器。

接口与数据流：

```text
CameraReceiver / VideoDecoder / YoloDetector / VideoSender
Px4Link / GroundStationLink
        → RegisterSource + ReportData + 模块状态
        → HealthManager
        → Topic<HealthStatus>
        ├── MissionStateMachine（安全门禁和降级判断）
        └── GroundStationLink（健康状态回传）

MissionStateMachine::Status() → GroundStationLink
GroundStationTarget + PX4 Home → TargetEstimator（局部NED线性卡尔曼影子）
FlightStateSnapshot           → HealthManager/StateMachine/Fusion
```

当前仓库已经完成 `HealthManager` 独立实现并接入 `DroneApplication`：支持标准数据源注册、100ms 单调时钟新鲜度检查、链路/设备健康位、超时位、恢复快照和生命周期管理；`HealthManagerStub` 仍保留供骨架测试。应用级监控线程已把视频、PX4、地面站、解码器、YOLO和图传计数变化转换为 `ReportData()`，HealthStatus 已接入状态机并通过65012下行，MissionStatus通过65013下行；`health_status_topic_` 不再是主程序占位源。CPU负载和视频/PX4/地面站等现有模块活动`error_bits`已接入。维护者已取消独立激光雷达和独立电源管理：距离后续由双目摄像头深度模块提供，电量统一读取PX4动力电池；原位定义仅保留兼容，不再作为待接入任务。该阶段仍不启用控制输出。

## 6. 生命周期和线程模型

### 启动原则

1. 创建全部组件；
2. 在任何 `Start()` 前完成 Topic 绑定；
3. 先启动消费者，后启动生产者；
4. 单模块失败只使系统降级，不恢复旧控制状态；
5. 状态机完成前，PX4断开不应使视频链路崩溃。

示例：

```text
GroundStationLink（消费者）
→ Px4Link（FlightState生产者）
```

### 停止原则

先停止生产者，再停止消费者：

```text
Px4Link
→ GroundStationLink
```

视频链路：

```text
CameraReceiver
→ VideoDecoder
→ YoloDetector/FrameCompositor
→ VideoSender
```

所有 Stop 必须幂等，线程退出后再销毁 Topic 和依赖对象。
