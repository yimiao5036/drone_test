# 需求分析

## 1. 文档状态

本文记录当前已经确认的需求、V1 能力边界和仍需通过硬件设计或实测确定的项目。未确认内容统一标记为“待定”，不得在实现时自行猜测。

## 2. 系统参与者

| 参与者 | 职责 |
|--------|------|
| 地面站 | 创建任务、持续发送目标状态、查看遥测、发送人工任务指令和可选拦截授权 |
| 香橙派算力板 | 感知、状态估计、任务决策、解锁、起飞、跟踪、拦截协调和正常返航控制 |
| PX4 飞控 | 姿态和位置底层控制、导航状态融合、动力电池监测、Home 管理和最终失联保护 |
| 遥控器/飞手 | 测试、故障处置和人工接管 |
| 摄像头 | 提供正前方 H.265 视频 |
| 单点激光雷达 | 提供机头正前方绝对距离 |
| 拦截设备 | 执行具体拦截动作，通过通用接口接入 |

## 3. 已确认约束

- 算力板为 Orange Pi RK3588，运行 Ubuntu。
- 飞控硬件为 Pixhawk 2.4.8，固件已升级为 PX4 1.17.0。
- 算力板通过串口 MAVLink 与 PX4 通信，自身没有 GPS。
- 地面站自研，通过电台和算力板使用 MAVLink 通信。
- 摄像头固定指向机头正前方，通过 RJ45/TCP 发送 H.265 1080p、25 FPS 视频。
- 光流由算力板从解码图像计算，没有独立光流传感器。
- YOLO 输出目标类别、置信度和目标在画面中的像素位置。
- 障碍物类别先保留一个通用类别，具体分类体系待定。
- 激光雷达为机头正前方单点雷达，更新频率可修改。
- 动力电池和算力板电池独立；PX4 提供动力电池信息，算力板电池监测硬件待设计。
- V1 正常返航由算力板控制并使用 PX4 上报的 Home 点。
- 算力板或串口完全失效时，PX4 自身失联保护作为最后保障。
- V1 拦截后默认返回 Home。
- V1 障碍物处理只实现减速、刹停和悬停，自主绕行留待升级。

## 4. 功能需求

### 4.1 启动与自检

- FR-001：系统应检查 PX4 链路、导航状态、Home、动力电池和飞行模式。
- FR-002：系统应检查摄像头 TCP 连接、H.265 解码、YOLO、光流和雷达数据。
- FR-003：系统应区分必需能力、可降级能力和未安装能力。
- FR-004：飞行安全必需项失败时，系统不得请求解锁。

### 4.2 地面站任务输入

- FR-010：地面站应发送目标编号、经纬度、高度、速度、航向、定位精度、源时间戳、序号和有效期。
- FR-011：算力板应拒绝过期、非法或异常跳变的目标状态。
- FR-012：目标位置更新频率和超时阈值必须配置化。
- FR-013：地面站可发送任务开始、取消、返航、人工拦截授权和任务状态查询；V1 以一次任务为主。

### 4.3 起飞与远距离接近

- FR-020：解锁和起飞由算力板通过 PX4 完成。
- FR-021：算力板应以 PX4 实际状态确认解锁、模式切换和起飞结果。
- FR-022：未稳定捕获目标时，算力板应根据地面站目标状态和 PX4 本机位置执行位置引导。
- FR-023：对移动目标的位置引导应持续更新，不应把旧目标位置作为永久航点。

### 4.4 视觉跟踪

- FR-030：视觉输出应包含类别、置信度、像素位置、帧序号和采集时间。
- FR-031：目标连续稳定识别且飞行器到达上一位置控制目标后，系统方可切换为速度和方向跟踪。
- FR-032：切换条件应使用位置误差和速度阈值，不使用浮点坐标精确相等。
- FR-033：视觉跟踪速度、加速度和方向变化必须限幅。
- FR-034：卡尔曼滤波可用于平滑和短时预测，但预测时间与不确定度必须有上限。
- FR-035：目标丢失策略应可替换，并支持最新 GPS 目标校验、整机搜索和退回位置引导。

### 4.5 感知与障碍物处理

- FR-040：摄像头负责障碍物类别和画面方位，激光雷达负责机头前向绝对距离，光流提供图像运动信息。
- FR-041：雷达距离只有在完成相机—雷达标定且空间关联成立时，才可作为目标距离。
- FR-042：V1 检测到前向危险时应按距离分级减速、刹停并悬停。
- FR-043：V1 不得在无法确认侧向安全时自动选择绕行方向。
- FR-044：障碍解除后的恢复必须重新验证任务输入、视觉、飞行状态和安全距离。
- FR-045：避障决策必须通过抽象策略提供，以便升级为视觉绕行、深度感知或路径规划。

### 4.6 拦截

- FR-050：拦截设备应通过统一接口报告未提供、未就绪、就绪、执行中、成功、失败、已使用和故障状态。
- FR-051：具体捕网或其他拦截方式不得进入状态机通用逻辑。
- FR-052：拦截授权应支持自动授权和地面站确认两种策略。
- FR-053：拦截后决策应支持自动返航、自动继续和地面站决定；V1 默认自动返航。

### 4.7 返航、降落和接管

- FR-060：正常返航由算力板使用 PX4 上报的有效 Home 点完成。
- FR-061：返航过程中感知模块继续工作，V1 遇到障碍物应刹停悬停并请求处置。
- FR-062：算力板、控制程序或串口完全失效时，应由 PX4 的 Offboard 丢失保护执行后备动作。
- FR-063：遥控器接管优先于算力板任务控制。
- FR-064：人工接管后不得自动恢复旧任务，恢复前必须重新验证全部控制条件。
- FR-065：系统必须确认 landed 和 disarmed 后才可声明任务结束。
- FR-066：V1 拦截后不自动进入第二次任务。

### 4.8 电源

- FR-070：算力板应读取 PX4 的动力电池状态，用于飞行和返航能力判断。
- FR-071：应预留算力板独立电池监测接口。
- FR-072：算力板电池监测硬件完成后，应提供电压、电流、剩余容量、健康状态和数据时间。
- FR-073：任一电源余量不足时，应阻止新任务或触发保守返航策略。

## 5. 非功能需求

- NFR-001：使用 C++17、CMake、RAII 和 spdlog。
- NFR-002：物理链路互相隔离，不得因摄像头、图传或地面站阻塞 PX4 控制输出。
- NFR-003：所有跨线程队列有界，并定义满队列策略。
- NFR-004：图像和感知数据优先保证新鲜度，允许丢弃旧帧。
- NFR-005：所有控制相关数据携带时间戳、序号、坐标系、单位和有效性。
- NFR-006：策略、设备和通信适配器通过接口注入，可使用 mock 独立测试。
- NFR-007：关键阈值必须配置化，不得散落在状态机代码中。
- NFR-008：PX4 控制和保护行为必须通过 SITL、台架和受控飞行逐级验证。
- NFR-009：程序升级不得要求修改通用状态机才能更换摄像头、避障策略或拦截设备。

## 6. 能力升级点

| 能力 | V1 | 预留升级 |
|------|----|----------|
| 摄像头 | 固定前视 | 云台相机及姿态反馈 |
| 视频处理 | H.265 解码、YOLO、光流 | 更换解码器、模型或推理后端 |
| 障碍处理 | 刹停、悬停 | 单目深度、多方向测距、局部路径规划 |
| 目标丢失 | 短时预测和整机搜索 | 云台搜索、多传感器跟踪、多假设管理 |
| 返航 | 算力板控制至 PX4 Home | 带障碍地图的路径规划返航 |
| 拦截 | 通用接口 | 多种执行机构插件 |
| 算力板电源 | 接口预留 | 电量计、BMS 或 UPS 硬件接入 |
| PX4 | 1.17.0 适配 | 飞控版本适配层 |

## 7. 待定项

- TCP 视频流的应用层帧边界、连接握手、鉴权和重连协议。
- 相机型号、内参、畸变参数及相机—机体—雷达外参。
- YOLO 推理后端、模型格式和障碍物具体类别。
- 地面站与 PX4 串口波特率、MAVLink system/component ID 分配。
- 目标和本机高度基准。
- 所有控制、超时、制动、滤波和锁定阈值。
- 视觉丢失的最终分类、搜索和退出策略。
- 算力板独立电池的监测硬件和保护阈值。
- PX4 1.17.0 的具体 Offboard、遥控器和 RTL 保护参数。
