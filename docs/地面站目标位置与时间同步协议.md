# 地面站目标位置与时间同步协议

> 文档状态：方案冻结，暂不进入代码实现  
> 协议版本：V1  
> 冻结日期：2026-09-03  
> 适用链路：自研地面站 `255/190` 与飞机地面站链路身份 `N/25`、`N/26` 之间的 MAVLink 2 链路  
> 不适用链路：Orange Pi `1/191` 与 PX4 `1/1` 之间的本机 MAVLink 链路

## 1. 功能职责与边界

本协议解决以下问题：

1. 地面站和飞机使用各自单调时钟时，如何估计时钟偏移与链路往返延迟；
2. 飞机如何判断目标位置从“地面站生成时刻”起是否仍然有效；
3. 多机环境中如何把目标精确发送给某一类别、某一编号的飞机；
4. 如何识别地面站进程重启、目标重复、乱序、过期和字段非法；
5. 如何向地面站返回“已接收/已拒绝”的协议结果。

本协议当前只冻结设计，不实现以下行为：

- 不在 `GroundStationLink` 中解析并发布目标；
- 不生成 `ControlIntent` 或 `Px4Setpoint`；
- 不调用 `Px4Link::SendCommand()`；
- 不切换 PX4 Offboard；
- 不解锁、不起飞、不执行拦截设备；
- 不把“目标消息已接收”解释为“飞行任务已执行”。

当前正式配置继续保持：

```json
"enable_control": false
```

## 2. 身份与路由

身份规则引用 `docs/多机身份与功能寻址设计.md`：

```text
地面站来源：255/190
捕网类 N 号：N/25
火箭类 N 号：N/26
27～99：未定义，全部预留
```

目标消息必须同时携带：

```text
target_system
target_component
```

机载端只有在以下条件同时成立时才继续解析：

```text
MAVLink帧头来源 == 255/190
目标system == 本机aircraft_system_id
目标component == 本机aircraft_component_id
```

目标二元身份不匹配时直接忽略且不返回 ACK，避免共享链路上所有飞机对同一消息响应。

## 3. 时钟原则

### 3.1 控制实效性只使用单调时钟

地面站和 Orange Pi 均使用本进程单调时钟进行协议时间计算。禁止用本地时区时间或可被 NTP/人工调整的墙上时间直接进行控制实效性判断。

系统时间可用于日志显示，但不能作为目标过期判断的唯一依据。

### 3.2 不修改操作系统时钟

时间同步只在 `GroundStationLink` 内维护：

```text
地面站时钟相对飞机时钟的offset
TIMESYNC RTT
offset抖动
最后有效样本时间
同步状态
```

不调用系统校时接口，不改变 Orange Pi 或地面站操作系统时间。

### 3.3 目标时间源必须与 TIMESYNC 一致

目标消息中的 `source_time_ms` 必须与地面站响应 `TIMESYNC.ts1` 使用同一个单调时钟源。`TIMESYNC` 使用纳秒，目标消息使用毫秒，两者只做单位换算，不允许分别使用 `Date.now()` 和单调时钟。

## 4. MAVLink 标准 TIMESYNC

### 4.1 发起方

由飞机端 `GroundStationLink` 主动发起 `TIMESYNC`。最终判断目标是否过期的是飞机端，因此飞机端必须掌握地面站时钟到本机时钟的映射。

### 4.2 交互流程

飞机发送请求时记录本机单调时钟 `t1`：

```text
飞机 source=N/25 或 N/26
TIMESYNC.tc1 = 0
TIMESYNC.ts1 = t1_ns
```

地面站收到后立即读取地面站单调时钟 `t2` 并响应：

```text
地面站 source=255/190
TIMESYNC.tc1 = t1_ns
TIMESYNC.ts1 = t2_ns
```

飞机收到响应时记录本机单调时钟 `t3`：

```text
RTT = t3 - t1
offset = t2 - (t1 + t3) / 2
```

其中：

```text
offset = 地面站时钟 - 飞机时钟
```

将地面站时刻映射到飞机本地时钟：

```text
time_in_aircraft_clock = time_in_ground_clock - offset
```

### 4.3 响应匹配

`TIMESYNC` 没有目标字段。飞机端必须同时检查：

1. MAVLink 来源为 `255/190`；
2. `tc1` 与当前尚未完成的请求时间戳匹配；
3. 当前链路实例与发出请求的链路实例相同；
4. RTT 为正且未超过配置上限。

其他飞机即使收到同一响应，也会因没有匹配的 `tc1` 请求而忽略。

### 4.4 单向延迟边界

`RTT / 2` 只能作为链路单向延迟的近似值。上下行排队和无线链路可能不对称，本协议不声称能够得到绝对精确的单向传播时间。

目标消息的传输年龄通过“同步后的源时间映射”估算，RTT 用于判断同步样本质量和链路趋势。

## 5. 时间同步状态

定义四种状态：

| 状态 | 含义 | 目标处理 |
|---|---|---|
| `UNSYNCHRONIZED` | 尚无有效样本 | 不允许进入控制数据流 |
| `ACQUIRING` | 正在收集样本 | 不允许进入控制数据流 |
| `SYNCHRONIZED` | offset、RTT和样本年龄满足要求 | 允许继续校验目标 |
| `DEGRADED` | RTT、offset跳变或样本超时 | 清除旧目标，禁止进入控制数据流 |

同步不能只做一次。连接建立后快速采样，稳定后低频保持；地面站进程重启、链路重连、时钟异常或样本超时后重新进入 `ACQUIRING`。

### 5.1 样本滤波

不得对所有样本直接算术平均。建议维护固定容量滑动窗口：

1. 丢弃 RTT 超限样本；
2. 优先选择 RTT 较小的样本，减少排队延迟对 offset 的污染；
3. 对候选 offset 取中位数；
4. 计算 offset 抖动；
5. offset 突然跳变时进入 `DEGRADED`，不自动相信新时间。

具体窗口容量、RTT上限、offset跳变上限和同步超时必须配置化，并在 HM30 实测后冻结。文档中的任何示例数值均不作为正式飞行参数。

## 6. 地面站进程会话标识

地面站每次启动生成随机非零 `uint32_t ground_station_boot_id`。

原因：地面站重启后单调时钟和更新序号会重新开始。如果没有 boot ID，飞机可能把新进程的消息误判为旧消息，或错误沿用旧 offset。

飞机检测到 boot ID 变化后必须：

1. 清空上一会话的目标序号；
2. 清空尚未过期的旧目标；
3. 清空旧时间同步窗口；
4. 重新完成 `TIMESYNC`；
5. 在同步恢复前拒绝目标进入控制数据流。

## 7. 自定义目标消息

### 7.1 消息名称与编号

```text
42000 TRACK_TARGET_UPDATE
42001 TRACK_TARGET_ACK
```

`42000～42099` 作为本项目地面站任务协议预留段，新增消息前必须更新正式 dialect、C++生成代码、地面站生成代码和本文档。

动态目标使用 `UPDATE` 而不是可重试的普通命令语义。新目标覆盖旧目标，禁止在新序号已经发送后重发更旧的位置。

### 7.2 TRACK_TARGET_UPDATE 必填字段

| 字段 | 类型 | 单位 | 说明 |
|---|---:|---|---|
| `source_time_ms` | `uint64_t` | ms | 地面站单调时钟生成时刻 |
| `ground_station_boot_id` | `uint32_t` | - | 地面站本次进程会话标识 |
| `update_seq` | `uint32_t` | - | 当前 boot ID 内单调递增序号 |
| `target_id` | `uint32_t` | - | 业务目标编号，必须非零 |
| `valid_for_ms` | `uint32_t` | ms | 从地面站生成时刻开始的有效期 |
| `lat` | `int32_t` | degE7 | WGS84 纬度 ×1e7 |
| `lon` | `int32_t` | degE7 | WGS84 经度 ×1e7 |
| `flags` | `uint16_t` | bitmask | 可选字段有效标志 |
| `target_system` | `uint8_t` | - | 目标飞机同类编号 |
| `target_component` | `uint8_t` | - | 目标飞机功能类别 |
| `coordinate_frame` | `uint8_t` | enum | V1 固定为 WGS84 |
| `protocol_version` | `uint8_t` | - | V1 固定为1 |

### 7.3 可选字段

| 字段 | 类型 | 单位 | 说明 |
|---|---:|---|---|
| `alt_mm` | `int32_t` | mm | 目标高度 |
| `velocity_north_cms` | `int16_t` | cm/s | 北向速度 |
| `velocity_east_cms` | `int16_t` | cm/s | 东向速度 |
| `velocity_down_cms` | `int16_t` | cm/s | 下向速度 |
| `heading_cd` | `uint16_t` | cdeg | 真北航向，0～35999 |
| `horizontal_accuracy_cm` | `uint16_t` | cm | 水平精度 |
| `vertical_accuracy_cm` | `uint16_t` | cm | 垂直精度 |
| `alt_reference` | `uint8_t` | enum | 0未知、1 MSL、2 AGL、3 WGS84椭球 |

### 7.4 flags

```text
bit0 = altitude有效
bit1 = velocity_north有效
bit2 = velocity_east有效
bit3 = velocity_down有效
bit4 = heading有效
bit5 = horizontal_accuracy有效
bit6 = vertical_accuracy有效
bit7～15 = 预留，V1必须为0
```

未设置有效位的字段不得参与控制；转换为内部消息时建议用 NaN 表示无效浮点值，并保留 `validity_flags`。

## 8. 目标实效性计算

飞机收到目标时记录本机单调时钟：

```text
receive_time_ms
```

把地面站生成时刻映射到飞机时钟：

```text
source_in_aircraft_clock = source_time_ms - offset_ms
```

计算目标传输年龄：

```text
transport_age_ms = receive_time_ms - source_in_aircraft_clock
```

计算剩余有效期：

```text
remaining_valid_ms = valid_for_ms - transport_age_ms
```

示例：

```text
目标原始有效期：1000ms
到达飞机时估算年龄：280ms
内部剩余有效期：720ms
```

不得在飞机收到目标后重新赋予完整的1000ms。

转换为内部 `GroundStationTarget` 时：

```text
header.receive_time_ms = 本机接收时间
header.valid_for_ms = 扣除传输年龄后的剩余有效期
```

后续模块继续使用本机单调时钟判断剩余有效性。通信层不修改目标经纬度；带速度时的延迟外推由 `TargetEstimator` 负责。

## 9. 接收校验顺序

机载端按固定顺序校验：

1. MAVLink来源必须为`255/190`；
2. target二元身份必须匹配本机；
3. `protocol_version`必须支持；
4. `ground_station_boot_id`必须有效；
5. 时间同步必须为`SYNCHRONIZED`；
6. `update_seq`必须比同一boot ID内已接收序号新；
7. `target_id`必须非零；
8. 经纬度必须在WGS84合法范围；
9. `valid_for_ms`必须在配置范围；
10. flags不得包含未定义位；
11. 可选字段及其有效位必须一致；
12. 时间戳不得明显来自未来；
13. `transport_age_ms`不得超过链路上限和消息有效期；
14. `remaining_valid_ms`必须满足后续处理的最小余量。

任一控制相关字段不确定时采用拒绝，不自动修正。

## 10. ACK 语义

`TRACK_TARGET_ACK` 只表示机载通信层对目标更新的接收和校验结果，不表示 PX4 已执行控制。

建议字段：

| 字段 | 类型 | 说明 |
|---|---:|---|
| `ground_station_boot_id` | `uint32_t` | 回显会话标识 |
| `update_seq` | `uint32_t` | 回显更新序号 |
| `target_id` | `uint32_t` | 回显目标编号 |
| `measured_age_ms` | `uint32_t` | 飞机估算的目标传输年龄 |
| `timesync_rtt_ms` | `uint32_t` | 最近有效TIMESYNC RTT |
| `reason_code` | `uint16_t` | 详细原因 |
| `result` | `uint8_t` | 接收结果 |
| `target_system` | `uint8_t` | 回显目标system |
| `target_component` | `uint8_t` | 回显目标component |
| `protocol_version` | `uint8_t` | 当前为1 |

结果建议：

```text
0 ACCEPTED
1 REJECTED_INVALID_FIELD
2 REJECTED_STALE_OR_DUPLICATE
3 REJECTED_UNSUPPORTED_VERSION
4 REJECTED_TIME_SYNC_UNAVAILABLE
5 REJECTED_NOT_READY
6 REJECTED_INTERNAL_ERROR
```

原因码建议：

```text
0   OK
1   SOURCE_ID_INVALID
2   TARGET_ADDRESS_MISMATCH
3   PROTOCOL_VERSION_UNSUPPORTED
4   BOOT_ID_INVALID_OR_CHANGED
5   UPDATE_SEQUENCE_STALE
6   TARGET_ID_INVALID
7   LATITUDE_OR_LONGITUDE_INVALID
8   VALID_FOR_INVALID
9   FLAGS_INVALID
10  ALTITUDE_REFERENCE_INVALID
11  HEADING_INVALID
12  ACCURACY_INVALID
13  TIME_SYNC_UNAVAILABLE
14  SOURCE_TIME_IN_FUTURE
15  TARGET_EXPIRED
16  REMAINING_VALIDITY_TOO_SHORT
17  MODULE_NOT_READY
100 INTERNAL_ERROR
```

地址不匹配时不返回 ACK；其他属于本机目标但字段非法的消息可返回拒绝 ACK。

## 11. 动态目标不重发旧更新

地面站目标建议以固定频率持续更新。目标更新是“最新状态流”，不是普通可靠控制命令：

- 新 `update_seq` 覆盖旧目标；
- ACK超时不允许在更新序号已经前进后重发旧位置；
- 飞机拒绝重复和倒序更新；
- 地面站可通过 ACK RTT、丢失率和最新已确认序号监控链路；
- 起飞、返航、拦截授权等一次性动作必须使用独立可靠命令协议，不能复用目标状态流。

## 14. 计划测试

实现时至少覆盖：

1. TIMESYNC请求/响应与offset公式；
2. 非`255/190`响应被忽略；

4. 高RTT样本被丢弃；
5. offset跳变进入DEGRADED；
6. 同步超时清除旧目标；
7. 合法`N/25`、`N/26`目标精确寻址；
8. 地面站boot ID变化重置序号和同步；

10. 经纬度、flags、有效期和可选字段校验；
11. 目标传输年龄从原始有效期中扣除；
12. 过期目标不发布；
13. ACK只表达接收结果；
14. `enable_control=false`时不存在`Px4Setpoint`或PX4命令输出。

## 15. 实施顺序

本协议暂不实现。后续实施顺序固定为：

```text
HM30延迟与RTT采样
→ 实现TIMESYNC但不接目标
→ 验证offset/RTT/jitter稳定性
→ 冻结正式门限
→ 生成正式MAVLink dialect
→ 实现TRACK_TARGET_UPDATE/ACK
→ 只发布GroundStationTarget，不接控制
→ 状态机和控制链完成后再评审是否进入自动位置引导
```
