# 状态机设计

## 1. 设计目标

状态机负责任务阶段切换和控制权仲裁，不直接实现 YOLO、滤波、避障算法或 MAVLink 编解码。具体策略通过接口注入，便于后续升级摄像头、避障传感器、返航算法和拦截设备。

任务状态、飞行状态、设备健康状态和拦截设备状态必须分别保存，不能用一个枚举表达全部系统状态。

控制权优先级为：

```text
PX4 内部安全保护
  > 遥控器人工接管
  > 算力板安全控制
  > 算力板正常任务控制
  > 地面站任务指令
```

## 2. 任务状态

| 编号 | 状态 | 说明 |
|------|------|------|
| S0 | BOOT | 进程启动和基础资源初始化 |
| S1 | SELF_CHECK | 检查飞控、地面站、摄像头、双目深度、模型和配置 |
| S2 | READY | 等待地面站下发任务 |
| S3 | ARMING | 算力板请求 PX4 解锁并验证真实解锁状态 |
| S4 | TAKEOFF | 算力板控制起飞到任务高度 |
| S5 | GPS_APPROACH | 根据地面站目标位置执行远距离位置引导 |
| S6 | VISUAL_HANDOVER | 验证视觉稳定性并完成位置到速度控制切换 |
| S7 | VISUAL_TRACKING | 根据视觉、光流和飞行状态执行速度与方向跟踪 |
| S8 | OBSTACLE_HOLD | V1 检测到前方危险后减速、刹停并悬停（**暂缓至下一期**，2026-10-12 维护者决定，见 S8 节） |
| S9 | INTERCEPT_READY | 检查锁定状态、执行机构状态和可选授权 |
| S10 | INTERCEPT_EXECUTING | 调用抽象拦截接口并等待结果 |
| S11 | POST_INTERCEPT | 评估目标和系统状态；V1 默认进入返航 |
| S12 | RETURN_HOME | 算力板控制返回 PX4 上报的 Home 点 |
| S13 | LANDING | 降落并确认落地 |
| S14 | DISARMED | 确认上锁，任务结束，不自动接受第二次任务 |
| S15 | MANUAL_OVERRIDE | 遥控器人工接管 |
| S16 | FAILSAFE | 算力板仍可用时执行降级；完全失效时依赖 PX4 保护 |

## 3. 状态动作表

| 状态 | 入口动作 | 状态内动作 | 出口动作 | 超时或异常处理 |
|------|----------|------------|----------|----------------|
| BOOT | 加载配置、日志和基础资源，禁止控制输出 | 初始化队列、内存池和设备适配器 | 发布初始化结果 | 可恢复错误限次重试；不可恢复错误停止启动 |
| SELF_CHECK | 清空旧健康结果并开始检查 | 汇总 PX4、Home、导航、遥控器、感知和电源能力 | 冻结本次自检结果并上报 | 必需项失败时保持禁止解锁，重试或停止启动 |
| READY | 上报待命、能力清单与 availability | 接收并校验任务分配（65014）、目标和人工指令 | 回 65015 并锁定本次任务参数 | 预检失败/目标过期时继续待命，不进入解锁 |
| ARMING | 每拍发布 `kTakeoff` 原点保持意图；`bootstrap_lead` 后发一次 `DO_SET_MODE(176,1/6/0)`，实际 6/0 后发一次 `ARM_DISARM(400,1)` | 读取 ACK 与真实 mode/armed（实际状态为最终判据） | 记录解锁结果，初始化 S4 爬升目标并迁移 | 模式/解锁超时或 ACK 非 ACCEPTED 中止：地面回 READY（必要时一次 DISARM），已离地转 RETURN_HOME，状态不明 unavailable；**不重试** |
| TAKEOFF | 持续发布 `kTakeoff` 意图（原点水平保持、z 按 `climb_rate` 逐拍推进） | 检查实际高度/水平误差/垂直速度，持续 `stable_time` | `TakeoffComplete()+BeginEngage()`，初始化接近控制 | 空中超时：仍 Offboard→LANDING(AUTO.LAND)，已让权→LANDING 仅监控；地面超时→停流/必要时一次 DISARM/READY；空中中止→RETURN_HOME（不空中 disarm） |
| GPS_APPROACH | 初始化全球/局部位置引导 | 消费最新目标状态并更新位置设定值，同时运行感知 | 停止位置控制输出并保存最后位置目标 | 目标暂时过期先保持；策略超时后返回 Home |
| VISUAL_HANDOVER | 冻结最后位置目标，初始化视觉控制器 | 验证视觉稳定、位置误差、速度和首条限幅指令 | 清除旧位置控制意图或撤销本次切换 | 任一条件失效返回 GPS_APPROACH |
| VISUAL_TRACKING | 启用视觉速度和方向控制 | 融合检测、光流、姿态及有效双目深度，更新目标估计 | 清除视觉速度意图并保存目标估计 | 目标丢失时执行目标丢失策略，禁止无限预测 |
| OBSTACLE_HOLD | 限速、刹停并记录来源状态 | 保持悬停，持续检查障碍、传感器和人工指令 | 清除制动意图，重新初始化目标状态的控制器 | 危险持续时保持悬停并告警，不自动绕行 |
| INTERCEPT_READY | 冻结锁定快照并检查执行条件 | 检查设备就绪、飞行稳定和可选地面站授权 | 记录授权结果并解除快照锁定 | 授权超时或条件失效时取消执行 |
| INTERCEPT_EXECUTING | 调用通用拦截设备接口 | 监视设备状态、目标状态和中止条件 | 记录执行结果，禁止重复触发 | 超时或设备故障按失败结果进入 POST_INTERCEPT |
| POST_INTERCEPT | 汇总目标、设备、电源和任务结果 | 执行拦截后决策策略 | 固化决策和任务结果 | V1 无法确定时采用默认返回 Home |
| RETURN_HOME | 校验 PX4 Home 并初始化算力板返航控制 | 持续生成返航设定值并运行前向感知 | 清除返航控制意图并初始化降落 | 遇障进入 OBSTACLE_HOLD；控制链失效依赖 PX4 后备保护 |
| LANDING | 初始化降落控制 | 检查高度、垂直速度和 landed 状态 | 请求上锁并确认 disarmed | 超时或状态异常进入 FAILSAFE 或等待人工接管 |
| DISARMED | 上报任务结束并固化结果 | 保持控制输出禁止，允许读取日志和状态 | V1 无自动出口 | 不自动接受第二次任务 |
| MANUAL_OVERRIDE | 立即停止正常任务控制输出 | 监控 PX4、遥控器和系统健康，不自动夺回控制权 | 清除旧任务控制器并重新执行恢复检查 | 接管持续时保持本状态；链路异常由 PX4 保护 |
| FAILSAFE | 记录故障、禁止不安全任务动作 | 链路仍可用时执行悬停、受控返航或降落 | 清除故障控制意图并重新验证系统 | 算力板或链路完全失效时由 PX4 执行后备保护 |

### 4.5 转移判定规则

同一控制周期只允许提交一个任务状态转移。多个事件同时满足时按以下优先级选择：

```text
PX4 已进入内部保护或算力板失去控制能力
  > 遥控器人工接管
  > 算力板检测到关键故障
  > 障碍物制动
  > 返航或取消
  > 正常任务状态转移
```

状态转移执行顺序固定为：

```text
检查事件和守卫条件
  -> 执行当前状态出口动作
  -> 执行转移动作
  -> 更新当前状态和进入时间
  -> 执行下一状态入口动作
  -> 发布状态转移事件
```

守卫条件必须使用同一控制周期生成的不可变数据快照。状态恢复必须重新验证下一状态入口条件，不能仅凭“恢复到故障前状态”直接跳转。

## 5. 主状态流

```text
BOOT
  -> SELF_CHECK
  -> READY
  -> ARMING
  -> TAKEOFF
  -> GPS_APPROACH
  -> VISUAL_HANDOVER
  -> VISUAL_TRACKING
  -> INTERCEPT_READY
  -> INTERCEPT_EXECUTING
  -> POST_INTERCEPT
  -> RETURN_HOME
  -> LANDING
  -> DISARMED
```

公共转移：

```text
飞行状态 + 遥控器接管       -> MANUAL_OVERRIDE
飞行状态 + 可处理关键异常    -> FAILSAFE
飞行状态 + 算力板完全失效    -> PX4 独立执行后备保护
GPS_APPROACH/VISUAL_TRACKING/RETURN_HOME + 前向危险 -> OBSTACLE_HOLD
```

## 6. 状态详细设计

### S0 BOOT

入口动作：

- 加载配置并初始化日志。
- 初始化消息队列、内存池和各硬件适配器。
- 初始化 H.265 解码、YOLO、光流和状态估计模块。
- 所有控制输出默认禁止。

成功进入 `SELF_CHECK`，基础资源不可恢复失败则停止启动并上报告警。

### S1 SELF_CHECK

检查项：

- PX4 MAVLink 心跳、固件版本、armed 状态和飞行模式。
- PX4 GPS、姿态、航向、动力电池和 Home 点有效性。
- 遥控器可用状态以及接管状态。
- 地面站链路和任务消息解析能力。
- 双目摄像头连接、左右图同步/解码和视频帧新鲜度；硬件切换前沿用当前单路视频检查。
- YOLO模型、光流和双目深度算法初始化状态。
- 双目深度有效范围、质量和数据新鲜度；独立激光雷达不再检查。
- PX4动力电池状态和新鲜度；不再检查独立算力板电池接口。

自检结果区分必需能力、可降级能力和未安装能力。飞行安全必需项失败时禁止解锁。

### S2 READY

- 上报待命状态、能力清单与可用状态（65013 v2 的 `availability`）。
- 接收包含目标完整状态的任务消息（65010）与任务分配（65014）。
- **任务分配入口（2026-10-22，Task 4）**：S2 收到 65014 `MissionAssignment`
  后做预检，全部满足才接受并进入 `ARMING`：
  - 字段：协议版本=1；`flags` 只允许已知位且 bit0（授权自动起飞）必须置位；
    `target_id != 0`；`interceptor_type == 本机功能类别`
    （`ground_station.aircraft_component_id`，25 捕网/26 火箭）；
    `valid_for_ms > 0` 且未超过本机收到时刻 + 有效期；
  - 控制路径：已注入 PX4 命令接口且估计/视觉/测距输入已绑定；
  - 飞行与导航：PX4 在线、`landed_state_valid && landed`、未 armed、
    局部位置/姿态/Home 有效；
  - 设备与任务机会：无任务故障/执行器故障；`MissionAssignmentTracker`
    处于 `kIdle` 且本次上电尚未消耗空中任务机会。
  - 失败：回 65015 `rejected` + 具体 reason，保持 S2，不自动重试；
    预检拒绝不消耗任务机会；状态不确定（未连接/故障）时
    `availability=unavailable`。
  - 成功：tracker `Accept` → 记录起飞原点（`BeginTakeoff`）→ 回 65015
    `accepted`（`availability=assigned`）→ 进入 `ARMING`，同拍开始发布
    `kTakeoff` 原点保持意图（S3/S4 时序见下）。
- 重复 `assignment_id`：只重发原 65015，不重新预检、不重新进入 `ARMING`
  （地面站需换新 id 才能重新分配）。
- **65014 取消（`flags.bit1`，2026-10-22 Task 10，规格 §5.1/§7.5）**：
  取消在重复/普通预检**之前**处理，只校验协议版本与未知 flags 位，
  **不要求 bit0**；`assignment_id` 必须匹配当前活动分配。
  - 未离地（tracker 未消耗空中任务机会）：S3/S4 复用统一中止——停流、必要时
    一次 DISARM、tracker `AbortOnGround()`、回 READY、65015
    cancelled/`cancelled_by_gcs`；
  - 已离地（tracker 已消耗机会或 S5~S13）：`AbortAirborne()` → `RETURN_HOME`，
    65015 cancelled/`cancelled_by_gcs`，不空中 disarm、不触发拦截；
    已在 S12/S13/S14 时只记录并回执，不重置降落链；
  - 幂等：重复取消重发最近结果，500ms 内不重复执行取消动作；无活动分配且
    该 id 从未处理 → rejected/`not_ready`；活动分配为其他 id →
    rejected/`already_assigned`；
  - 被取消的分配不可恢复；地面取消后回到 READY，可用新 `assignment_id` 重新
    分配（不自动重试）。
- **影子兼容**：未注入命令接口（`enable_control=false`）时，65014 一律回
  `rejected/control_disabled` 且 `availability=unavailable`；既有“有效 65010
  目标 + 导航就绪 → `GPS_APPROACH` 影子验证”路径保持。注入命令接口后，
  65010 目标不得单独把 S2 推到 S5，必须由 65014 分配进入 S3。
- V1 不从 `DISARMED` 自动开始第二次任务；一次上电只执行一次空中任务，
  取消/中止后不自动重试。
- **生产装配（Task 9）**：`DroneApplication` 已接 `SetAssignmentInput` /
  `AssignmentAckOutput`，并在估计器/视觉监控/双目测距三者齐备时调用
  `SetEstimationInputs`；`takeoff` 与 `expected_interceptor_type` 同源注入。

### S3 ARMING

入口：接受 65014 后 `MissionAssignmentTracker::BeginTakeoff()` 记录起飞原点
`x0/y0/z0`（局部 NED，D 向上为负）；状态机每决策拍（10Hz）发布
`type=kTakeoff` 的控制意图（**不用 `kPositionGuide` 代替**）：目标
`x0/y0/z0`、`reason_code` 带 bit31 控制权请求位（低位=7 地面站任务）、
`valid_until_ms` 按注入的意图有效期。

时序（`takeoff` 配置节）：

1. 保持原点意图满 `bootstrap_lead_ms`（默认 300ms），确保控制器已发布若干帧
   原点保持设定值（`FlightController::kBootstrap` 已接入，2026-10-22）；
2. 发送**一次** `MAV_CMD_DO_SET_MODE(176)`：`param1=1`（custom mode enable）、
   `param2=6`（Offboard）、`param3=0`；
3. 等待**实际** `flight_mode=6 && flight_sub_mode=0`；超时 `mode_timeout_ms`
   （默认 2000ms）→ 中止；
4. 实际 6/0 后发送**一次** `MAV_CMD_COMPONENT_ARM_DISARM(400)`：`param1=1`；
5. 等待**实际** `armed=true`；超时 `arm_timeout_ms`（默认 3000ms）→ 中止；
6. 成功（实际 armed + Offboard）→ `TAKEOFF`。实际 `armed && !landed` 时每拍
   调用 tracker `MarkAirborne()`（幂等，消耗一次上电一次空中任务机会）。

约束：

- 176/400 各只发一次；**不自动重发**，失败后不得原地循环重发；
- 176/400 的 ACK 只作过程反馈：`last_result` 非 0（ACCEPTED）且非 5
  （IN_PROGRESS）→ 立即中止（176→mode_timeout，400→arm_timeout）；
  实际模式/armed 仍是最终判据；
- 命令入队失败（`SendCommand` 返回 false）同样中止、不重试；
- 中止当拍起停止发布 `kTakeoff`/位置意图，不留下持续控制流。

失败处置（65015 `aborted`，`result=kCancelledOrAborted`）：

| 情况 | 动作 |
|---|---|
| 模式超时/176 ACK 失败/176 入队失败 | aborted `mode_timeout`（入队失败为 `bootstrap_timeout`）；地面中止 |
| 解锁超时/400 ACK 失败/400 入队失败 | aborted `arm_timeout`；地面中止 |
| 地面中止 | 停发意图；若 `armed && landed` 只发一次 DISARM(400,param1=0)；tracker `AbortOnGround()`；回 READY（状态不明则 `availability=unavailable`） |
| 已离地（`armed && !landed`）中止 | tracker `AbortAirborne()` → `RETURN_HOME`；**不空中 disarm** |
| PX4 断连/离地状态不明 | aborted `px4_disconnected`；`takeoff_unavailable_latched_` per-boot 锁存，`availability=unavailable`、新分配 `not_ready`，不错误回到 ready |
| 任务故障（S16 路径） | aborted `mission_fault`，随后进入 FAILSAFE |

重复 `assignment_id` 只重发最新 65015（`RememberResult` 已更新为 aborted），
不再迁移。遥控器接管立即进入 `MANUAL_OVERRIDE`。

### S4 TAKEOFF

- 持续发布 `kTakeoff` 意图：水平保持 `x0/y0`；高度目标
  `z_target = z0 - takeoff.height_m`（NED 向上为负），每拍按
  `climb_rate_mps * dt` 逐拍推进（**不阶跃**）；意图继续带 bit31，
  `yaw_deg` 尽量保持当前姿态航向。
- 到达判据同时满足并保持 `stable_time_ms`（默认 1000ms）：
  `|z - z_target| <= z_tolerance_m`、水平误差 `<= xy_tolerance_m`、
  `|vz| <= max_vz_mps`。
- 到达 → tracker `TakeoffComplete()` + `BeginEngage()` → `GPS_APPROACH`，
  availability=engaged。
- 空中超时 `height_timeout_ms`（默认 15000ms）：
  - PX4 仍在 Offboard → `LANDING`，由现有降落链发 AUTO.LAND(4/6)；
  - PX4 已离开 Offboard → 停发让权，`LANDING` 仅监控，不再争控。
- 地面超时 → 停流；若 `armed && landed` 只发一次 DISARM；回 READY（状态
  不明则 unavailable）。
- 已离地后任何中止 → `RETURN_HOME`，不空中 disarm。
- 失败不重试；任务故障按上表 `mission_fault` 收口。

### S5 GPS_APPROACH

- 地面站持续发送目标编号、经纬度、高度、速度、航向、定位精度、时间戳和有效期。
- 算力板利用 PX4 上报的本机位置计算目标距离和方向，持续更新位置引导设定值。
- 过期或跳变异常的目标位置不得直接用于控制。
- **仅接受本分配目标（2026-10-22 Task 10，规格 §7.5）**：控制任务下只认
  `target_id == assignment.target_id` 的 65010 与估计目标；其他编号直接忽略
  （不影响本机、不更新引导、不参与交接）。影子模式保持既有 S5 行为。
- **目标等待/丢失收口**（`takeoff.target_wait_timeout_ms`/
  `target_lost_timeout_ms`，仅控制任务 S5）：
  - 起飞后、首个匹配目标到达前在 `x0/y0` 悬停等待；超时 → 中止分配，
    65015 aborted(`target_wait_timeout`) → `RETURN_HOME`；
  - 获得目标后匹配目标持续失效超时 → 65015 aborted(`target_lost`) →
    `RETURN_HOME`；恢复即清零丢失计时；一次任务只中止一次；
  - 中止当拍停发位置引导，不触发拦截/发射。
- **目标失效原地保持（2026-10-22 落地，替代“直接停发”）**：目标过期 /
  `target_id` 不匹配 / 估计器无输出时，控制任务在 S5 每决策拍发布
  `kPositionGuide` 保持意图——目标取 PX4 **当前局部位置**（绝不使用过期
  目标坐标）、无前馈、`reason_code = bit31 | 9`。目的是让 setpoint 流不断，
  使 FlightController 保持 ACTIVE、PX4 保持 Offboard，避免 PX4 在
  `COM_OF_LOSS_T`（1s）后按失效兜底（SITL 无 RC 时 `NAV_RCL_ACT=2` 会升级
  为 RTL）抢先接管；10s 看门狗到点后由 S12 无缝接管返航。连续 3 拍新鲜估计
  才退出保持；PX4 局部位置无效时回落停发；累计保持超
  `takeoff.target_hold_max_ms`（默认 60000）→ 65015 aborted → S12；
  期间 65013 置告警位 bit5。
- 摄像头、YOLO 和光流持续工作，寻找目标。
- 视觉目标满足稳定锁定条件后进入 `VISUAL_HANDOVER`。
- 前向危险进入 `OBSTACLE_HOLD`。

### S6 VISUAL_HANDOVER

位置控制切换到视觉速度控制必须同时满足：

- 目标连续稳定识别，置信度和检测连续性满足配置。
- 图像、检测和本机姿态均未超龄。
- 无前向危险。
- 飞行器进入上一位置目标的允许误差范围。
- 当前速度低于切换阈值。

第一条视觉速度设定值必须经过限幅，避免位置和速度控制切换产生突变。任一条件失效时返回 `GPS_APPROACH`。

### S7 VISUAL_TRACKING

- 根据目标像素位置、固定相机标定参数、本机姿态和光流估计目标视线及运动趋势。
- 当前无独立雷达计划；目标距离后续只接受与YOLO目标区域、帧序号和时间戳正确关联的有效双目深度。
- 状态估计器第一阶段使用局部NED恒速度线性卡尔曼平滑地面站目标并进行有限时预测。
- 卡尔曼预测不得无限期生成控制指令，预测时长和不确定度必须有上限。
- 视觉丢失时调用 `ITargetLostStrategy`：结合最新有效的地面站目标位置决定预测、整机转向搜索或退回 `GPS_APPROACH`。
- 视觉丢失原因可能是遮挡、漏检、目标离开或拦截结果，V1 不强行分类。
- 前向危险进入 `OBSTACLE_HOLD`。
- 满足锁定和拦截前置条件后进入 `INTERCEPT_READY`。

### S8 OBSTACLE_HOLD

> **暂缓至下一期（2026-10-12 维护者决定）**：本期不实现避障事件源（无前向
> 障碍检测组件），`EV_OBSTACLE_RISK` 不会产生，S8 在实现中保持休眠/缺省不可达；
> 状态与转移设计保留。代价：本期试飞必须在空旷无遮挡场地进行，前向安全由
> 飞手/遥控接管兜底（S15 MANUAL_OVERRIDE）。

V1 的 `IObstacleAvoidanceStrategy` 实现为安全停止策略：

1. 根据前向距离和相对运动趋势限速。
2. 进入制动阈值后发送刹停指令。
3. 稳定后保持悬停。
4. 上报障碍物、距离、画面方位和原任务状态。
5. 等待危险解除、地面站指令或遥控器接管。

V1 不自动选择左右绕行方向。危险解除并重新验证数据后，可回到进入本状态前的 `GPS_APPROACH`、`VISUAL_TRACKING` 或 `RETURN_HOME`。恢复不是简单跳回旧状态，必须重新检查对应入口条件。

后续升级只替换避障策略，例如视觉可通行区域、单目深度、扫描测距或路径规划，不修改任务状态机。

### S9 INTERCEPT_READY

- 检查目标锁定质量、相对状态、飞行稳定性和执行机构就绪状态。
- 检查动力电池和算力板电池能力；算力板电池硬件未完成前按照配置采取保守策略。
- `IInterceptionAuthorizationPolicy` 支持自动授权和地面站确认两种实现。
- V1 默认允许采用自动授权，但保留地面站确认模式。
- 条件满足后进入 `INTERCEPT_EXECUTING`；条件失效返回 `VISUAL_TRACKING`。
- **V1 入口判据（2026-10-19 落地，`interception` 配置节）**：`enabled=true`、
  视觉状态新鲜且 `LOCKED`、连续锁定帧 ≥ `lock_frames`、测距有效且新鲜并落在
  `[min_range_m, max_range_m]`、PX4 `connected+armed+Offboard(6/0)`、姿态/局部位置
  有效、命令窄接口已注入、执行器未触发且 `Ready()`（无进行中的保持/复位时序）、
  任务未进入 S16。`auto_authorize=true` 时
  S9→S10；false 时等待地面站授权（协议未实现），超 `authorization_timeout_ms`
  按设计返航。S9 条件失效回 S7；S9/S10 期间继续输出视觉伺服意图保持瞄准。
  默认 `enabled=false`；测距窗口上限已于 2026-10-23 冻结为双目测距极限 **8m**
  （进入 ≤8m 才算有效射程；发射方向与机头一致），下限 2.0 仍为占位、待实机最小
  可用距离确认；现场本地副本开启前还须确认授权策略。可选电池门限
  `min_battery_percent` 当前保持 **0（不启用）**，待实机测出悬停/巡航耗电与返航
  降落储备后再冻结。

### S10 INTERCEPT_EXECUTING

- 通过 `IInterceptionDevice` 调用具体执行机构。
- 状态机只关心未提供、未就绪、执行中、成功、失败、已使用和故障等通用状态。
- 具体捕网或其他手段不进入状态机实现。
- 完成或失败后均进入 `POST_INTERCEPT`。
- **V1 实施口径（Task 5，2026-10-21）**：状态机每决策拍调用
  `INetActuator::Update(ActuatorFeedback)`，执行器内部推进 ACK 确认 → 触发保持
  （`reset_delay`）→ 复位行程 → 复位稳定（`reset_settle`）→ `Ready`。S10 内
  `Trigger()` 只调一次：**无飞行快照不触发**（无连接证据），快照 `connected=false`
  → S16；入队失败下拍重试，超过 `fire_timeout` → S16。**触发命令入队
  （`Fired()`）即进入 S11，不等发射 ACK**。复位由执行器在触发 ACK 后自主计时，
  不再由“离开拦截序列”触发（未触发即离开不发任何命令）。

### S11 POST_INTERCEPT

- 记录拦截结果、目标状态、执行机构剩余能力和系统健康。
- `IPostInterceptionPolicy` 保留自动返航、自动继续和地面站决定三种策略。
- V1 默认策略为拦截结束后返回 Home。
- 没有目标、执行机构不可用、电量不足或关键能力异常时必须返回。
- **V1 单发口径**：触发命令入队成功（`Fired()`）即视为拦截动作结束，**不判断命中**；只记录“已发射/未发射”，随后返航。发射入队超时、ACK 超时/非 ACCEPTED 或断连属故障，进入 S16，不再按“失败返航”处理。详见本节末「S11~S14 V1 实施口径」。

### S12 RETURN_HOME

- 使用 PX4 上报且经验证有效的 Home 点；算力板没有独立 GPS。
- 正常情况下由算力板规划返回过程并持续向 PX4 发送控制设定值。
- 摄像头、光流和双目深度在返航时按能力继续运行。
- V1 遇到障碍物进入 `OBSTACLE_HOLD`，等待人工处置或危险解除，不自动绕行。（**本期暂缓**：无避障事件源，返航遇障由 PX4 后备与人工接管兜底，2026-10-12）
- 到达 Home 附近并满足降落条件后进入 `LANDING`。
- 算力板、控制程序或飞控串口完全失效时，无法继续由算力板控制，此时依赖 PX4 配置的 Offboard 丢失保护执行后备 RTL 或其他安全动作。
- **V1 实施口径**：不使用 PX4 自动 RTL；Home 局部 NED 由 Home 经纬度 + EKF 锚点换算，速度由 PX4 限速参数约束；返航高度/到达半径/降落指令见本节末「S11~S14 V1 实施口径」。

### S13 LANDING

- 算力板正常时控制降落，持续检查高度、垂直速度和 landed 状态。
- 确认落地后请求上锁。
- 只有 PX4 确认 disarmed 后才能进入 `DISARMED`。
- **V1 口径**：使用 PX4 `AUTO.LAND` 降落指令，不计算力板下降控制；确认 landed 后若仍 armed，发 DISARM；确认 disarmed 后进入 `DISARMED`。

### S14 DISARMED

- 上报任务结束、拦截结果和故障摘要。
- V1 一次上电任务默认只执行一次拦截，不能自动回到 `READY`。
- 如后续支持第二次任务，必须新增显式复位、自检和执行机构恢复流程。

### S11~S14 V1 实施口径（2026-10-19 定案）

V1 仅单发捕网；多发成功判据与再交战策略留 V2（`IPostInterceptionPolicy` 保留）。

1. **完成判据**：S10 触发命令入队成功（执行器 `Fired()`，不等 ACK），即视为拦截动作结束；**不判断命中**。S11 只记录“已发射/未发射”，随后进入 S12。摄像头继续运行，只用于记录/目标状态诊断，**不参与返航判断**。发射入队超时/执行器 ACK 故障/断连 → S16（见 S16 节），不走返航。
2. **返航方式**：算力板位置设定值飞回 Home，**不使用 PX4 自动 RTL**。Home 局部 NED 由 Home 经纬度（`HOME_POSITION`）+ EKF 锚点（`GPS_GLOBAL_ORIGIN`）换算（`GeodeticToLocalNed`）；`HOME_POSITION.x/y/z` 作为交叉校验/诊断。返航速度由 PX4 `MPC_XY_VEL_MAX` 约束，V1 不另做速度环（巡航近似恒速，末端自然减速）。
3. **返航高度**：相对 Home 高度 `<5m` 时，先在当前位置原地爬升到 5m，再水平返航；`≥5m` 时保持当前高度返航。
4. **到达判据**：水平距 Home `≤2.0m`、垂直误差 `≤0.5m`、水平速度 `≤0.5m/s` 持续 `1s`；超时 `60s` 转失败处理（悬停告警/地面站或人工处置）。
5. **降落**：到达后发 `MAV_CMD_DO_SET_MODE`（AUTO.LAND，4/6），立即停止位置设定值；等待 PX4 `landed`；若仍 armed，发 `MAV_CMD_COMPONENT_ARM_DISARM`（0）请求上锁；确认 `disarmed` 后进入 S14。
6. **Home/锚点无效**：原地悬停并告警，等待 Home/锚点恢复后继续；超时/低电由地面站/人工处置，或按 PX4 已配置的 failsafe 执行。V1 不在无 Home 基准时盲目返航。
7. **控制权监控**：每拍核对 PX4 `flight_mode`；离开 Offboard、进入 RTL/LAND、人工接管或 failsafe 时立即停止设定值并记录，不与 PX4 争控制权。
8. **边界**：S9/S10 入口判据已按 `interception` 配置节落地（默认 **关闭**；测距窗口上限已于 2026-10-23 冻结为双目测距极限 8m，下限仍占位，现场本地副本开启前还须确认授权策略）；验收通过测试钩子/独立装配工具驱动。**SITL 返航专项（`--sitl-stage4-return`）2026-10-19 已全 PASS**（S7→S9→S10→S12→S13→S14；证据 `tools/return_evidence/`）。`MissionStatus` 的任务结果字段暂不新增（先用状态+日志），协议扩展另行评审；多发命中判据/再交战策略 V2。

### S15 MANUAL_OVERRIDE

- 检测到遥控器接管后停止正常任务设定值，避免与人工控制冲突。
- 保存接管前状态和原因，但不得未经重新验证直接恢复。
- 恢复自动控制需要明确操作，并重新检查 PX4 模式、位置、Home、目标数据和障碍物状态。

### S16 FAILSAFE

算力板仍在工作且 PX4 链路可用时，可根据错误执行悬停、受控返航或降落。若算力板或链路已经完全失效，安全动作只能由 PX4 自身执行。

**V1 最小实现（Task 5，2026-10-21）**：捕网执行器故障（187 ACK 超时 / 非 ACCEPTED /
PX4 断连）与 S10 触发命令入队超时统一走 `HandleMissionFault()`：置
`MissionStatus.active_warning_bits` bit4「捕网执行器 ACK 故障」、调用
`IPx4CommandSender::CancelPendingCommands()` 恰好一次、打一条 ERROR、迁移 S16。
此后状态机每拍只维护告警位与状态发布，**停发位置/伺服/返航/降落一切控制意图**；
不重试、不补发复位（机构停在原位，交 PX4/遥控/人工处置）。故障为终态，需重启
程序复位 `mission_faulted_`。S16 的“算力板主动悬停/返航”策略不在 V1 自动执行——
PX4 在 Offboard 设定值停发后按自身 failsafe（`COM_OF_LOSS_T`）接管。

PX4 1.17.0 Offboard setpoint 丢失已完成源码核实和 SITL 验证：`COM_OF_LOSS_T=1s`，无人工控制信号时应用在1270ms后观测到6/0→4/5 AUTO/RTL；`COM_OBL_RC_ACT=0`先请求Position，再由PX4可运行性回退链选择RTL。遥控器接管/失联、数据链完全中断和真实硬件RTL仍必须继续经过台架与受控实飞确认，不能仅依赖SITL。

## 6.1 地面站直控发射（GcsNetFire，2026-10-23）

与任务状态机**并行的独立执行通道**，用于拆桨台架/测试中由地面站直接触发一次
捕网发射（65016 指令 / 65017 回执），不经过任务授权链、不产生 `ControlIntent`、
不改变任务状态：

- 门禁（任一不满足即 `REJECTED` + 原因码）：协议版本 → 确认位 → 指令滞留 →
  飞行状态新鲜（≤1s 且 `landed_state_valid`）→ **未解锁** → **已落地** →
  执行器 Ready/未故障/有剩余发数 → 冷却（`actuator.gcs_fire_cooldown_ms`）；
- 执行：`INetActuator::Trigger()`（single_pwm，`DO_SET_ACTUATOR` 归一化量），
  20ms 节拍推进触发-保持 1.5s-复位时序；周期走完补发 `COMPLETED`，执行器终态
  故障补发 `REJECTED`+`ACTUATOR_FAULTED`；同一 `command_id` 只触发一次；
- 装配：仅 `actuator.gcs_fire_enabled=true`（默认 false）且 PX4 命令接口可用时
  创建；与 `interception.enabled` 互斥（同时为 true 加载期抛错），避免与 S10
  自动拦截抢同一机构；
- 细节见 [`include/state_machine/gcs_net_fire.md`](../include/state_machine/gcs_net_fire.md)。

## 7. 可替换策略

| 接口 | V1 实现 | 后续升级方向 |
|------|---------|--------------|
| `IObstacleAvoidanceStrategy` | 减速、刹停、悬停 | 视觉绕行、深度感知、路径规划 |
| `ITargetLostStrategy` | 短时预测、GPS 校验、整机转向搜索 | 云台搜索、多模型跟踪 |
| `IReturnStrategy` | 算力板控制返回 PX4 Home | 带地图或局部规划的返航 |
| `IInterceptionAuthorizationPolicy` | 自动或地面站确认 | 分级授权规则 |
| `IPostInterceptionPolicy` | V1 默认返航 | 自动继续或地面站决策 |
| `IInterceptionDevice` | 通用占位实现 | 捕网或其他设备适配器 |

## 8. 待定参数

以下参数必须配置化，并在仿真和实机测试后确定：

- 视觉稳定锁定帧数、置信度和数据超时。
- 位置到速度控制切换的位置误差和速度阈值。
- 卡尔曼预测上限、搜索时间和 GPS 目标有效期。
- 双目深度有效距离、质量、减速、制动、解除阈值及滤波参数。
- 起飞、跟踪、返航的速度、加速度和距离限制。
- 地面站、PX4、双目摄像头图像/深度和图传链路超时。
- PX4 1.17.0 的 RC 接管/失联、数据链完全中断和真实硬件 RTL 参数；Offboard setpoint 丢失参数与无 RC SITL 行为已确认。
