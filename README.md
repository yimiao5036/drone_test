# drone_test

这是一个反无人机的项目。当前阶段使用 C++，编写一个运行在香橙派算力板上的控制系统。

## 硬件平台

- **算力板**：香橙派，芯片 RK3588
- **目标识别**：YOLOv26

## 功能

算力板上的主要功能是进行目标识别和控制无人机。系统接收地面站发送的目标无人机位置信息，预测目标轨迹后，指引 PX4 无人机在机载模式下飞向目标。

## 硬件连接与通信

- **算力板与 PX4**：通过串口通信。
- **算力板与地面站**：通过电台进行数传。
- **算力板与摄像头**：通过 RJ45（网口）连接，获取画面。
- **算力板与激光测距雷达**：通过串口连接。
- **算力板与图传模块**：通过另一个网口，走 RJ45 连接。

## 目标识别

使用 YOLOv26 进行目标识别，识别后的画面通过图传发回地面站。

## 系统架构设计

### 设计思路

借鉴 PX4、ROS2 等开源项目的设计思想，采用**线程 + 消息队列**的解耦架构：

- 每条物理链路一个独立线程，互不阻塞。
- 图像数据通过内存池传递，不进行拷贝，减少性能开销。YOLO 推理速度快于摄像头采集速度，内存池不会积压，无需丢帧策略。
- 线程之间通过消息队列或通知机制传递数据，实现模块解耦。
- 各模块可独立编译、独立测试。

### 线程模型（7 个线程）

| 线程 | 职责 | 数据流 |
|------|------|--------|
| 摄像头采集线程 | 通过网口从摄像头采集原始画面，写入内存池 A，通知 YOLO 线程 | 单向输出 |
| YOLO 识别线程 | 从内存池 A 取画面进行目标识别，识别结果发给控制线程；将识别后画框的图像写入内存池 B，通知图传发送线程 | 单向输出 |
| 图传发送线程 | 从内存池 B 取识别后的图像，通过另一个网口发送给图传模块 | 单向输出 |
| PX4 串口通信线程 | 与 PX4 飞控进行 MAVLink 协议通信（心跳、姿态、指令收发） | 双向 |
| 电台数传线程 | 与地面站进行 MAVLink 协议通信（接收目标位置、回传状态） | 双向 |
| 激光测距雷达线程 | 通过串口持续读取距离数据 | 单向读取 |
| 状态机与控制线程 | 消费各线程产出的数据，进行目标轨迹预测和状态机决策，生成 MAVLink 控制指令投递给 PX4 线程发送 | 核心逻辑 |

### MAVLink 库

MAVLink 库放于 `third_party/mavlink/`，CMakeLists.txt 自动检测并使用。

### 消息流

```
摄像头 --(网口)--> [摄像头采集线程] --(内存池A)--> [YOLO识别线程]
                                                       |
                                        识别结果 --> [状态机与控制线程]
                                                       |
                                            --(内存池B)--> [图传发送线程] --(网口)--> 图传模块 --> 地面站

地面站 --(电台/MAVLink)--> [电台数传线程] --(目标位置)--> [状态机与控制线程]

[激光测距雷达线程] --(距离数据)--> [状态机与控制线程]

[PX4 串口通信线程] <--(MAVLink 指令)--> [状态机与控制线程]
[PX4 串口通信线程] <--(串口/MAVLink)--> PX4 飞控
```

### 状态机

系统包含状态机，用于管理整体系统状态。状态机为自主实现，状态流转如下：

1. **上电自检**：检查 PX4、地面站、摄像头、图传、激光测距雷达是否正常。
2. **加载模型**：加载 YOLOv26 模型。
3. **解锁**：飞控解锁。
4. **起飞爬升**：原地起飞，达到目标高度。
5. **地面站引导**：进入机载模式，依赖地面站通过电台下发的目标位置来引导飞行，激光测距雷达用于避障。
6. **视觉跟踪**：摄像头捕捉并识别到目标后，地面站引导退为辅助，以摄像头和激光测距雷达为主进行跟踪。
7. **反制**（预留）：锁定目标后执行干扰、撞击、捕网等操作。
8. **成功/失败**：任务结束，返航降落。
9. **失控保护**：运行中任意关键链路异常时触发，执行保护策略。

电量检测功能后续预留。
