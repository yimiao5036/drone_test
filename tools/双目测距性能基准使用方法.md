# 双目测距性能基准使用方法

> 适用对象：在开发机或香橙派（RK3588）上定位 `StereoRanger` 单帧耗时、验证优化效果的维护者。
> 本文只讲**怎么跑、怎么判读**；算法语义与实现细节见
> [stereo_ranger 实现文档](../include/perception/stereo_ranger.md)，
> 相关约定（诊断开关、判读思路）参照 [NPU 性能分析探针使用方法](NPU性能分析探针使用方法.md)。

## 1. 功能职责与边界

`stereo_ranger_bench` 是**离线基准**：用真实预置校正矩阵 + 合成高清纹理图
（1280×720，全幅，`aux = ref` 按列整体位移）复现标准目标负载，输出
`StereoRangerCore` 五个阶段的 avg/p95/max 耗时：

| 阶段 | 内容 |
|---|---|
| remap | 行带立体校正 remap（双目）+ 黑帧检查 |
| census | Census 7×7 变换（双目） |
| 提点 | 掩膜 + Shi-Tomasi + 网格取点 |
| 匹配 | 粗/精搜索 + 抛物线亚像素 + 唯一性 + 左右一致性 |
| 聚合 | 逐框近端簇聚合 + EMA |

**边界**：不碰摄像头/解码/NPU/图传，也不测端到端延迟（那是
`video_latency_probe` 的职责）；合成图只覆盖"匹配负载"，不代表真实场景纹理。

## 2. 使用前提

- 板上运行前**先停止正式 `drone_control`**：基准吃满一个 CPU 核，同时跑会互相
  抢占、污染彼此数据；
- 板上需已 `cmake --build build` 过（矩阵随 `config/` 同步到 `build/config/`）；
- 正式程序侧的阶段耗时不依赖本工具（见第 4 节）。

## 3. 使用方法

### 3.1 默认：标准负载（400×380 框，30 次迭代）

```bash
./build/stereo_ranger_bench              # 30 次
./build/stereo_ranger_bench 60           # 60 次（更稳）
./build/stereo_ranger_bench 30 440 170 840 550   # 自定义框 x0 y0 x1 y1
```

输出示例（开发机 x86）：

```text
双目测距基准: 视差=[8,160]px 框=400x380 迭代=30 诊断统计=开（开发机 x86 数字，板上约为 1/2~1/4）
总计: 14.13ms/帧 (70.7 fps)，有效帧 30/30
阶段耗时（滚动窗口）:
  remap : avg=3.67ms p95=4.07ms max=4.43ms
  ...
```

### 3.2 A/B：诊断开销对照 `--no-stats`

```bash
./build/stereo_ranger_bench 60 --no-stats
```

关闭阶段统计与逐点快照（= 生产默认），用于量"诊断本身的开销"。开发机实测
（开/关各 3 轮、每轮 60 帧）差值在 ±0.5ms 轮间噪声内，**当前诊断开销量不出来**；
该开关的意义是遵守"生产热路径零诊断"约定、并为后续更重的诊断留闸门。

### 3.3 对照开发机与板上

同一命令在两边各跑一次，按**阶段占比**判断优化方向；绝对值参考：
香橙派 ≈ 开发机的 2~3 倍（2026-10-10 实测 2.8×，早期按 1.5× 估算偏差较大）。

## 4. 实时链路侧：摘要日志的阶段行

正式程序不依赖本工具，直接看组件摘要（`stereo_ranger` 段配置
`collect_detailed_latency=true`，开发阶段默认开，生产调优定型后置 false）：

```text
双目测距摘要: 帧=370 匹配帧=355 批次=370 发布=370 有效测距=355 有效占比=95.9%
  距离 min/avg/max=0.800/0.922/1.103m 跳过=15 帧未配=0 截断=0 处理avg=40.21ms max=120.86ms
双目测距阶段耗时 avg/p95(ms,n=355): remap=14.1/24.2 census=14.6/20.5 提点=9.9/13.8 匹配=3.6/4.4 聚合=0.0/0.0
```

判读顺序：先看「帧未配」（应为 0；有值说明处理跟不上、帧被挤出）→ 再看
「有效占比」（目标纹理/量程/标定）→ 最后看阶段占比定优化方向。

## 5. 已实测基线（2026-10-10，400×380 框；按需复测，勿重复消耗时间）

| 阶段 | 开发机（x86） | 香橙派（合成基准） | 香橙派（真实链路） |
|---|---:|---:|---:|
| remap | 3.7ms | 7.8ms | 14.1ms |
| census | 4.5ms | 13.8ms | 14.6ms |
| 提点 | 4.7ms | 14.3ms | 9.9ms |
| 匹配 | 1.6ms | 3.8ms | 3.6ms |
| **总计** | **14.1ms** | **39.6ms** | **≈40ms** |

要点：

- 真实链路的 remap 约为合成基准的 1.8 倍（合成图重复读、缓存热；真实帧每次
  读新相机帧 1280×720×2、冷缓存）——**以真实链路数字为准**；
- 优化前基线：开发机 107.2ms/帧、板上真实链路 ≈165ms/帧 且 10 秒窗口
  `帧未配≈39`（约 20% 帧被挤出）；优化后 `帧未配=0`、有效占比 71.7%→95.9%；
- 优化手段与推导见 [stereo_ranger 实现文档](../include/perception/stereo_ranger.md)
  「行带 + 列裁剪」「热路径性能」两节与设计文档 §4。

## 6. 判读指南：阶段占比 → 结论方向

| 现象 | 结论方向 | 下一步 |
|---|---|---|
| census 占比最高（板上 ≈37%） | 标量位运算型，ARM 无 x86 的宽 SIMD 优势 | `uint8` 批量比较（NEON `vcgtq`）+ 按字节 popcount |
| remap 占比高且真实链路 ≫ 合成基准 | 内存带宽型（每帧 2×1280×720 双线性读） | 评估 RGA 查表模式，或按 `disp_max` 收窄列范围/半分辨率 |
| 提点占比高 | Sobel+积分图+特征值，随带面积线性 | 行带分区多线程（A76 大核 4 路）；或进一步收窄掩膜区域 |
| 匹配占比高 | 候选数 × 点数 × 窗口的乘性负载 | 用 `coarse_stride`/`fine_halfwidth` 权衡（改语义，需重新对拍黄金值） |
| 总计高但各阶段之和远小于总计 | 统计外开销（分配/锁/调度） | 查复用缓冲是否生效、是否与其它线程抢核 |
| `帧未配` 增长 | 处理慢于帧率，帧被挤出缓冲 | 提升单帧速度，或加大 `frame_buffer_depth`（受拆分器池容量约束） |

## 7. 注意事项

- 基准与 `drone_control` **不要同时跑**；板上其它重负载（推流、浏览器拉流）也会
  影响数字，比较时保持环境一致；
- 前 3 帧为预热（缓存/TLB），不计入；单次 30 帧的 p95 抽样噪声较大，改结论
  建议 ≥60 帧；
- 最慢帧（max）常见于首个有效帧或系统调度抖动，看 p95 更有代表性；
- 诊断开关（`stereo_ranger.collect_detailed_latency`）只影响日志与快照，关掉后
  测距结果不变（有专门用例守住）。
