# 相机标定工具（tools/camera_calibration）

> 设计依据：`docs/superpowers/specs/2026-09-22-相机内参标定-design.md`
> 平台：Windows 开发机（Python 3.11+ / OpenCV 5.x，需 `pip install opencv-python numpy`）
> 对象：USB 双目模组（23H1328889HV1），采集档位与生产链路一致 2560×720@30 MJPG

## 用途

一次采集产出：左目内参+畸变、右目内参+畸变、左右目旋转平移 R/T（立体外参）。
对接下游：

- `visual_track_control` 的 camera 组占位值（FOV 由标定 JSON 直接回填）；
- 双目测距 v1.0 立体校正的全部输入（《双目深度估计思路.md》§3.1）。

## 三步流程

### 1. 生成并打印标定板

```powershell
chcp 65001   # 控制台切 UTF-8，否则中文输出乱码（Windows Terminal 可跳过）
python tools/camera_calibration/generate_charuco_board.py
```

- 默认 ChArUco 11×8 格、格子 22mm、标记 16mm、DICT_5X5_1000，A4 横放可容纳；
- **打印必须选"实际大小/100%"，打印后用尺子实测格子边长**，后续 `--square-mm`
  一律填实测值——打印缩放是标定误差的最大来源；
- 贴平到硬质平板（KT 板/亚克力板），不能有褶皱。

### 2. 采集（双目模组插 Windows USB）

```powershell
python tools/camera_calibration/capture_stereo_charuco.py --camera 0 --square-mm 22.3
```

- 预览窗口左右分屏（左目绿点、右目蓝点叠加角点），顶部显示已采对数与分区覆盖；
- **空格**采一对（左右目同帧都检出 ≥6 角点才落盘）；**Enter** 结束；**Esc** 放弃；
- 采集要求：目标 **~25 对**，覆盖：
  - 画面 3×3 全部 9 个分区（板子移到画面四角和边缘）；
  - 远（板占画面 1/4）/ 中（1/2）/ 近（3/4）三档距离；
  - 板面相对镜头各方向倾斜 ±30° 以内（俯仰/偏航/翻滚都要有）；
  - 每对保持板子静止半秒再按空格（运动模糊是常见废片原因）。

### 3. 标定（离线，可反复重跑）

```powershell
python tools/camera_calibration/calibrate_stereo.py                 # 自动取最新会话
python tools/camera_calibration/calibrate_stereo.py --session captures/20260922_170000
python tools/camera_calibration/calibrate_stereo.py --exclude left_003 right_007
```

输出（均在会话目录）：

- `calibration.json`：内参/畸变/R/T/RMS/FOV/板参数/分辨率/日期/OpenCV 版本；
- `rectified_preview.png`：校正后左右拼图 + 水平绿线，**目视检查同名点是否落在
  同一水平线上**（极线对齐是立体标定正确的直接判据）。

## 验收阈值

| 指标 | 通过 | 优 |
|---|---|---|
| 单目 RMS（左/右） | < 1.0 px | < 0.5 px |
| 立体 RMS | < 1.0 px | < 0.5 px |
| 基线 \|T\| | 与标称 60mm 偏差 ≤10% | ≤5% |
| 校正拼图 | 同名点在同一水平线上 | — |

不达标时按控制台列出的"复投影误差最大 3 对"剔除重跑；仍不达标则补采
（重点补姿态多样性与画面边缘分区）。

## 排障

| 现象 | 排查方向 |
|---|---|
| 控制台中文乱码 | 先 `chcp 65001`；或换 Windows Terminal |
| 采集显示"已采 N 对"但目录只有 meta.json | 已修复（2026-09-23）：cv2.imwrite/imread 不支持中文绝对路径会静默失败，三个脚本已全部改用 imencode/imdecode 安全 IO，且写失败会立即报错终止；请勿用旧版本采集 |
| 摄像头打不开/档位不符 | 脚本会自动尝试 DSHOW/MSMF × fourcc 先后共 4 种协商方式；仍失败会列出该设备各后端实际支持的档位与其他设备号。若只支持 3840×1080，用 `--width 3840 --height 1080` 采集（内参与 2560×720 档位不通用）；确认模组直插 USB（勿经 Hub） |
| 不确定哪个设备号是双目模组 | 先随便跑一轮看预览：双目模组画面是左右拼接的两个相似画面；或用失败时打印的各设备支持档位区分（模组支持 2560×720/3840×1080 SBS 档位） |
| 空格不落盘 | 看预览顶部 L=/R= 角点计数，哪一目不足就调整板子让其入画 |
| 标定被拒绝（<10 对） | 补采；采集脚本的 meta.json 里记录了实际对数 |
| 基线偏差 >10% 告警 | 90% 是 `--square-mm` 没按打印实测填；其次采集质量 |
| 立体标定样本不足 | 采集时板子需同时出现在左右两目画面（别离镜头太近导致右目出画） |

## 合成冒烟（改动标定代码后必跑）

```powershell
python tools/camera_calibration/synthetic_smoke.py %TEMP%\calib_smoke
```

虚拟双目（fx=900、基线 60mm）渲染 15 组板图跑全管线，恢复值应与真值吻合
（fx 误差 <1px、基线 <1mm、RMS <0.2px），退出码 0。仅验证管线/API 兼容，
不代表实机精度。

## 注意

- `captures/` 已 gitignore（图片体积大）；`calibration.json` 标定结果请另行归档
  （后续板上加载任务会定义正式存放位置）；
- 标定只对采集时的分辨率档位有效：换档位（如 3840×1080）需重新标定或按比例换算
  （fx/fy/cx/cy 随分辨率线性缩放，畸变系数不变——但优先重新标定）。
