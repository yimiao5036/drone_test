# 正式主程序配置管理

## 功能职责

`config::LoadAppConfig()`集中解析正式`drone_control`所需的日志、运行模块开关、HealthManager阈值、视频、YOLO、PX4、地面站数传、单目标估计器和视觉稳定性判定配置，生成强类型`AppConfig`。本模块不打开设备、不启动线程，也不解析地面站业务协议。

## 接口与数据流

```cpp
std::string ResolveConfigPath(const std::string& executable_directory,
                              const std::string& requested_path = {});
AppConfig LoadAppConfig(const std::string& path,
                        const std::string& executable_directory);
```

查找顺序：显式`--config`路径；否则可执行文件旁`config/config.json`；最后当前目录`./config/config.json`。模型等相对资源路径按可执行文件目录解析。

## 关键实现点

- PX4配置与`Px4LinkConfig::Validate()`使用同一类型和校验规则，PX4链路身份在`px4`节内独立声明，当前保持`1/191 → 1/1`；
- 阶段四装配门禁（2026-10-13 起）：`enable_control=true`要求`enable_px4`与`enable_ground_station`同时启用（状态机意图/目标来源），且`controller`节无条件`Validate()`——非法即加载期fail-fast；满足前置即允许加载，正式绑定由`DroneApplication`装配门禁执行。仓库生产`config.json`永远保持`false`，打开只发生在现场部署目录本地副本；
- 地面站链路需要PX4状态源，因此`enable_ground_station=true`时必须同时启用PX4；`enable_target_estimator=true`进一步要求PX4和地面站均启用；`enable_visual_monitor=true`要求视频链路启用（观测来源为YoloDetector）；`enable_visual_tracking=true`要求视频链路+视觉稳定性判定；`enable_stereo_ranging=true`要求视频链路+camera_source=uvc+stereo_split+视觉跟踪影子；`enable_visual_position_fusion=true`（2026-10-12 新增）要求目标估计器+双目测距+PX4同时启用；
- 地面站串口、MAVLink版本、飞机二元身份、地面站来源身份、心跳周期、TIMESYNC采样/超时/窗口参数和各类遥测发送周期均由JSON配置；捕网-01 HM30第一版TIMESYNC门限为`max_rtt_ms=300`、`max_offset_jump_ms=100`；
- `video.output_rtsp`支持身份占位符`{aircraft_component_id}`、`{aircraft_system_id}`和`{aircraft_number}`；生产配置按`component:system`二元键生成图传路径，捕网-01解析为`rtsp://127.0.0.1:8554/drone_25_1`；
- `video.prefer_rga_dma_transfer`控制解码后DRM PRIME DMA-BUF是否优先经RGA直传`VideoFramePool`。字段缺省为false；经600秒实机验证后当前生产配置设为true，RGA不可用/布局不支持/复制失败仍自动回退FFmpeg转存；
- `yolo.input_queue_capacity`控制解码帧待推理队列。容量2→1实测只损失约1.3%处理帧，却显著降低P99/最大帧龄，因此生产配置现设为1，采用丢旧留新的最新帧策略；
- `yolo.npu_core_mode`支持`auto/core0/core01/core012/all`，生产当前为`all`；探针可用`--npu-core`临时覆盖做同一模型A/B，非法值在配置加载期拒绝；
- `yolo.collect_npu_internal_perf`控制`RKNN_QUERY_PERF_RUN`诊断，生产固定为`false`；探针通过`--rknn-perf-run`临时启用，避免正式热路径常驻查询；
- `yolo.collect_npu_perf_detail`控制一次性`RKNN_QUERY_PERF_DETAIL`逐层报告，生产固定为`false`；启用后初始化带`RKNN_FLAG_COLLECT_PERF_MASK`并会降低帧率，只能用于独占探针诊断；
- 至少启用视频、PX4或地面站中的一个数据链路；
- 当前生产配置启用视频、PX4、地面站、单目标估计、视觉稳定性判定、视觉跟踪影子、双目测距与视觉融合影子链路，控制保持关闭；
- `visual_monitor`节配置观测订阅队列、100ms影子发布周期、观测超时、锁定/丢失帧数和平滑系数；`smoothing_alpha`必须在`(0,1]`，其余必须为正数；门限为影子初值，需实拍视频复核；
- `target_estimator`节配置订阅队列、100ms影子发布周期、恒速度滤波过程加速度噪声、初始速度不确定度、速度观测噪声、缺省水平/垂直精度，以及 `min_velocity_position_updates`（P3 速度前馈 KF 回退门限，默认 5，必须为正）；其余数值必须为有限正数。当前数值是录制数据整定前的影子初值，不得作为开放控制的依据。`target_estimator.visual`子组（2026-10-12）配置视觉融合：订阅队列、观测/快照超龄门限、视差σ（disparity_std_px）、置信度下限与相机安装外参 mount_*（默认全0=准直假设，未标定）；fxb_m_px 不出现在 JSON，由装配期从双目校正矩阵拷贝；

- `takeoff`节（2026-10-22，多机任务分配与自动起飞）配置 S3 解锁/Offboard、
  S4 自动爬升、到达判据与目标收口，全部可选、缺席回退默认值：

  | 字段 | 类型 | 默认 | 校验 |
  |---|---|---|---|
  | `height_m` | double | 2.0 | 有限且>0（相对起飞点爬升高度） |
  | `climb_rate_mps` | double | 0.5 | 有限且>0（S4 爬升速度） |
  | `bootstrap_lead_ms` | 毫秒 | 300 | ≥0（起飞意图到 176 的前置保持） |
  | `mode_timeout_ms` | 毫秒 | 2000 | >0（等待 Offboard 6/0 的超时） |
  | `arm_timeout_ms` | 毫秒 | 3000 | >0（等待解锁的超时） |
  | `bootstrap_timeout_ms` | 毫秒 | 6000 | >0，且 > `bootstrap_lead_ms + mode_timeout_ms + arm_timeout_ms` |
  | `height_timeout_ms` | 毫秒 | 15000 | >0（S4 到达任务高度超时） |
  | `stable_time_ms` | 毫秒 | 1000 | >0（到达判据持续时长） |
  | `z_tolerance_m` | double | 0.2 | 有限且≥0（到达判据垂直误差） |
  | `xy_tolerance_m` | double | 0.5 | 有限且≥0（到达判据水平误差） |
  | `max_vz_mps` | double | 0.3 | 有限且≥0（到达判据垂直速度） |
  | `target_wait_timeout_ms` | 毫秒 | 10000 | >0（等待目标位置超时） |
  | `target_lost_timeout_ms` | 毫秒 | 10000 | >0（目标丢失收口超时） |
  | `target_hold_max_ms` | 毫秒 | 60000 | >0（目标失效原地保持累计上限，超限中止返航） |
  | `battery_low_debounce_ms` | 毫秒 | 1000 | ≥0（低电防抖时长） |

  **目标保持累计上限（2026-10-22）**：S5 目标失效期间机载发“原地保持”意图
  （目标=PX4 当前位置，原因码 9），目标反复闪烁会不断清零
  `target_lost_timeout_ms` 计时；`target_hold_max_ms` 按本次 S5 **累计保持
  时长**收口，超限 → 65015 aborted（已获得目标按 `target_lost`，从未获得按
  `target_wait_timeout`）→ S12。默认 60000ms 是“容忍短时丢失”与“不允许无限
  悬停”的折中，按场地/任务时长调整。

  **无本地电量百分比**：`takeoff` 节刻意没有 `min_battery_percent`；自动起飞的低电
  门限唯一来源是 PX4 `BAT_LOW_THR`（并要求 `COM_LOW_BAT_ACT=0`），由后续任务的
  电池守卫统一读取，机载不维护第二套百分比阈值。`interception.min_battery_percent`
  仍只服务 S9/S10，不用于自动起飞。

  跨字段校验：`bootstrap_timeout_ms` 必须大于前置保持、模式等待与解锁等待之和，
  保证 Bootstrap 原点保持流不会早于 Offboard/解锁流程超时失效；非法值在配置
  加载期抛 `std::invalid_argument`，不静默降级。

- `actuator`节（2026-10-13，阶段四控制接入 Task 10）配置捕网执行器；机载只保存
  Actuator Set N 与归一化控制量，**输出功能、对应 PWM 映射区间、舵机行程与方向在
  PX4/QGC 侧配置**。当前生产配置显式声明单发 `single_pwm`（2026-10-21 确认：
  捕网接 MAIN5，Output Function=`Peripheral via Actuator Set 1`，故
  `net_channel=1`；注意它不是物理通道号）：

  | 字段 | 类型 | 默认 | 校验 |
  |---|---|---|---|
  | `type` | string | `single_pwm` | 当前仅 `single_pwm`；后续多发通过工厂切换 |
  | `net_channel` | int | 1 | 1..6（PX4 Actuator Set N） |
  | `net_fire_norm` | double | -0.7 | 有限值且 ∈ [-1, 1]，≠ `net_idle_norm` |
  | `net_idle_norm` | double | 0.0 | 有限值且 ∈ [-1, 1] |
  | `reset_delay_ms` | 毫秒 | 1500 | ≥0（发射 ACK 后到发复位的保持时间） |
  | `reset_settle_ms` | 毫秒 | 0 | ≥0（复位 ACK 后到 Ready 的稳定时间；多发用，单发默认 0） |
  | `gcs_fire_enabled` | bool | false | 地面站直控发射（65016）开关；与 `interception.enabled` 互斥，同时为 true 加载期抛错 |
  | `gcs_fire_cooldown_ms` | 毫秒 | 3000 | 100..60000（两次成功直控发射的最小间隔，防地面站误连点） |

  `reset_delay_ms`/`reset_settle_ms` 为 ACK 复位时序（2026-10-21）：发射 ACK
  ACCEPTED 后保持 `reset_delay_ms` 再发复位，复位 ACK ACCEPTED 后再稳定
  `reset_settle_ms` 才回 Ready。当前捕网枪说明书要求 1~2s；`reset_delay_ms`
  超出 [1000,2000] 启动 WARN（不拒绝）。**2026-10-23 维护者确认：机构为舵机、
  纯 PWM 驱动（`DO_SET_ACTUATOR` 归一化量经 MAIN5 映射到 PWM），保持 1.5s 即
  生产冻结值，G4-3 不再承担“时序冻结”职责**。

  标准 PX4 `PWM_MAIN_MINn/MAXn=1000/2000µs` 映射下（AUX 输出为 `PWM_AUX_*`），
  `-0.7→1150µs`（发射）、`0.0→1500µs`（待机）；实际行程以 QGC 中 MAIN5 的
  `PWM_MAIN_MIN5/MAX5` 为准。状态机只依赖 `INetActuator` 抽象接口；多发实现通过
  `type` 在 `CreateNetActuator` 工厂接入，详见
  `include/state_machine/net_actuator.md`。**2026-10-23 维护者确认**：机构为舵机、
  纯 PWM 驱动，行程由上述归一化量→PWM 映射决定，发射方向与机头一致，有效射程
  = 双目测距极限 ≤8m，故 G4-3 的“行程/方向”专项台架取消，仅保留实机首次发射
  的有效性观察。

- `health.cpu_sample_period_ms`定义`/proc/stat` CPU负载采样周期，默认1000ms且必须为正数；`health.startup_grace_ms`定义首包启动宽限期，生产默认5000ms，避免视频硬解/NPU初始化期间误报全源超时；
- `health`配置节定义各数据源最大允许无数据时间：`camera_max_age_ms`、`decoder_max_age_ms`、`yolo_max_age_ms`、`video_max_age_ms`、`px4_max_age_ms`和`ground_station_max_age_ms`；缺省时使用代码中的安全默认值，显式提供的值必须为正数；
- `ground_station.status_send_interval_ms.health/mission`分别控制`HEALTH_STATUS`（65012）和`MISSION_STATUS`（65013）周期，默认1000ms/500ms；状态变化仍会立即发送；
- 不对缺失或非法关键配置静默使用可能危险的默认值。

### fence 节（多边形围栏，2026-10-29 增）

| 键 | 默认 | 语义 |
|---|---|---|
| `enabled` | **`true`**（2026-10-29 起） | 总开关。true 且无区域时按 `default_*` 以 Home 为中心生成默认区域并回读 65022；false 时仍接收 65018、仍判定并上报 65019（只是**不做动作**） |
| `zone_cache_path` | `"config/zone.json"` | 区域缓存路径，按配置文件目录解析（`ResolveAdjacentPath`）；空串=不缓存 |
| `report_period_ms` | `5000` | 65022 区域回读周期（机载 → 地面站）；收到新区域时立即额外发一次 |
| `default_half_side_m` | `100.0` | 机载默认区域半边长（米）；仅在 `enabled=true` 且无缓存/未收到 65018 时，以 Home 为中心生成方形区域 |
| `default_alt_min_m` / `default_alt_max_m` | `0.0` / `30.0` | 默认区域高度带（相对 Home；`alt_max_m=0` 表示不限） |
| `default_zone_id` / `default_version` | `1` / `1` | 默认区域标识；地面站下发新版本即覆盖 |
| `default_action` | `1` | 默认区域越界动作（0 保持/1 返航/2 降落） |
| `violation_debounce_ms` | `1500` | 连续越界多久才动作，吸收单帧抖动 |
| `boundary_margin_m` | `1.0` | 钳制时距边界保留的安全边距；同时拷贝给 `controller.fence_margin_m` |
| `boundary_warn_m` | `10.0` | 距边界小于该值上报 `near_boundary`（必须 ≥ margin） |
| `follow_zone_action` | `true` | true=用 65018 里的 per-zone 动作；false=统一用 `violation_action` |
| `violation_action` | `1` | 0=保持、1=返航、2=降落（`follow_zone_action=false` 时生效） |
| `status_period_ms` | `1000` | 65019 上报周期 |

`FenceConfig::Validate()` 强制：路径非空、防抖非负、两个距离有限非负且 warn ≥ margin、
上报周期 > 0、动作枚举 ≤ 2。解析后 `config.controller.fence_margin_m = fence.boundary_margin_m`，
控制器不自读 fence 节（`drone_control_core` 不依赖 `drone_config` 的 fence 语义）。

`default_*` 在 `Validate()` 之前经 `NormalizeFenceDefaults()` 归一化（2026-10-30 审查修复，
WARN 后继续启动）：`default_zone_id/default_version=0` → 1（否则 `EnsureDefaultFenceZone()`
永不生成区域、开机无围栏也不落盘）；`default_half_side_m` 非有限或 ≤0 → 100m
（否则默认区域退化成空多边形）；`default_alt_min/max` 非有限 → [0,30]，`alt_max>0` 且
min>max 时把下限回退 0（保留操作者给的上限），避免默认区域整段判越界；
`default_action` >2 → return。下发区域本身的几何校验（自交/零面积/重复点/高度带倒挂/
非法高度基准）在 `control::fence::ValidateZone()`，见 `include/control/fence_geometry.md`。

| `heading_mode` | `1` | 1=返航机头朝飞行方向（指向 Home），0=不指定航向（保持原机头平移） |
| `heading_rate_limit_dps` | `30.0` | 航向角速度上限 |
| `heading_accel_limit_dps2` | `60.0` | 航向角加速度上限（二阶限幅，避免阶跃） |

`ReturnHomeConfig::Validate()` 拒绝 `heading_mode > 1` 与非有限/非正的速率上限。
机头朝向是给后续超声避障预留的：传感器装在机头，必须朝飞行方向才有意义。
