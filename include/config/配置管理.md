# 正式主程序配置管理

## 功能职责

`config::LoadAppConfig()`集中解析正式`drone_control`所需的日志、运行模块开关、HealthManager阈值、视频、YOLO、PX4、地面站数传、单目标估计器和视觉稳定性判定配置，生成强类型`AppConfig`。本模块不打开设备、不启动线程，也不解析地面站业务协议。

## 接口与数据流

```cpp
std::string ResolveConfigPath(const std::string& executable_directory,
                              const std::string& requested_path = {});
AppConfig LoadAppConfig(const std::string& path,
                        const std::string& executable_directory);
```

查找顺序：显式`--config`路径；否则可执行文件旁`config/config.json`；最后当前目录`./config/config.json`。模型等相对资源路径按可执行文件目录解析。

## 关键实现点

- PX4配置与`Px4LinkConfig::Validate()`使用同一类型和校验规则，PX4链路身份在`px4`节内独立声明，当前保持`1/191 → 1/1`；
- 正式控制尚未装配，`enable_control=true`直接拒绝启动；
- 地面站链路需要PX4状态源，因此`enable_ground_station=true`时必须同时启用PX4；`enable_target_estimator=true`进一步要求PX4和地面站均启用；`enable_visual_monitor=true`要求视频链路启用（观测来源为YoloDetector）；
- 地面站串口、MAVLink版本、飞机二元身份、地面站来源身份、心跳周期、TIMESYNC采样/超时/窗口参数和各类遥测发送周期均由JSON配置；捕网-01 HM30第一版TIMESYNC门限为`max_rtt_ms=300`、`max_offset_jump_ms=100`；
- `video.output_rtsp`支持身份占位符`{aircraft_component_id}`、`{aircraft_system_id}`和`{aircraft_number}`；生产配置按`component:system`二元键生成图传路径，捕网-01解析为`rtsp://127.0.0.1:8554/drone_25_1`；
- `video.prefer_rga_dma_transfer`控制解码后DRM PRIME DMA-BUF是否优先经RGA直传`VideoFramePool`。字段缺省为false；经600秒实机验证后当前生产配置设为true，RGA不可用/布局不支持/复制失败仍自动回退FFmpeg转存；
- `yolo.input_queue_capacity`控制解码帧待推理队列。容量2→1实测只损失约1.3%处理帧，却显著降低P99/最大帧龄，因此生产配置现设为1，采用丢旧留新的最新帧策略；
- `yolo.npu_core_mode`支持`auto/core0/core01/core012/all`，生产当前为`all`；探针可用`--npu-core`临时覆盖做同一模型A/B，非法值在配置加载期拒绝；
- `yolo.collect_npu_internal_perf`控制`RKNN_QUERY_PERF_RUN`诊断，生产固定为`false`；探针通过`--rknn-perf-run`临时启用，避免正式热路径常驻查询；
- `yolo.collect_npu_perf_detail`控制一次性`RKNN_QUERY_PERF_DETAIL`逐层报告，生产固定为`false`；启用后初始化带`RKNN_FLAG_COLLECT_PERF_MASK`并会降低帧率，只能用于独占探针诊断；
- 至少启用视频、PX4或地面站中的一个数据链路；
- 当前生产配置启用视频、PX4、地面站、单目标估计和视觉稳定性判定影子链路，控制保持关闭；
- `visual_monitor`节配置观测订阅队列、100ms影子发布周期、观测超时、锁定/丢失帧数和平滑系数；`smoothing_alpha`必须在`(0,1]`，其余必须为正数；门限为影子初值，需实拍视频复核；
- `target_estimator`节配置订阅队列、100ms影子发布周期、恒速度滤波过程加速度噪声、初始速度不确定度、速度观测噪声以及缺省水平/垂直精度；所有值必须为有限正数。当前数值是录制数据整定前的影子初值，不得作为开放控制的依据；
- `health.cpu_sample_period_ms`定义`/proc/stat` CPU负载采样周期，默认1000ms且必须为正数；`health.startup_grace_ms`定义首包启动宽限期，生产默认5000ms，避免视频硬解/NPU初始化期间误报全源超时；
- `health`配置节定义各数据源最大允许无数据时间：`camera_max_age_ms`、`decoder_max_age_ms`、`yolo_max_age_ms`、`video_max_age_ms`、`px4_max_age_ms`和`ground_station_max_age_ms`；缺省时使用代码中的安全默认值，显式提供的值必须为正数；
- `ground_station.status_send_interval_ms.health/mission`分别控制`HEALTH_STATUS`（65012）和`MISSION_STATUS`（65013）周期，默认1000ms/500ms；状态变化仍会立即发送；
- 不对缺失或非法关键配置静默使用可能危险的默认值。

## 日志行为

配置模块本身不初始化日志。解析错误抛出异常，由`main.cpp`在控制台输出一次；成功加载后由主程序记录配置路径和日志等级。

## 测试方式

```bash
cmake -S . -B build
cmake --build build --target config_test -j$(nproc)
./build/config_test
```

覆盖生产配置解析、RGA DMA生产开关及缺省关闭行为、HealthManager阈值、目标估计器参数及依赖门禁、视觉稳定性判定参数及依赖门禁、模型相对路径、PX4身份独立性、地面站串口/发送周期、TIMESYNC参数与窗口关系、捕网/火箭二元身份、图传身份路径展开、预留component拒绝、类型与component不匹配、地面站来源身份、控制门禁、地面站缺少PX4状态源门禁和全部模块禁用校验。

## 排查/修改要点

- 新增JSON字段时同步修改`config/config.json`、`config.h`、`config.cpp`和本测试；
- 不在`main.cpp`或smoke中再次复制正式配置语义；后续应继续让工具复用本模块；
- 开放`enable_control`前必须先完成状态机、控制器、台架门禁和对应测试；
- TIMESYNC第一阶段已实现；目标消息当前通过`V2_EXTENSION.message_type=65010/65011`实现最小接收/ACK/Topic发布闭环。继续扩展`TRACK_TARGET_UPDATE/ACK`时必须同步配置、payload布局、测试、地面站工具和实现文档。
- 地面站身份已按`docs/多机身份与功能寻址设计.md`实施：`aircraft_system_id==aircraft_number`，`net_capture→25`，`rocket→26`，`27～99`全部预留且不得启用，地面站来源固定`255/190`。
