# 正式主程序集成（DroneApplication）

## 功能职责

`DroneApplication`是正式进程的组件所有者和装配根，负责根据`AppConfig`创建视频与PX4组件、在启动前绑定Topic、按顺序启动和停止。`main.cpp`只处理配置、日志、信号和进程等待。

当前边界：

- 已装配完整视频链路；
- 已装配PX4真实串口遥测链路；
- 不绑定`Px4Setpoint`，不发送任何飞行控制命令；
- 地面站、状态机、健康管理和控制器后续按实施计划接入。

## 接口与数据流

```cpp
class DroneApplication {
public:
    explicit DroneApplication(config::AppConfig config);
    bool Start();
    void Stop();
    bool IsRunning() const;
};
```

当前数据流：

```text
CameraReceiver → VideoDecoder → YoloDetector → FrameCompositor → VideoSender
PX4 /dev/ttyS1 → Px4Link → Topic<FlightStateSnapshot>
```

PX4状态Topic当前由`Px4Link`持有，后续直接供`GroundStationLink`、状态机和感知融合订阅。

## 关键实现点

- 所有Topic在任何组件`Start()`前绑定；
- 视频消费者先启动，摄像头生产者最后启动；
- 停机先停止PX4物理链路，再按视频生产者到消费者顺序停止；
- 单模块启动失败记录降级，其他独立模块继续运行；
- 当前代码没有调用`Px4Link::SetInput()`和`SendCommand()`，因此正式程序只读遥测；
- Stop幂等，析构再次调用安全。

## 日志行为

INFO记录应用创建、启用模块、启动完成、停止和销毁；模块启动失败记录一次ERROR。装配层不逐帧、不逐遥测快照打印日志。

## 测试方式

开发机构建：

```bash
cmake -S . -B build
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
```

硬件验证：香橙派运行`./build/drone_control`，确认视频继续出图、PX4串口连接和遥测请求正常，并检查PX4没有收到ARM、模式或setpoint控制消息。

## 排查/修改要点

- 新增组件必须先创建、再绑定、最后启动；不得在运行后临时换Topic；
- 后续接地面站时先启动地面站消费者，再启动PX4状态生产者；停机反向；
- `enable_control=false`期间禁止连接FlightController输出；
- 算法接入只增加Topic接线，不把算法逻辑写入本类；
- 跨会话实施顺序见`docs/主程序集成与数据链路实施计划.md`。
