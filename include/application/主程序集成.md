# 正式主程序集成（DroneApplication）

## 功能职责

`DroneApplication`是正式进程的组件所有者和装配根，负责根据`AppConfig`创建视频、PX4和地面站数传组件、在启动前绑定Topic、按顺序启动和停止。`main.cpp`只处理配置、日志、信号和进程等待。

## 接口与数据流

```cpp
class DroneApplication {
public:
    explicit DroneApplication(config::AppConfig config);
    bool Start();
    void Stop();
    bool IsRunning() const;
    // 控制面装配诊断快照（阶段四装配门禁断言/排查）：控制器是否创建、意图输入
    // 是否接状态机、65014/65015 是否接线、估计输入是否成组绑定、命令接口是否
    // 注入、控制器实际 bootstrap_timeout；控制输出相关字段仅enable_control=true。
    ControlAssemblySnapshot ControlAssembly() const;
};
```

当前数据流：

```text
CameraReceiver → VideoDecoder → YoloDetector → FrameCompositor → VideoSender
YoloDetector → Topic<VisualTargetObservation> → VisualTargetMonitor → Topic<VisualTargetStatus>（→ MissionStateMachine，三输入齐备时）
PX4 /dev/ttyS1 → Px4Link → Topic<FlightStateSnapshot>
                                      ├→ GroundStationLink → /dev/ttyS6 → 自研地面站
                                      └→ MissionStateMachine

各模块计数 → DroneApplication健康监控线程 → HealthManager
HealthManager → Topic<HealthStatus> → MissionStateMachine / GroundStationLink
地面站目标 → GroundStationLink::TargetOutput() → MissionStateMachine::StatusOutput() → GroundStationLink
                                      └→ TargetEstimator ← PX4 EKF 锚点(#49)/姿态/局部位置
                       StereoRanger::DistanceOutput() ↘（视觉融合开启时）相机系位置→NED 观测
                                                  └→ Topic<TargetState>
TargetEstimator/TargetState + VisualTargetStatus + StereoTargetDistance
    → MissionStateMachine::SetEstimationInputs（三者齐备时）
GroundStationLink::MissionAssignmentOutput() → MissionStateMachine::SetAssignmentInput
MissionStateMachine::AssignmentAckOutput() → GroundStationLink::SetMissionAssignmentAckInput
GroundStationLink::NetFireCommandOutput() → GcsNetFire::SetCommandInput（仅 gcs_fire_enabled）
GcsNetFire::AckOutput() → GroundStationLink::SetNetFireAckInput（65017）
MissionStateMachine::IntentOutput() → FlightController → Topic<Px4Setpoint>
    （enable_control=false：影子，无消费者；=true：→ Px4Link → PX4 串口）
```

`GroundStationLink`拥有独立订阅队列，只消费最新飞行快照；串口设备和发送频率均由JSON配置。`MissionStateMachine`已实现 S2~S14 的完整意图链，生产装配已接分配/回执与估计输入，但仍为安全影子（`interception.enabled=false`、`enable_control=false`），不把意图送达 PX4；65014 在无命令接口时回 `control_disabled`。`TargetEstimator`是第二条影子链路：以 EKF 锚点（#49 `ref_*`，与 PX4 设定值执行帧同源；方案 C，2026-10-16）为原点，把地面站指定的单一目标转换到局部NED并线性滤波；2026-10-12 起可选融合双目视觉NED观测（`enable_visual_position_fusion`，经 `visual_ned_converter` 转换，只细化不初始化、不延展有效期，见 `include/perception/目标估计器.md`）。

## 关键实现点

- 所有Topic在任何组件`Start()`前绑定；
- 视频消费者先启动，摄像头生产者最后启动；视觉稳定性判定作为YOLO观测的消费者，先于YoloDetector启动；
- 目标估计器、飞行控制器和状态机先于地面站、HealthManager和PX4生产者启动（飞行控制器是状态机意图的消费者，先于状态机启动），以便不遗漏后续Home、目标、意图及健康消息；地面站消费者先于PX4状态生产者启动；停机时先停止PX4和视频生产者，再停止健康上报线程/HealthManager，最后停止飞行控制器、状态机、目标估计器和地面站消费者；
- 单模块启动失败记录降级，其他独立模块继续运行；
- 状态机配置在`BuildComponents()`内从`AppConfig`透传：`takeoff`（S3/S4 自动起飞时序，整节）、`expected_interceptor_type`（取`ground_station.aircraft_component_id`）、`interception`（S9/S10 入口，默认关闭）与`return_home`（S11~S14，默认启用）随`MissionStateMachineConfig`注入；
- 任务分配接线与`enable_control`无关：`GroundStationLink::MissionAssignmentOutput()`→`SetAssignmentInput`，`AssignmentAckOutput()`→`SetMissionAssignmentAckInput`；无控制装配时状态机仍回65015 `control_disabled`；
- 地面站直控发射接线（2026-10-23，G4-5）：仅当`actuator.gcs_fire_enabled=true`且PX4/地面站链路均存在时创建`GcsNetFire`（`config_.actuator`+`px4_link_.get()`），并绑定`PX4 StateOutput()`→`SetFlightStateInput`、`GroundStationLink::NetFireCommandOutput()`→`SetCommandInput`、`AckOutput()`→`SetNetFireAckInput`；启动顺序在飞行控制器/状态机之后、地面站链路之前，停止在目标估计器之后、地面站链路之前。该通道不产生`ControlIntent`，与`enable_control`无关，但受“落地且未解锁”门禁约束；`gcs_fire_enabled=false`（生产默认）时65016由链路丢弃；
- 估计输入成组接线：仅当`TargetEstimator`、`VisualTargetMonitor`、`StereoRanger`三者均创建时调用`SetEstimationInputs(EstimatedOutput(), StatusOutput(), DistanceOutput())`；缺一不接，S5保持影子行为；
- 飞行控制器`bootstrap_timeout`通过`config_.controller`的局部副本注入`takeoff.bootstrap_timeout`，不回写`config_`；该值须覆盖`bootstrap_lead+mode_timeout+arm_timeout`（配置校验强制）；
- 只有`enable_control=true`才调用`Px4Link::SetInput()`绑定`FlightController::SetpointOutput()`并注入PX4快照源与状态机命令接口；`enable_control=false`（仓库生产基线）下控制器影子运行、命令接口不注入，正式程序只读遥测，不输出控制；装配状态可由`ControlAssembly()`快照断言；
- 意图输入纪律：`FlightController::SetInput()`只接`MissionStateMachine::IntentOutput()`；`VisualTrackingShadow`影子意图不带授权请求位（`reason_code` bit31，`common::kControlIntentReasonRequestControl`），接入控制器会每拍清锁存压死授权门禁，永不接线；
- `enable_visual_monitor=true`时必须`enable_video=true`；该影子链路关闭不影响视频链路；
- 双目测距距离输出只在视觉跟踪影子装配时接入（可选通道）；探针等裁剪配置关闭视觉监控/视觉跟踪后`enable_stereo_ranging`仍可能为true，装配层对所有可选组件必须判空，不得无条件解引用（历史段错误：探针启动即SIGSEGV，回归测试`drone_application_test`）；
- Stop幂等，析构再次调用安全。

## 视频延迟诊断

`VideoLatencySnapshot()`汇总解码、YOLO、叠加和编码推流阶段的固定窗口延迟，供`tools/video_latency_probe.cpp`读取；同时汇总实际输入编码、硬解模式、编码访问单元/字节/关键帧计数、DRM/RGA DMA成功与回退计数、最近256帧的解码细分以及YOLO的RGA/letterbox/NPU/输出布局/后处理细分。正式应用不逐帧打印延迟；探针独占运行视频链路，使用方法见`tools/video_latency_probe.md`。

## 日志行为

INFO记录应用创建、启用模块、启动完成、停止和销毁；模块启动失败记录一次ERROR；`enable_control=true`装配期打一次WARN「正式控制输出已启用」。装配层不逐帧、不逐遥测快照打印日志。

## 排查/修改要点

- 新增组件必须先创建、再绑定、最后启动；不得在运行后临时换Topic；
- 地面站目标、任务状态机影子链路、单目标估计影子链路和HealthManager健康Topic已接入；新增健康数据源时必须同步配置阈值、注册逻辑和测试；
- `enable_control=false`期间禁止连接FlightController输出；`interception.enabled`生产默认必须保持false，返航/降落链只在SITL验收配置或现场本地副本显式开启；自动起飞同理，只在SITL/台架/现场本地副本通过65014显式触发；
- 状态机新增配置节时必须同时更新`config::AppConfig`、`DroneApplication::BuildComponents()`透传和配置文档（`include/config/配置管理.md`）；
- 算法接入只增加Topic接线，不把算法逻辑写入本类；
- 视觉控制律接入主工程时只复用算法输出并适配为`ControlIntent/Px4Setpoint`，不得使用独立库的演示用`MavlinkCommandGateway`绕过`Px4Link`直接发MAVLink；
- 跨会话实施顺序见`docs/archive/历史计划/主程序集成与数据链路实施计划.md`。
